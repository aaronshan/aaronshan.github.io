系统表

PyPaimon 通过现有的 catalog 和 read-builder API 暴露 table$<name> 系统表。支持的短名称为: snapshots、schemas、options、manifests、files、partitions、 tags 和 branches。sys 数据库下的全局表 (sys.all_tables、sys.catalog_options 等)以及流式的 audit_log / binlog 系列暂未暴露。

基本用法​

为 scan 和 read 复用同一个 read builder,这样在其上设置的任何 投影或 limit 对两侧都生效:

from pypaimon import CatalogFactory

catalog = CatalogFactory.create({'warehouse': '/path/to/warehouse'})
snapshots = catalog.get_table('default.my_table$snapshots')

read_builder = snapshots.new_read_builder()
splits = read_builder.new_scan().plan().splits()
print(read_builder.new_read().to_pandas(splits))

with_projection 和 with_limit 在同一个 builder 上链式调用:

read_builder = (
    snapshots.new_read_builder()
    .with_projection(['snapshot_id', 'commit_user', 'commit_time'])
    .with_limit(10)
)
splits = read_builder.new_scan().plan().splits()
arrow_table = read_builder.new_read().to_arrow(splits)

返回的对象暴露了常规的 Table 接口,因此同一个 read builder 可与 to_pandas、to_arrow、to_iterator、 to_record_batch_iterator 和 to_duckdb 一起使用。写入会抛出 NotImplementedError —— 系统表是只读的。

可用表​

下面按 SystemTableLoader 中出现的顺序列出每张系统表, 包括其列布局(含可空性)和主键选择。

$snapshots​

每个持久化快照对应一行。

列类型说明
snapshot_idBIGINT NOT NULL主键
schema_idBIGINT NOT NULL
commit_userSTRING NOT NULL
commit_identifierBIGINT NOT NULL
commit_kindSTRING NOT NULLAPPEND、COMPACT 等
commit_timeTIMESTAMP(3) NOT NULL
base_manifest_listSTRING NOT NULL
delta_manifest_listSTRING NOT NULL
changelog_manifest_listSTRING
total_record_countBIGINT所有存活数据文件的未合并记录数;并非逻辑行数
delta_record_countBIGINT由新增和删除的数据文件引起的未合并记录数净变化
changelog_record_countBIGINT
watermarkBIGINT
next_row_idBIGINT

专用格式(Dedicated Format)列存储在独立的数据文件中,这些文件中的每一个 都会计入快照的记录数。例如,向包含一个专用 BLOB 列的表追加 N 个逻辑行 会使 delta_record_count 增加 2 * N。当你需要逻辑行数时,请使用 COUNT(*)。

每个 tag 对应的快照元数据。

限制​

  • 尚未实现谓词下推。 调用 with_filter(...) 会被接受,但之后调用 new_read() 会抛出 NotImplementedError,而不是静默丢弃谓词。请改为在客户端侧 对返回的 Arrow 表 / DataFrame 进行过滤。
  • $manifests 中的 min_partition_stats / max_partition_stats 输出为 NULL。PyPaimon 尚未提供将分区行转换为其字符串形式的 辅助工具。
  • tag.time_retained 和 tag.create_time 为 NULL。 PyPaimon 的 Tag 数据类尚未携带这些字段 ——/export 与 FileSystemCatalog.get_tag 当前的行为一致。
  • branch.create_time 在底层存储无法提供 mtime 时回退为 epoch 0 (例如通过 PyArrowFileIO 访问的某些远程对象存储)。 本地文件系统 catalog 总会填充真实时间。
  • partitions.created_at / created_by / updated_by / options / done 对于文件系统路径填充的是占位符。暴露了这些字段的 REST 托管 catalog 将在后续版本中接入。
  • list_tables 不会枚举系统表。 系统表仍可通过 get_table('db.t$name') 访问。

各 Catalog 的支持情况​

  • FilesystemCatalog —— 完全支持。
  • RESTCatalog —— 完全支持;依赖 catalog 元数据的列 (如 $partitions.created_by)会在服务端暴露这些字段时 通过 REST API 填充。
