Primary-Key 索引

Primary-Key 表可以随压缩后的数据文件一起维护 Vector、Full Text、FM、BTree、Bitmap 和 Multivalue 索引。这些索引是 bucket 本地的、基于源数据文件的:每个索引组记录 其源数据文件,并将匹配结果映射回物理行位置。读取被索引的行时会应用 deletion vector,因此更新和删除保持精确。

Primary-Key 索引与使用 create_global_index 创建的索引不同。普通的 Global Index 面向全表的行 ID,并为 Data Evolution 表 独立构建。Primary-Key 索引则跟随 Primary-Key 表的写入和 Compaction 生命周期,用于定位其压缩数据文件内的行。

选择索引​

  • BTree
  • Bitmap
  • Multivalue
  • Vector
  • Full Text
  • FM

BTree 适用于选择性的标量谓词,如相等、IN、比较、范围和 null 检查。普通的 Flink、Spark 和 Java 批量扫描会自动应用它;无需索引专用的查询 API。

内置格式和支持的数据类型请参见 BTree Index。

Bitmap 适用于枚举型维度、标签等列,压缩位图可以高效评估 相等、IN、null 检查、补集谓词以及受支持的字符串谓词。 普通的批量扫描会自动应用它。

谓词与格式细节请参见 Bitmap Index。

Multivalue 适用于 ARRAY 列上的元素归属谓词。它为每个不同的非 null 元素 存储一条压缩位图 posting list,并加速 Paimon Core 的 ARRAY_CONTAINS、 ARRAYS_OVERLAP 和 ARRAY_CONTAINS_ALL 谓词。null 数组、空数组和 null 元素 不会产生归属 posting;数组的 null 检查回退到普通数据路径。

该 Core 谓词与索引下推独立于 SQL 连接器可用。连接器在将其数组归属 表达式翻译为对应的 Paimon 谓词后,即可使用此索引。

对独立构建 Multivalue 索引的仅追加表或 Data Evolution 表,请参见 Global Multivalue Index。

Vector 适用于对随 Primary-Key 表一起更新的 embedding 做近似最近邻(ANN) Top-K 搜索。索引实现和距离度量按字段配置,搜索通过 Spark SQL、Flink 过程和 Java API 暴露。

对独立构建 Vector 索引的仅追加表或 Data Evolution 表,请参见 Global Vector Index。

Full Text 适用于对可随 Primary-Key 表一起更新或删除的 CHAR、VARCHAR 或 STRING 内容进行原生打分搜索。固定的 full-text 实现会被自动选中。 搜索通过 Spark SQL、Flink 过程和 Java API 暴露。

对独立构建 Full Text 索引的仅追加表或 Data Evolution 表,请参见 Global Index。

FM 适用于 CHAR、VARCHAR 或 STRING 列上的精确子串谓词。连接器把 字面量子串表达式转换为 Paimon 的 CONTAINS 谓词后,普通批量扫描会自动 应用它。支持任意字节长度的 needle,无需选择 gram 大小。

对独立构建 FM 索引的仅追加表或 Data Evolution 表,请参见 FM Index。

同一张表中的不同列可以使用不同的索引家族。一个列最多只能出现在 pk-vector.index.columns、pk-full-text.index.columns、pk-btree.index.columns、 pk-bitmap.index.columns、pk-multivalue.index.columns 和 pk-fm.index.columns 中的一个里。

使用要求​

所有 Primary-Key 索引都要求:

  • 使用固定 bucket 模式(bucket > 0)或 postpone bucket 模式 (bucket = -2)的 Primary Key 表。
  • pk-clustering-override = false。
  • 所选索引实现支持的索引列类型。

动态 bucket 表、仅追加表、复合索引和自定义索引家族不受 该配置支持。

  • BTree, Bitmap, Multivalue, and FM
  • Vector
  • Full Text

BTree、Bitmap、Multivalue 和 FM 额外要求:

  • deletion-vectors.enabled = true。
  • deletion-vectors.merge-on-read = false。
  • BTree 和 Bitmap 需要受支持的标量列类型,Multivalue 需要由受支持的标量元素 组成的 ARRAY。FM 要求 CHAR、VARCHAR 或 STRING 列。

每个条目创建一个独立的单列索引。只要一个列未被其他 Primary-Key 索引家族 占用,就支持多个列。

Vector 额外要求:

  • 元素类型为 FLOAT 的 VECTOR 列。
  • Merge Engine 为 deduplicate、partial-update、aggregation 或 first-row。
  • deletion-vectors.enabled = true,但 first-row 除外,此时必须为 false。
  • 每个写入器和读取器的 classpath 上都有已配置的 ANN 实现。

目前每张表仅支持一个向量列。

Full Text 额外要求:

  • CHAR、VARCHAR 或 STRING 列。
  • Merge Engine 为 deduplicate、partial-update、aggregation 或 first-row。
  • deletion-vectors.enabled = true,但 first-row 除外,此时必须为 false。
  • deletion-vectors.merge-on-read = false。
  • 每个写入器、compactor 和读取器的 classpath 上都有 paimon-full-text 模块及其原生实现。

目前每张表仅支持一个全文列。

创建表​

下面的表在不同列上使用了全部六个索引家族:Vector 用于 embedding,Full Text 用于 content,FM 用于 raw_text,BTree 用于 amount,Bitmap 用于 status, Multivalue 用于 tags。

  • Flink SQL
  • Spark SQL
CREATE TABLE items (
    id BIGINT,
    status STRING,
    amount DECIMAL(12, 2),
    tags ARRAY<STRING>,
    content STRING,
    raw_text STRING,
    embedding ARRAY<FLOAT> COMMENT '__VECTOR_FIELD;3',
    PRIMARY KEY (id) NOT ENFORCED
) WITH (
    'bucket' = '8',
    'deletion-vectors.enabled' = 'true',
    'pk-vector.index.columns' = 'embedding',
    'fields.embedding.pk-vector.index.type' = 'ivf-flat',
    'fields.embedding.pk-vector.distance.metric' = 'cosine',
    'fields.embedding.pk-vector.index.options' = '{"nlist":"256"}',
    'pk-full-text.index.columns' = 'content',
    'fields.content.pk-full-text.index.options' = '{"tokenizer":"jieba"}',
    'pk-fm.index.columns' = 'raw_text',
    'fields.raw_text.pk-fm.index.options' = '{"partition-row-count":"100000"}',
    'pk-btree.index.columns' = 'amount',
    'fields.amount.pk-btree.index.options' = '{"block-size":"64 kb"}',
    'pk-bitmap.index.columns' = 'status',
    'fields.status.pk-bitmap.index.options' = '{"dictionary-block-size":"16 kb"}',
    'pk-multivalue.index.columns' = 'tags',
    'fields.tags.pk-multivalue.index.options' = '{"dictionary-block-size":"16 kb"}'
);

向量列的注释指令会把 SQL 的 ARRAY<FLOAT> 列转换为 Paimon 的定长 VECTOR<FLOAT> 类型。Java API 用户可以直接用 DataTypes.VECTOR(3, DataTypes.FLOAT()) 定义。

CREATE TABLE items (
    id BIGINT,
    status STRING,
    amount DECIMAL(12, 2),
    tags ARRAY<STRING>,
    content STRING,
    raw_text STRING,
    embedding ARRAY<FLOAT> COMMENT '__VECTOR_FIELD;3'
) USING paimon
TBLPROPERTIES (
    'primary-key' = 'id',
    'bucket' = '8',
    'deletion-vectors.enabled' = 'true',
    'pk-vector.index.columns' = 'embedding',
    'fields.embedding.pk-vector.index.type' = 'ivf-flat',
    'fields.embedding.pk-vector.distance.metric' = 'cosine',
    'fields.embedding.pk-vector.index.options' = '{"nlist":"256"}',
    'pk-full-text.index.columns' = 'content',
    'fields.content.pk-full-text.index.options' = '{"tokenizer":"jieba"}',
    'pk-fm.index.columns' = 'raw_text',
    'fields.raw_text.pk-fm.index.options' = '{"partition-row-count":"100000"}',
    'pk-btree.index.columns' = 'amount',
    'fields.amount.pk-btree.index.options' = '{"block-size":"64 kb"}',
    'pk-bitmap.index.columns' = 'status',
    'fields.status.pk-bitmap.index.options' = '{"dictionary-block-size":"16 kb"}',
    'pk-multivalue.index.columns' = 'tags',
    'fields.tags.pk-multivalue.index.options' = '{"dictionary-block-size":"16 kb"}'
);

在 schema 校验阶段,重复、空白、未知、不受支持或跨家族重复的列会被拒绝。

维护与覆盖​

Paimon 基于 Level 0 以上的完整 COMPACT 数据文件构建 Primary-Key 索引。索引组 保存将索引结果映射回物理行所需的源文件名和行数。 数据文件与索引文件的变更在同一个 snapshot 中提交。

新的 Level-0 APPEND 文件不是索引源。在物理数据 compaction 产生合格的输出之前,它们保持未覆盖状态。仅元数据的层级提升保留其 APPEND 源,因此同样保持未覆盖状态。

对 postpone-bucket 表,前台写入可能落到 bucket -2 中,或落到真实 bucket 内待处理的 Level-0 文件中。这些行在批量 compaction 将它们发布到真实 bucket 后才可见。只有当该过程把行物理重写为合格的 compact 输出时才会创建 索引;仅仅是分配或提升一个待处理文件,并不会使其成为索引源。

数据层级维护​

每个索引列为每个非零数据层级的完整合格源文件集合维护一个不可变的索引组。 每个组写一个 payload 文件;一个 FM payload 可以包含多个可独立读取的 内部分区。当数据 compaction 改变了某个层级时,Paimon 会重建 该整个层级组,包括目标层级中并非本次 compaction 直接输入的文件。 一个层级组只有在其有序的源文件名与行数与当前数据层级完全一致时 才会被使用;过期的 payload 和跨层级的 payload 会被拒绝。

重建会在完整的新组就绪后原子替换旧组。无关的 数据层级保留其现有 payload。

索引构建可以在写入器内部异步执行。等待 compaction 的写入器也会 等待进行中的索引维护;非阻塞写入器则可以在后续 commit 中完成 维护。因此覆盖率可能暂时不完整。

覆盖行为取决于索引家族和搜索模式。vector-index.search-mode 和 full-text-index.search-mode 默认为 fast。在 fast 模式下,Primary-Key Vector 和 Full Text 查询只搜索被活跃索引组覆盖的数据。未覆盖的文件不会被搜索, 因此部分覆盖可能导致结果不完整。

  • BTree、Bitmap、Multivalue 和 FM 扫描总是通过普通数据路径读取未覆盖的文件。 部分覆盖影响的是加速效果,而不是结果的完整性。索引裁剪之后仍会应用 原始谓词和 deletion vector。
  • 在 full 或 detail 模式下,Vector 搜索会对没有活跃 ANN 组的文件做精确 评估,并将这些结果与 ANN 候选合并。在默认的 fast 模式下,这些文件会被省略。

Primary-Key Full Text 目前仅支持 full-text-index.search-mode = fast。它只搜索 持久化的 archive,并忽略未覆盖的文件;full 和 detail 会被拒绝,因为 尚未实现感知合并的逻辑行回退。因此,新追加的 Level-0 行只有在 compaction 发布了合格的数据文件和 archive 之后,才能被全文搜索到。

BTree、Bitmap、Multivalue 与 FM 查询​

当受支持的谓词到达 Paimon 后,BTree、Bitmap、Multivalue 和 FM 索引会自动应用于 以 snapshot 为作用域的 Core 批量扫描。BTree 和 Bitmap 可以加速相等、IN、 null 检查、比较与范围、补集谓词以及受支持的字符串谓词。 Multivalue 加速 ARRAY_CONTAINS、ARRAYS_OVERLAP 和 ARRAY_CONTAINS_ALL 谓词。 FM 加速精确的 CONTAINS 谓词。例如,Spark 会把下面的字面量 子串过滤转换为 Paimon 的 CONTAINS 谓词:

SELECT id, raw_text
FROM items
WHERE raw_text LIKE '%needle%';

FM 的结果对被索引的文件是精确的。Paimon 会正常读取未覆盖的文件,并重新应用 原始谓词和 deletion vector,因此部分索引覆盖影响的是性能而不是 结果的完整性。

Java/Core 谓词也可以直接构造:

Predicate predicate = new PredicateBuilder(rowType)
        .arraysOverlap(
                tagsFieldIndex,
                Arrays.asList(
                        BinaryString.fromString("blue"),
                        BinaryString.fromString("green")));
ReadBuilder readBuilder = table.newReadBuilder().withFilter(predicate);
TableScan.Plan plan = readBuilder.newScan().plan();

SQL 引擎需要连接器特有的表达式转换,才能将其数组归属 函数转换为对应的 Core 谓词。

Paimon 按如下方式组合索引谓词结果:

  • 对于 AND,任何可用的被索引子项都可以缩小源文件范围;未被索引的子项 保留为残余过滤器。
  • 对于 OR,只有当每个分支都能被安全评估时才使用索引位置。否则, 源文件按普通方式扫描。

规划使用所选 snapshot 的数据 manifest 和索引 manifest。如果某个索引组 缺失、不完整、不可读、已损坏,或返回了非法的物理位置,受影响的 源文件会回退到普通数据路径。

Vector 搜索​

一次 Vector 搜索捕获一个表 snapshot,在所选 bucket 中搜索活跃的 ANN 组, 并把它们的候选合并为全局 Top-K。候选按物理行位置从源数据 文件中物化。Deletion vector 会移除过期的版本和已删除的行。

  • Spark SQL
  • Flink SQL
  • Java API

使用 vector_search 表值函数。Spark 通过 __paimon_search_score 元数据列暴露 ANN 分数。

SELECT id, status, __paimon_search_score
FROM vector_search(
    'items',
    'embedding',
    array(0.1f, 0.2f, 0.3f),
    10,
    map('ivf.nprobe', '32')
);

查询维度必须与被索引向量的维度一致。分区谓词会在 ANN 搜索之前应用。 当 spark.paimon.vector-search.distribute.enabled 为 true 时,Spark 可以把 足够大的 bucket 本地搜索组分发执行,并在 driver 上合并各 task 的局部 Top-K 结果。

Flink 以过程的形式暴露 Vector 搜索,并返回 JSON 序列化的行。使用 projection 避免读取不需要的列。

CALL sys.vector_search(
    `table` => 'default.items',
    vector_column => 'embedding',
    query_vector => '0.1,0.2,0.3',
    top_k => 10,
    projection => 'id,status,__paimon_search_score',
    options => 'ivf.nprobe=32',
    `where` => 'status = ''active'''
);
GlobalIndexResult result = table.newVectorSearchBuilder()
        .withVectorColumn("embedding")
        .withVector(queryVector)
        .withLimit(10)
        .withOption("ivf.nprobe", "32")
        .executeLocal();

ReadBuilder readBuilder = table.newReadBuilder();
TableScan.Plan plan = readBuilder.newScan().withGlobalIndexResult(result).plan();
try (RecordReader<InternalRow> reader = readBuilder.newRead().createReader(plan)) {
    reader.forEachRemaining(row -> consume(row));
}

精确重排(Exact Rerank)​

Primary-Key Vector 搜索可以多召回一些 ANN 候选,并用原始 向量对它们重排。例如,下面的表选项在计算精确距离之前 召回至多四倍于请求 Top-K 的候选:

'fields.embedding.ivf-flat.refine_factor' = '4'

refine_factor、refine-factor、rerank_factor 和 rerank-factor 均可使用。查询选项 会覆盖表选项,而字段/索引前缀优先于更不具体的前缀。 该系数必须是正整数。系数为 1 表示在不额外召回候选的情况下做精确重排。

只有 ANN 候选能参与重排,因此更大的系数可以提高召回率,但不能 保证得到精确的全局 Top-K。它也会增加 ANN 工作量和数据文件 I/O。在 full 或 detail 模式下,未覆盖的文件会被精确搜索,并与 ANN 候选单独合并; 默认的 fast 模式不搜索这些文件。

Full-Text 搜索​

一次 Primary-Key Full-Text 搜索捕获一个表 snapshot,在所选 bucket 中搜索活跃的 archive,应用 deletion vector,并把原生相关度分数 合并为全局 Top-K。分数保留为 __paimon_search_score;除非之后 full-text 路由被 Hybrid 搜索组合,否则它不会被 RRF 改写。

  • Spark SQL
  • Flink SQL
  • Java API
SELECT id, content, __paimon_search_score
FROM full_text_search(
    'items',
    'content',
    '{"match":{"query":"paimon lake"}}',
    10
)
ORDER BY __paimon_search_score DESC;

Flink 返回 JSON 序列化的行。当需要原生相关度分数时,请在 projection 中加入 __paimon_search_score。top_k 必须在 1 到 10,000 之间。

CALL sys.full_text_search(
    `table` => 'default.items',
    `column` => 'content',
    query => '{"match":{"query":"paimon lake"}}',
    top_k => 10,
    projection => 'id,content,__paimon_search_score'
);
GlobalIndexResult result = table.newFullTextSearchBuilder()
        .withQuery("content", queryJson)
        .withLimit(10)
        .executeLocal();

ReadBuilder readBuilder = table.newReadBuilder();
TableScan.Plan plan = readBuilder.newScan().withGlobalIndexResult(result).plan();
try (RecordReader<InternalRow> reader = readBuilder.newRead().createReader(plan)) {
    reader.forEachRemaining(row -> consume(row));
}

分区谓词可以在打分之前裁剪 bucket。任意行谓词不能下推到 full-text 的 Top-K 路由中。

Hybrid 搜索​

Spark 的 hybrid_search 可以按物理数据文件位置融合 Primary-Key Vector 和 Full Text 路由。Hybrid 为所有物理路由捕获同一个 snapshot,拒绝混合物理路由 与全局行 ID 路由,并在读取行之前对其源文件去重。支持的排序器 有 rrf、weighted_score 和 mrr;路由权重必须是有限的正数。

SELECT id, __paimon_search_score
FROM hybrid_search(
    'items',
    array(named_struct(
        'field', 'embedding',
        'query_vector', array(0.1f, 0.2f, 0.3f),
        'limit', 20,
        'weight', 1.0f,
        'options', map())),
    array(named_struct(
        'column', 'content',
        'query', '{"match":{"query":"paimon lake"}}',
        'limit', 20,
        'weight', 1.0f,
        'options', map())),
    10,
    'rrf'
)
ORDER BY __paimon_search_score DESC;

Merge Engine 行为​

Vector 和 Full Text 的维护遵循表的 Merge Engine:

  • deduplicate:更新会为最新的行建索引,deletion vector 隐藏被替换的 物理行。删除会通过 deletion vector 同时从两个搜索索引中移除旧行。
  • partial-update:Vector 索引基于经过 lookup 补全后的 compact 输出行构建。
  • aggregation:Vector 索引基于聚合后的 compact 输出行构建。
  • first-row:被保留的第一行会被建索引。必须禁用 deletion vector, 因为具有相同主键的后续行是被忽略,而不是删除被保留的行。

Full Text 按同样的规则对 lookup 补全后、聚合后或被保留的 compact 输出文本建索引。 Null 文本会占用一个物理行序号,但不会加入原生的 term 索引。

Schema 演进​

一个已被索引的列在其定义存在期间不能被重命名、删除或更改类型。 索引列列表、字段级实现设置以及构建选项都应视为索引定义的一部分。 要更改某个已索引列的家族或不兼容的构建选项, 请使用期望的定义创建一张新表并迁移数据。

限制​

  • BTree、Bitmap、Multivalue 和 FM 的定义均为单列索引。
  • Multivalue 支持由全局索引 key 序列化器接受的标量元素类型组成的数组。 Null 元素不会被索引。更高的数组和元素基数会增加展开排序的 I/O 和索引文件大小。
  • 目前每张表仅支持一个 Vector 索引列。
  • 目前每张表仅支持一个 Full-Text 索引列。
  • 仅支持 FLOAT 向量。
  • 索引基于合格的 compact 输出构建,而不是直接基于 Level-0 追加。
  • 索引加速和 Vector 搜索是以 snapshot 为作用域的批操作;连续流式 以及 lateral 的 Vector 或 Full Text 搜索不受支持。
  • Flink Vector 搜索返回行,但不把 ANN 分数暴露为单独的列。
  • FAST 是默认搜索模式,未覆盖的文件会被排除在 Primary-Key Vector 和 Full Text 结果之外。Vector 在 FULL 和 DETAIL 模式下支持对未覆盖文件的 精确回退;Primary-Key Full Text 在 compaction 创建持久化 archive 之前仅支持 FAST。
  • Full Text 路由支持分区裁剪,但不支持在 Top-K 之前应用任意行谓词。
  • Hybrid 搜索不能混合基于源文件的物理路由与全局行 ID 路由。
  • 不支持同一列上两个定义之间的在线替换。
