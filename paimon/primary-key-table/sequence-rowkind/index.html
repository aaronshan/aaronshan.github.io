Sequence 与 Rowkind

建表时,你可以通过指定 'sequence.field' 字段来确定更新的先后顺序, 也可以通过指定 'rowkind.field' 来确定记录的 changelog 类型。

Sequence Field​

默认情况下,Primary Key 表根据输入顺序确定合并顺序(最后输入的记录最后合并)。然而,在分布式计算中, 某些情况会导致数据乱序。这时,你可以使用一个时间字段作为 sequence.field,例如:

  • Flink
CREATE TABLE my_table (
    pk BIGINT PRIMARY KEY NOT ENFORCED,
    v1 DOUBLE,
    v2 BIGINT,
    update_time TIMESTAMP
) WITH (
    'sequence.field' = 'update_time'
);

sequence.field 值最大的记录将最后合并;如果值相同,则使用输入 顺序来决定哪条记录最后合并。sequence.field 不支持 GEOMETRY、GEOGRAPHY 或受管理的 BLOB 字段。

你可以为 sequence.field 定义多个字段,例如 'update_time,flag',多个字段将按顺序依次比较。

信息

用户自定义的 sequence 字段与 first_row 和 first_value 等功能冲突,可能会产生非预期的结果。

Row Kind 字段​

默认情况下,Primary Key 表根据输入行确定 row kind。你也可以定义 'rowkind.field',使用某个字段来提取 row kind。

合法的 row kind 字符串为 '+I'、'-U'、'+U' 或 '-D'。

Snapshot 排序​

在多写入器场景中,wall-clock 序列号无法在各写入器之间全局有序, 你可以启用 'sequence.snapshot-ordering',在合并相同主键的记录时使用 commit 的 snapshot id 作为排序依据。来自更晚 snapshot 的记录被视为更新, 与每条记录自身的序列号无关。

  • Flink
CREATE TABLE my_table (
    pk BIGINT PRIMARY KEY NOT ENFORCED,
    v1 DOUBLE,
    v2 BIGINT
) WITH (
    'sequence.snapshot-ordering' = 'true',
    'write-only' = 'true'
);
注意

该选项要求 'write-only' = 'true'。Compaction 必须由独立的专用 compact 作业执行。这确保 compaction 能正确保留每条记录的 snapshot id。

信息

'sequence.snapshot-ordering' 与 'sequence.field' 互斥。同一张表上不能同时 启用两者。

信息

排序依据仅仅是 commit 的 snapshot id;同一个 snapshot 内记录的顺序 不做保证,这是有意设计。在默认配置下这并无影响:写入器 会缓冲一次 commit 的写入('write-buffer-spillable' = 'true'),并在刷写前 对它们执行 merge 函数,因此每个 snapshot 中每个主键最多只写入一条 记录——常见情况已被完全覆盖。因此我们刻意不处理同一个键分散在 一个 snapshot 的多个文件中的情况。该情况只会在 'write-buffer-spillable' = 'false', 或溢写数据超过 'write-buffer-spill-disk-size' 时出现,此时缓冲区可能在 commit 中途被刷写;相同的键可能落入同一个 snapshot 的多个文件中,且序列号 相同,它们的相对顺序变成未定义。这只影响 snapshot 内部的顺序, 绝不会影响该功能提供的跨 snapshot 排序。
