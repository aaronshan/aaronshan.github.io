参与贡献

Apache Paimon 由一个开放友好的社区开发。我们热烈欢迎每一个人加入社区并为 Apache Paimon 做出贡献。 与社区互动以及为 Paimon 做贡献有很多方式，包括提问、提交 bug 报告、提出新特性建议、参与邮件列表讨论、 贡献代码或文档、改进网站、测试发布候选版本以及撰写相关博客等。

你想做什么？​

为 Apache Paimon 做贡献不只是为项目写代码。下面列出了帮助项目的不同机会：

领域 更多信息
报告 Bug 要报告 Paimon 的问题，请在 Paimon issues 中提交。
请提供你遇到的问题的详细信息，如有可能，请附上能帮助复现问题的描述。
贡献代码 阅读代码贡献指南
代码评审 阅读代码评审指南
发布版本 发布新的 Paimon 版本。
支持用户 在用户邮件列表上回答问题， 查看 Issues 中最新的工单，其中许多实际上是用户提问。
宣传 Paimon 组织或参加 Paimon Meetup，为 Paimon 博客撰稿，在 dev@paimon.apache.org 邮件列表上分享你的会议、meetup 或博客文章。
还有其他问题？请联系 dev@paimon.apache.org 邮件列表获取帮助！

代码贡献指南​

Apache Paimon 依靠志愿者的代码贡献来维护、改进和扩展。我们欢迎为 Paimon 做贡献。

欢迎随时提问。你可以向 Dev 邮件列表发送邮件，或在你正在处理的 issue 下发表评论。

1讨论​

创建 Issue 或发起邮件列表讨论并达成共识

请求认领 issue 时请注意，不能只说一句“请把它分配给我”，你需要说明你对该 issue 的理解和你的设计，如有可能，还需要提供你的 POC 代码。

2实现​

创建 Pull Request，并按照 issue 中商定的方案实现。

1.只有在被分配到 issue 后才创建 PR。2.请关联相关 issue（如有），例如 fix #123。3.请在你自己 fork 的项目中启用 actions。

3评审​

与评审人员协作。


1.确保不包含无关或不必要的格式调整。2.请确保测试通过。3.请不要随意 resolve 评审对话。

4合并​

Paimon 的 committer 检查贡献是否满足要求，并将代码合并到代码库中。

代码评审指南​

每次评审都需要检查以下六个方面。我们建议按顺序检查这些方面，以避免在形式要求未满足或社区尚未就接受该变更达成共识时，把时间花在细致的代码质量评审上。

1. 贡献是否描述清楚？​

检查贡献是否有足够清晰的描述以支撑一次良好的评审。琐碎的变更和修复不需要长篇描述。如果实现完全按照 issue 或开发邮件列表上先前的讨论进行，只需简要引用该讨论即可。

如果实现与共识讨论中商定的方案不同，则需要详细描述实现方式，才能对该贡献进行进一步评审。

2. 该贡献是否需要特定 Committer 的关注？​

某些变更需要特定 committer 的关注和批准。

如果 pull request 需要特别关注，应由被标记（tagged）的 committer/贡献者之一给出最终批准。

3. 整体代码质量是否良好，符合我们希望在 Paimon 中维护的标准？​

  • 代码是否遵循了正确的软件工程实践？代码是否正确、健壮、可维护、可测试？
  • 在修改性能敏感部分时，变更是否考虑了性能影响？
  • 变更是否有足够的测试覆盖？测试执行是否快速？
  • 如果依赖发生了变化，NOTICE 文件是否已更新？

代码规范可参阅 Flink Java 代码风格与质量指南。

4. 文档是否已更新？​

如果 pull request 引入了新特性，应对该特性进行文档化。

成为 Committer​

当你积累了足够的贡献后，就可能被提名为 Paimon 的 Committer。参见 Committer。
