验证发布候选版本

在投票之前，请独立验证发布候选版本。签名的 Paimon 和 PyPaimon 源码归档包才是发布物。 Maven、TestPyPI 和 GitHub Actions 检查是对源码验证的补充，但不能替代源码验证。

只报告你实际执行过的检查、使用过的平台和工具版本。

收集候选版本的输入​

所有取值和 URL 均取自投票邮件：

PAIMON_VERSION="2.0.0"
RC_NUMBER="1"
RC_TAG="release-${PAIMON_VERSION}-rc${RC_NUMBER}"

PAIMON_RC_DIR="paimon-${PAIMON_VERSION}-rc${RC_NUMBER}"
PAIMON_ARCHIVE="apache-paimon-${PAIMON_VERSION}-src.tgz"
PYPAIMON_RC_DIR="pypaimon-${PAIMON_VERSION}-rc${RC_NUMBER}"
PYPAIMON_ARCHIVE="pypaimon-${PAIMON_VERSION}.tar.gz"

从 ASF dist dev 下载候选包，不要从第三方镜像下载：

curl -O "https://dist.apache.org/repos/dist/dev/paimon/${PAIMON_RC_DIR}/${PAIMON_ARCHIVE}"
curl -O "https://dist.apache.org/repos/dist/dev/paimon/${PAIMON_RC_DIR}/${PAIMON_ARCHIVE}.asc"
curl -O "https://dist.apache.org/repos/dist/dev/paimon/${PAIMON_RC_DIR}/${PAIMON_ARCHIVE}.sha512"

curl -O "https://dist.apache.org/repos/dist/dev/paimon/${PYPAIMON_RC_DIR}/${PYPAIMON_ARCHIVE}"
curl -O "https://dist.apache.org/repos/dist/dev/paimon/${PYPAIMON_RC_DIR}/${PYPAIMON_ARCHIVE}.asc"
curl -O "https://dist.apache.org/repos/dist/dev/paimon/${PYPAIMON_RC_DIR}/${PYPAIMON_ARCHIVE}.sha512"

curl -O https://downloads.apache.org/paimon/KEYS

将工作流运行 URL、公告的 commit SHA、Java Nexus staging URL 以及 TestPyPI URL 与这些 文件放在一起对照。它们必须都指向这个 RC。

验证签名和校验和​

gpg --import KEYS
gpg --verify "${PAIMON_ARCHIVE}.asc" "${PAIMON_ARCHIVE}"
gpg --verify "${PYPAIMON_ARCHIVE}.asc" "${PYPAIMON_ARCHIVE}"

确认两个签名均为有效签名，且签名密钥的完整指纹属于 RM，并出现在下载的 KEYS 文件中。 同时检查生成每个签名的确切密钥或子钥：

gpg --with-subkey-fingerprint \
  --list-keys "<FULL_SIGNING_KEY_FINGERPRINT>"

按照 ASF 发布分发政策 的要求， 签名密钥必须是 RSA 且至少 2048 位。新生成的发布密钥应为 RSA 4096。DSA、ECDSA、EdDSA 和 Ed25519 签名密钥不满足该政策，即使签名在密码学上有效。

在 Linux 上：

sha512sum -c "${PAIMON_ARCHIVE}.sha512"
sha512sum -c "${PYPAIMON_ARCHIVE}.sha512"

在 macOS 上：

shasum -a 512 -c "${PAIMON_ARCHIVE}.sha512"
shasum -a 512 -c "${PYPAIMON_ARCHIVE}.sha512"

验证 Git 来源​

git clone https://github.com/apache/paimon.git paimon-candidate-git
git -C paimon-candidate-git fetch --tags
git -C paimon-candidate-git tag -v "${RC_TAG}"
git -C paimon-candidate-git rev-parse "refs/tags/${RC_TAG}^{commit}"

解析出的 commit 必须同时等于投票邮件中的 SHA 和 Release 工作流成功运行的 head_sha。 检查自上个版本以来的提交，确认 RC tag 是从预期的发布分支准备的。RC 打 tag 之后，发布 分支可以继续前进，无需与 RC 提交保持一致；验证对象是为投票宣布的不可变 tag 和候选产物。

检查源码归档包​

解压前先列出归档内容：

tar tzf "${PAIMON_ARCHIVE}" | sed -n '1,100p'
tar tzf "${PYPAIMON_ARCHIVE}" | sed -n '1,100p'

# Use Python as well because macOS tar hides AppleDouble (._*) entries.
python3 - "${PAIMON_ARCHIVE}" "${PYPAIMON_ARCHIVE}" <<'PY'
import sys
import tarfile

for archive in sys.argv[1:]:
    with tarfile.open(archive, "r:*") as source:
        for member in source.getmembers():
            parts = [
                part
                for part in member.name.split("/")
                if part not in ("", ".")
            ]
            if member.name.startswith("/") or ".." in parts:
                raise ValueError(
                    "%s contains an unsafe path: %s"
                    % (archive, member.name)
                )
            if "__MACOSX" in parts or any(
                part.startswith("._") for part in parts
            ):
                raise ValueError(
                    "%s contains macOS metadata: %s"
                    % (archive, member.name)
                )
    print("Archive metadata check passed: " + archive)
PY

至少检查以下内容：

  • Paimon 归档包有且仅有一个名为 paimon-PAIMON_VERSION 的顶层目录。
  • PyPaimon 归档包有且仅有一个名为 pypaimon-PAIMON_VERSION 的顶层目录。
  • LICENSE、NOTICE、README 文件、构建文件、依赖声明以及必需的源文件齐全且正确。
  • 不包含 Git 元数据、IDE 状态文件、凭据、Maven target 目录、Python dist 或 __pycache__ 目录、编译后的 class、生成的 JAR 或无关的二进制文件。
  • 所有打包的第三方材料均与 Apache License 2.0 兼容，并在需要时记录于 LICENSE 或 NOTICE 中。
  • Maven POM 使用 PAIMON_VERSION，不带有 -SNAPSHOT。
  • paimon-python/setup.py 和 PyPaimon 包元数据使用 PAIMON_VERSION，不带有 .dev。

解压 Paimon 候选包：

tar xzf "${PAIMON_ARCHIVE}"

运行仓库的许可证检查。PyPaimon 检查脚本会临时解压其源码包，并在结束时删除该临时目录：

cd "paimon-${PAIMON_VERSION}"
mvn -N -ntp -DskipTests apache-rat:check
cd ..

SOURCE_PACKAGE="${PYPAIMON_ARCHIVE}" \
  "./paimon-${PAIMON_VERSION}/paimon-python/dev/check-licensing.sh"

请审阅生成的报告，而不是只看退出码。许可证检查完成后，解压一份全新的 PyPaimon 源码树， 用于下面的构建和测试步骤：

tar xzf "${PYPAIMON_ARCHIVE}"

从源码归档包构建 Java​

编译签名的源码归档包，并在至少一个受支持的 JDK 上运行适当的测试或冒烟测试。 记录 java -version、mvn -version 和确切的执行范围。投票人无需在本地复现完整的 CI 矩阵，也无需运行任何完整的 JDK 测试流水线。RM 负责在发起投票前评审相关的 CI 结果。

JDK 8 流水线​

该流水线覆盖默认 reactor、Flink 1.x 和 Spark 3.x。作为可选的兼容性检查，投票人可以 运行与打包等价的构建，而无需复现完整的 JDK 8 测试流水线：

(
  cd "paimon-${PAIMON_VERSION}"
  mvn -ntp clean install -DskipTests \
    -Pdocs-and-source,spark3,flink1
)

JDK 11 流水线​

该流水线覆盖 Flink 2.x 和 Iceberg。作为可选的兼容性检查，投票人可以运行与打包等价的 构建，而无需复现完整的 JDK 11 测试流水线：

(
  cd "paimon-${PAIMON_VERSION}"
  mvn -ntp clean install -DskipTests -Pdocs-and-source,flink2 \
    -pl org.apache.paimon:paimon-flink-2.0,org.apache.paimon:paimon-flink-2.1,org.apache.paimon:paimon-flink-2.2,org.apache.paimon:paimon-iceberg \
    -am
)

JDK 17 流水线​

该流水线覆盖 Spark 4.x。作为可选的兼容性检查，投票人可以运行与打包等价的构建，而无需 复现完整的 JDK 17 测试流水线：

(
  cd "paimon-${PAIMON_VERSION}"
  mvn -ntp clean install -DskipTests -Pdocs-and-source,spark4 \
    -pl paimon-spark/paimon-spark-4.0,paimon-spark/paimon-spark-4.1 \
    -am
)

请排查警告和被跳过的模块。编译成功退出本身并不能证明候选版本适合发布。可选的 -DskipTests 命令本身不足以满足投出具有约束力 +1 的要求；请报告你实际完成的 源码构建、测试或冒烟测试范围。这并不要求覆盖每一条 JDK 流水线。

验证 Java staging 仓库​

使用投票邮件中提供的确切的 orgapachepaimon-XXXX staging URL。测试候选版本时， 不要从 Maven Central 或本地缓存解析产物。

对 staging 仓库：

  • 确认其状态为已关闭（closed），使候选版本在投票期间不能再变化。
  • 确认版本为 PAIMON_VERSION，绝不是 snapshot。
  • 确认每个发布的模块都有对应的 POM、主产物、源码 JAR、分离签名以及适用的校验和。 对 Maven 会生成 Javadoc JAR 的模块确认其存在；纯 Scala 和 wrapper 模块可能不会生成。
  • 检查 shaded 和 bundled JAR 中是否包含必需的 META-INF/LICENSE 和 META-INF/NOTICE 内容，以及是否存在意外的重复或被打包的依赖。
  • 在干净的 Maven 仓库中解析代表性产物，并运行一个小型的消费者冒烟测试。

确认流水线边界：

流水线必须包含
JDK 8默认 Java 8 产物、Flink 1.x 和 Spark 3.x
JDK 11Flink 2.x、paimon-flink2-common 和 paimon-iceberg
JDK 17Spark 4.x 及其 Scala 2.13 公共产物

抽查代表性 class 文件的编译目标版本。Java class 主版本号对应关系为：52 对应 Java 8， 55 对应 Java 11，61 对应 Java 17：

JAR_FILE="/path/to/a/representative.jar"
CLASS_NAME="$(jar tf "${JAR_FILE}" | grep '\.class$' | grep -v 'module-info' | head -1 | sed 's#/#.#g;s#\.class$##')"
javap -verbose -classpath "${JAR_FILE}" "${CLASS_NAME}" | grep 'major version'

对每条流水线至少一个代表性 JAR 执行该检查。同时还要确认 Java 8 产物可以被 JDK 8 运行 时加载；仅靠 class 文件检查无法发现所有对新版本 JDK API 的使用。

从源码构建并测试 PyPaimon​

首先在隔离环境中构建官方的 PyPaimon 源码候选包：

python3 -m venv pypaimon-rc-venv
. pypaimon-rc-venv/bin/activate
python -m pip install --upgrade pip setuptools wheel

cd "pypaimon-${PAIMON_VERSION}"
python setup.py sdist bdist_wheel
python -m pip install "dist/pypaimon-${PAIMON_VERSION}"*.whl
python -c "import pypaimon; print('PyPaimon import OK')"
cd ..

检查生成的 sdist 和 wheel。它们必须包含预期的 Python 源码、LICENSE、NOTICE、 README 和包元数据，且不含测试、缓存、凭据或无关的构建输出。

本指南覆盖 Paimon 与 PyPaimon 的联合发布。PyPaimon 候选版本的完整 Python 测试套件 位于签名的 Paimon 源码归档包中；PyPaimon 源码分发包不得单独用于独立发布。在环境 允许的范围内，于尽可能多的受支持 Python 版本上，从 paimon-PAIMON_VERSION/paimon-python 运行测试。项目 CI 选择 Python 3.6、3.7、 3.10 和 3.11 作为主要的兼容性流水线：

(
  cd "paimon-${PAIMON_VERSION}/paimon-python"
  python -m pip install -r dev/requirements.txt
  python -m pip install -r dev/requirements-dev.txt
  python -m pytest pypaimon/tests -v
)

部分可选的集成测试需要额外的服务或包。请记录哪些测试被执行、被跳过或失败。

验证 TestPyPI 候选版本​

在新环境中安装确切的 RC 版本：

python3 -m venv pypaimon-testpypi-venv
. pypaimon-testpypi-venv/bin/activate
python -m pip install \
  --index-url https://test.pypi.org/simple/ \
  --extra-index-url https://pypi.org/simple/ \
  "pypaimon==${PAIMON_VERSION}rc${RC_NUMBER}"
python -c "import pypaimon; print('TestPyPI package OK')"

检查可用文件、包元数据、Python 版本要求、依赖、许可文件，并执行一次代表性的读/写 操作。RC 后缀应是相对最终 PyPaimon 源码候选版本唯一的版本差异；任何源码差异都是 发布阻塞项。

审查 GitHub Actions 证据​

打开投票邮件中链接的工作流运行，确认：

  • 它是由签名的 RC_TAG 触发的；
  • head_sha 等于公告的提交；
  • 公共校验任务确认了 RC_TAG 恰好是 release-PAIMON_VERSION-rcRC_NUMBER，且 PAIMON_VERSION 与根 Maven project.version 一致；
  • JDK 8、JDK 11 和 JDK 17 三条仓库流水线均成功完成；
  • 合并后的 Java 仓库产物带有预期的 tag、commit、清单和 SHA-512 校验和，并能标识 全部三条流水线；
  • 每条流水线中启用 deploy 的预期项目清单，与合并仓库中的 POM、主 JAR 和源码 JAR 一致，Maven 生成的 Javadoc JAR 予以保留；
  • Python 打包和 Python 发布任务的结果有清晰记录；
  • 日志显示了预期的 JDK 和 Python 版本；
  • TestPyPI 版本与投票邮件中的版本一致；
  • 之后的重跑没有用其他提交的产物悄悄替换失败的流水线。

Java 仓库镜像是未签名的工作流输出；请验证已关闭的 Nexus 仓库包含相同的产物，并附有 RM 的签名。仓库流水线负责打包发布产物；它们不是完整的 JDK 测试流水线。投票人无需 要求或复现任何一条 JDK 流水线的完整测试运行。RM 在发起投票前会手动确认相关 CI 检查 已通过；无关的 CI 失败单独评估，不是自动的发布门槛。

报告你的投票​

在投票邮件线程中回复 +1、0 或 -1，说明你的投票是否具有约束力，并列出你完成 的检查。

+1 (binding/non-binding)

Verified:
- signed RC tag and announced commit SHA
- Paimon and PyPaimon GPG signatures, RSA signing-key policy, and SHA-512 checksums
- LICENSE, NOTICE, source-only archive contents, and release versions
- Paimon source build/test scope on <OS/ARCH>, JDK <version>, Maven <version>
- Java staging repository and representative class-file targets
- PyPaimon source build/tests on Python <versions>
- TestPyPI installation and smoke test
- GitHub Actions run provenance, Java package manifests, and Python artifacts

对于 -1，请把失败描述得足够精确，使 RM 能够复现。RM 工作流参见 创建发布版本。
