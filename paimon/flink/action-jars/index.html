Action Jars

Flink 本地集群启动后,你可以使用以下命令执行 action jar。

<FLINK_HOME>/bin/flink run \
 /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
 <action>
 <args>

以下命令用于对表执行 compaction。

<FLINK_HOME>/bin/flink run \
 /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
 compact \
 --path <TABLE_PATH>

Merge Into 表​

Paimon 支持通过 flink run 提交 'merge_into' 作业来实现 "MERGE INTO"。

信息

重要的表属性设置:

  1. 仅主键表支持该特性。
  2. 该 action 不会产生 UPDATE_BEFORE,因此不建议设置 'changelog-producer' = 'input'。

设计参考了如下语法:

MERGE INTO target-table
  USING source_table | source-expr AS source-alias
  ON merge-condition
  WHEN MATCHED [AND matched-condition]
    THEN UPDATE SET xxx
  WHEN MATCHED [AND matched-condition]
    THEN DELETE
  WHEN NOT MATCHED [AND not_matched_condition]
    THEN INSERT VALUES (xxx)
  WHEN NOT MATCHED BY SOURCE [AND not-matched-by-source-condition]
    THEN UPDATE SET xxx
  WHEN NOT MATCHED BY SOURCE [AND not-matched-by-source-condition]
    THEN DELETE

merge_into action 使用 "upsert" 语义而非 "update",即如果行已存在则更新,否则插入。 例如,对于非主键表,你可以更新任意列;但对于主键表,如果你想更新主键, 就必须插入一条与表中现有行主键不同的新行。在这种场景下,"upsert" 语义就很有用。

运行以下命令为表提交一个 'merge_into' 作业。

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    merge_into \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table <target-table> \
    [--target_as <target-table-alias>] \
    --source_table <source_table-name> \
    [--source_sql <sql> ...]\
    --on <merge-condition> \
    --merge_actions <matched-upsert,matched-delete,not-matched-insert,not-matched-by-source-upsert,not-matched-by-source-delete> \
    --matched_upsert_condition <matched-condition> \
    --matched_upsert_set <upsert-changes> \
    --matched_delete_condition <matched-condition> \
    --not_matched_insert_condition <not-matched-condition> \
    --not_matched_insert_values <insert-values> \
    --not_matched_by_source_upsert_condition <not-matched-by-source-condition> \
    --not_matched_by_source_upsert_set <not-matched-upsert-changes> \
    --not_matched_by_source_delete_condition <not-matched-by-source-condition> \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]]
    
You can pass sqls by '--source_sql <sql> [, --source_sql <sql> ...]' to config environment and create source table at runtime.
    
-- Examples:
-- Find all orders mentioned in the source table, then mark as important if the price is above 100 
-- or delete if the price is under 10.
./flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    merge_into \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table T \
    --source_table S \
    --on "T.id = S.order_id" \
    --merge_actions \
    matched-upsert,matched-delete \
    --matched_upsert_condition "T.price > 100" \
    --matched_upsert_set "mark = 'important'" \
    --matched_delete_condition "T.price < 10" 
    
-- For matched order rows, increase the price, and if there is no match, insert the order from the 
-- source table:
./flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    merge_into \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table T \
    --source_table S \
    --on "T.id = S.order_id" \
    --merge_actions \
    matched-upsert,not-matched-insert \
    --matched_upsert_set "price = T.price + 20" \
    --not_matched_insert_values * 

-- For not matched by source order rows (which are in the target table and does not match any row in the
-- source table based on the merge-condition), decrease the price or if the mark is 'trivial', delete them:
./flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    merge_into \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table T \
    --source_table S \
    --on "T.id = S.order_id" \
    --merge_actions \
    not-matched-by-source-upsert,not-matched-by-source-delete \
    --not_matched_by_source_upsert_condition "T.mark <> 'trivial'" \
    --not_matched_by_source_upsert_set "price = T.price - 20" \
    --not_matched_by_source_delete_condition "T.mark = 'trivial'"
    
-- A --source_sql example: 
-- Create a temporary view S in new catalog and use it as source table
./flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    merge_into \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table T \
    --source_sql "CREATE CATALOG test_cat WITH (...)" \
    --source_sql "CREATE TEMPORARY VIEW test_cat.`default`.S AS SELECT order_id, price, 'important' FROM important_order" \
    --source_table test_cat.default.S \
    --on "T.id = S.order_id" \
    --merge_actions not-matched-insert\
    --not_matched_insert_values *

'matched' 相关术语解释:

  1. matched:变更行来自目标表,且每行都能基于 merge-condition 和可选的 matched-condition 匹配到一行源表数据(source ∩ target)。
  2. not matched:变更行来自源表,且所有行都无法基于 merge-condition 和可选的 not_matched_condition 匹配到任何目标表数据(source - target)。
  3. not matched by source:变更行来自目标表,且所有行都无法基于 merge-condition 和可选的 not-matched-by-source-condition 匹配到任何源表数据(target - source)。

参数格式:

  1. matched_upsert_changes:
    col = <source_table>.col | expression [, ...](表示用给定的值设置 <target_table>.col。不要在 'col' 前加 '<target_table>.'。)
    特别地,你可以使用 '*' 以源表所有列进行设置(要求目标表的 schema 与源表一致)。
  2. not_matched_upsert_changes 与 matched_upsert_changes 类似,但你不能引用源表的列,也不能使用 '*'。
  3. insert_values:
    col1, col2, ..., col_end
    必须指定所有列的值。对于每一列,你可以引用 <source_table>.col 或使用表达式。
    特别地,你可以使用 '*' 以源表所有列进行插入(要求目标表的 schema 与源表一致)。
  4. not_matched_condition 不能使用目标表的列来构造条件表达式。
  5. not_matched_by_source_condition 不能使用源表的列来构造条件表达式。
注意
  1. 目标表别名不能与已有表名重复。
  2. 如果源表不在当前 catalog 和当前 database 中,source-table-name 必须是全限定名(database.table;如果创建了新 catalog,则为 catalog.database.table)。 例如:
    (1) 如果源表 'my_source' 在 'my_db' 中,需要全限定:
    --source_table "my_db.my_source"
    (2) 关于 sqls 的示例:
    当 sqls 改变了当前 catalog 和 database 时,可以不全限定源表名:
    --source_sql "CREATE CATALOG my_cat WITH (...)"
    --source_sql "USE CATALOG my_cat"
    --source_sql "CREATE DATABASE my_db"
    --source_sql "USE my_db"
    --source_sql "CREATE TABLE S ..."
    --source_table S
    但在以下情况必须全限定:
    --source_sql "CREATE CATALOG my_cat WITH (...)"
    --source_sql "CREATE TABLE my_cat.`default`.S ..."
    --source_table my_cat.default.S
    在之后的参数中,你可以直接使用 'S' 作为源表名。
  3. 必须至少指定一个 merge action。
  4. 如果同时存在 matched-upsert 和 matched-delete action,则它们的条件也都必须存在(not-matched-by-source-upsert 和 not-matched-by-source-delete 同理)。否则,所有条件都是可选的。
  5. 所有条件、set 变更和 values 都应使用 Flink SQL 语法。为确保整个命令在 Shell 中正常运行,请用 "" 包裹以转义空格,并使用 '\' 转义语句中的特殊字符。 例如:
    --source_sql "CREATE TABLE T (k INT) WITH ('special-key' = '123\!')"

关于 'merge_into' 的更多信息,参见

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    merge_into --help

从表中删除数据​

在 Flink 1.16 及更早版本中,Paimon 仅支持通过 flink run 提交 'delete' 作业来删除记录。

运行以下命令为表提交一个 'delete' 作业。

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    delete \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table <table-name> \
    --where <filter_spec> \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]]
    
filter_spec is equal to the 'WHERE' clause in SQL DELETE statement. Examples:
    age >= 18 AND age <= 60
    animal <> 'cat'
    id > (SELECT count(*) FROM employee)

关于 'delete' 的更多信息,参见

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    delete --help

从 Data Evolution 表中删除数据​

对于 Data Evolution 模式下的非主键 append 表, Paimon 支持与主键表相同的 delete action 来逻辑删除匹配的行。 该 action 会根据目标表的类型分发到相应的实现。普通的 append-only 表不受支持。

该 action 会基于 $row_tracking 系统表的一个固定快照评估过滤条件, 并将匹配的行记录到 deletion vectors 中。它不会重写已有的数据文件或专用的 BLOB 文件。

信息

目标表必须:

  1. 没有主键;
  2. 使用 bucket-unaware 模式(bucket = -1);
  3. 开启 row-tracking.enabled;
  4. 开启 data-evolution.enabled;
  5. 开启 deletion-vectors.enabled。

运行以下命令提交一个 delete 作业:

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    delete \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table <table-name> \
    [--source_sql <sql> [--source_sql <sql> ...]] \
    --where "<filter_spec>" \
    [--sink_parallelism <sink-parallelism>] \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]]

filter_spec 使用 Flink SQL 表达式语法,等价于 SQL WHERE 子句中的谓词。例如:

last_access_time < TIMESTAMP '2026-07-01 00:00:00'
status = 'expired'
id >= 100 AND id < 200

source_sql 可以重复指定。每条语句都会在目标查询之前按顺序执行,因此 Flink SQL 支持的任意有界表 以及可选的视图都可以被注册,并在 filter_spec 的子查询中引用。这并不局限于某个特定的外部系统: JDBC 数据库、数据仓库以及其他有界 connector 都可以使用,只要相应的 connector 在 action 作业的 classpath 中可用。

子查询也是放置源侧过滤条件的合适位置。在下面的示例中, action 读取一张访问状态表,只选出冷数据 URL,然后从目标 Paimon 表中删除匹配的行:

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    delete \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table <table-name> \
    --source_sql "CREATE TEMPORARY TABLE access_state (
        url STRING,
        last_ingest_time TIMESTAMP(3),
        last_request_time TIMESTAMP(3)
    ) WITH (
        'connector' = 'jdbc',
        'url' = '<jdbc-url>',
        'table-name' = '<access-state-table>'
    )" \
    --where "url IN (
        SELECT url
        FROM access_state
        WHERE last_ingest_time < TIMESTAMP '2026-07-01 00:00:00'
          AND (last_request_time IS NULL
               OR last_request_time < TIMESTAMP '2026-07-01 00:00:00')
    )" \
    --sink_parallelism 8

使用子查询可以避免把一个庞大的候选集合拷贝到临时的 Paimon 表中。 外部数据源必须是有界的,这样 action 才能结束并提交一个 delete 快照。

注意
  • 该 action 执行的是逻辑删除。Data Evolution compaction 会保留这些逻辑删除而不是将它们物化, 旧的 data-evolution.compaction.rewrite-row-ids 选项已不再支持。 请单独运行 CALL sys.materialize_deletion_vectors(...) 将生成的 deletion vectors 应用到 最新的表状态并分配新的 row ID。被替换的文件在被历史快照或 tag 引用期间仍会保留; 只有当这些引用和快照过期后,存储空间才会被回收。
  • 不要对同一张表并发运行多个 delete action,或者并发的 APPEND、COMPACT、 OVERWRITE 操作。冲突的提交会导致 action 失败,而不是静默覆盖 deletion vectors。
  • 行位置按 anchor 文件并行聚合。Deletion vectors 随后在相互独立的 rewrite group 之间并行写入。 一个已有的 deletion-vector 索引文件就是一个原子的 rewrite group,且始终只有一个写入者, 因为它可能包含多个 anchor 文件的 deletion vectors。
  • 将大规模删除拆分为有界的批次,以限制 row-tracking 规划、deletion-vector 内存占用 和外部数据源的扫描规模。
  • 快照保留策略必须在作业完成之前保留该 action 的固定基准快照。

更多信息,请运行:

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    delete --help

删除分区​

运行以下命令为表提交一个 'drop_partition' 作业。

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    drop_partition \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table <table-name> \
    [--partition <partition_spec> [--partition <partition_spec> ...]] \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]]

partition_spec:
key1=value1,key2=value2...

关于 'drop_partition' 的更多信息,参见

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    drop_partition --help

重写文件索引​

运行以下命令为表提交一个 'rewrite_file_index' 作业。

    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]]

重新分配 Row ID​

运行以下命令为 data evolution 表提交一个 'reassign_row_id' 作业。 该 action 会重写元数据,使各分区的 row-id 区间不再重叠。

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    reassign_row_id \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table <table-name> \
    [--table_conf <paimon-table-conf> [--table_conf <paimon-table-conf> ...]] \
    [--partition <partition_spec> [--partition <partition_spec> ...]] \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]]

partition_spec:
key1=value1,key2=value2...

关于 'reassign_row_id' 的更多信息,参见

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    reassign_row_id --help

强制启动 Flink 作业​

某些 action(如 create_tag)是轻量级的,默认不会作为作业提交到 Flink 集群。如果你 希望统一所有 action 的使用体验,可以使用 --force_start_flink_job 标志确保将它们作为作业提交。例如,

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    drop_partition \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table <table-name> \
    [--partition <partition_spec> [--partition <partition_spec> ...]] \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]]
    --force_start_flink_job true
