Procedures

Flink 1.18 及更高版本支持 Call Statements, 它让你可以通过编写 SQL 来操作 Paimon 表的数据和元数据,而无需提交 Flink 作业。

在 1.18 中,procedure 仅支持按位置传参。你必须按顺序传入所有参数,如果某些参数不想传, 必须使用 '' 作为占位符。例如,如果你想以并行度 4 对表 default.t 做 compaction, 但不想指定分区和排序策略,call 语句应为
CALL sys.compact('default.t', '', '', '', 'sink.parallelism=4')。

在更高版本中,procedure 支持按名称传参。你可以按任意顺序传参,任何可选参数都可以省略。 对于上面的例子,call 语句为
CALL sys.compact(`table` => 'default.t', options => 'sink.parallelism=4')。

指定分区:我们使用字符串来表示分区过滤条件。"," 表示 "AND",";" 表示 "OR"。例如,如果你想 指定两个分区 date=01 或 date=02,需要写成 'date=01;date=02';如果你想指定一个 date=01 且 day=01 的分区,需要写成 'date=01,day=01'。

表选项语法:我们使用字符串来表示表选项,格式为 'key1=value1,key2=value2...'。

所有可用的 procedure 如下所列。

对表执行 compaction。参数:
  • table(必填):目标表标识符。
  • partitions(可选):分区过滤条件。
  • order_strategy(可选):'order'、'zorder'、'hilbert' 或 'none'。
  • order_by(可选):需要排序的列。'order_strategy' 为 'none' 时留空。
  • options(可选):表的额外动态选项。优先级高于原始的 `tableProp`,低于 `procedureArg`。
  • where(可选):分区谓词(不能与 "partitions" 同时使用)。注意:where 是关键字,需要像 `where` 这样加一对反引号。
  • partition_idle_time(可选):用于对 'partition_idle_time' 时间内没有收到任何新数据的分区执行全量 compaction,且只有这些分区会被 compact。该参数不能与 order compact 一起使用。
  • compact_strategy(可选):决定如何挑选要合并的文件,默认由运行时执行模式决定。'full' 策略仅支持批模式,所有文件都会被选中合并。'minor' 策略:根据指定条件挑选需要合并的文件集合。

    CALL sys.compact(`table` => 'default.T', partitions => 'p=0', order_strategy => 'zorder', order_by => 'a,b', options => 'sink.parallelism=4')

    -- use partition predicate
    CALL sys.compact(`table` => 'default.T', `where` => 'dt>10 and h<20', order_strategy => 'zorder', order_by => 'a,b', options => 'sink.parallelism=4')
