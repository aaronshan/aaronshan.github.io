Lookup Join

Lookup Join 是流式查询中的一种 join 类型。它用于从 Paimon 查询数据来丰富另一张表。该 join 要求一张表具有 processing time 属性,另一张表由 lookup source connector 提供支持。

Paimon 在 Flink 中支持对带主键的表和 append 表进行 lookup join。下面的示例演示了该特性。

准备工作​

首先,创建一张 Paimon 表并进行实时更新。

-- Create a paimon catalog
CREATE CATALOG my_catalog WITH (
  'type'='paimon',
  'warehouse'='hdfs://nn:8020/warehouse/path' -- or 'file://tmp/foo/bar'
);

USE CATALOG my_catalog;

-- Create a table in paimon catalog
CREATE TABLE customers (
    id INT PRIMARY KEY NOT ENFORCED,
    name STRING,
    country STRING,
    zip STRING
);

-- Launch a streaming job to update customers table
INSERT INTO customers ...

-- Create a temporary left table, like from kafka
CREATE TEMPORARY TABLE orders (
    order_id INT,
    total INT,
    customer_id INT,
    proc_time AS PROCTIME()
) WITH (
    'connector' = 'kafka',
    'topic' = '...',
    'properties.bootstrap.servers' = '...',
    'format' = 'csv'
    ...
);

普通 Lookup​

现在你可以在 lookup join 查询中使用 customers 表。

-- enrich each order with customer information
SELECT o.order_id, o.total, c.country, c.zip
FROM orders AS o
JOIN customers
FOR SYSTEM_TIME AS OF o.proc_time AS c
ON o.customer_id = c.id;

重试 Lookup​

如果 orders(主表)的记录因为 customers(lookup 表)的对应数据尚未就绪而 join 不上, 你可以考虑使用 Flink 的延迟重试 Lookup 策略。 仅支持 Flink 1.16+。

-- enrich each order with customer information
SELECT /*+ LOOKUP('table'='c', 'retry-predicate'='lookup_miss', 'retry-strategy'='fixed_delay', 'fixed-delay'='1s', 'max-attempts'='600') */
o.order_id, o.total, c.country, c.zip
FROM orders AS o
JOIN customers
FOR SYSTEM_TIME AS OF o.proc_time AS c
ON o.customer_id = c.id;

异步重试 Lookup​

同步重试的问题在于一条记录会阻塞后续记录,导致整个作业被阻塞。 你可以考虑使用 async + allow_unordered 来避免阻塞,join 失败的记录将不再阻塞其他记录。

-- enrich each order with customer information
SELECT /*+ LOOKUP('table'='c', 'retry-predicate'='lookup_miss', 'output-mode'='allow_unordered', 'retry-strategy'='fixed_delay', 'fixed-delay'='1s', 'max-attempts'='600') */
o.order_id, o.total, c.country, c.zip
FROM orders AS o
JOIN customers /*+ OPTIONS('lookup.async'='true', 'lookup.async-thread-number'='16') */
FOR SYSTEM_TIME AS OF o.proc_time AS c
ON o.customer_id = c.id;
信息

如果主表(orders)是 CDC 流,Flink SQL 会忽略 allow_unordered(仅支持 append 流), 你的流式作业可能会被阻塞。你可以尝试使用 Paimon 的 audit_log 系统表特性来绕过这个问题 (将 CDC 流转换为 append 流)。

大规模 Lookup(固定 Bucket)​

默认情况下,每个 Flink subtask 都会存储一份 lookup 表的完整副本。如果 customers(lookup 表)的数据量 对单个 subtask 来说太大,你可以按如下方式启用 shuffle lookup 优化 (适用于 Flink 2.0+ 和固定 bucket 的 Paimon 表)。该优化会将同一 bucket 的数据发送到指定的 subtask,因此每个 Flink subtask 只需存储整体数据的一部分。

-- enrich each order with customer information
SELECT /*+ LOOKUP('table'='c', 'shuffle'='true') */
o.order_id, o.total, c.country, c.zip
FROM orders AS o
JOIN customers
FOR SYSTEM_TIME AS OF o.proc_time AS c
ON o.customer_id = c.id;

请注意,只有当 join key 包含所有 bucket key 时,该优化才会生效。

动态分区​

在传统数仓中,每个分区通常维护最新的全量数据,因此这种分区表只需 join 最新的分区。 Paimon 针对该场景专门开发了 max_pt 特性。

创建 Paimon 分区表

CREATE TABLE customers (
  id INT,
  name STRING,
  country STRING,
  zip STRING,
  dt STRING,
  PRIMARY KEY (id, dt) NOT ENFORCED
) PARTITIONED BY (dt);

Lookup Join

SELECT o.order_id, o.total, c.country, c.zip
FROM orders AS o
JOIN customers /*+ OPTIONS('scan.partitions'='max_pt()', 'lookup.dynamic-partition.refresh-interval'='1 h') */
FOR SYSTEM_TIME AS OF o.proc_time AS c
ON o.customer_id = c.id;

Lookup 节点会自动刷新到最新分区,并查询最新分区的数据。

scan.partitions 选项也可以以 key1=value1,key2=value2 的形式指定固定分区。 多个分区之间用分号(;)分隔。 指定固定分区时,该选项也可以用于批式 join。

scan.partitions 选项还可以对父分区指定 max_pt(),形式为 key1=max_pt(),key2=max_pt()。 此时会加载最新父分区下的所有子分区。例如,如果分区键为 'year', 'day', 'hh', 你可以指定 year=max_pt(),它会找到 year 的最新分区并加载其所有子分区用于 lookup。 仅支持按层级依次指定分区。例如,设置 year=max_pt(),hh=max_pt() 时,hh=max_pt() 没有意义。

查询服务(Query Service)​

你可以运行一个 Flink 流式作业为表启动查询服务。当 QueryService 存在时,Flink Lookup Join 会优先从它获取数据,这将有效提升查询性能。

  • Flink SQL
  • Flink Action
CALL sys.query_service('database_name.table_name', parallelism);
<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    query_service \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table <table-name> \
    [--parallelism <parallelism>] \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]]
