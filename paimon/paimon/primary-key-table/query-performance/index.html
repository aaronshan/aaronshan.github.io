查询性能

表模式​

表 schema 对查询性能的影响最大。参见表模式。

对于 Merge On Read 表,最需要注意的是 bucket 数量,它会限制 读取数据的并发度。

对于 MOW(Deletion Vectors)表、COW 表或 Read Optimized 表, 读取数据的并发度没有限制,并且它们还可以利用非主键列上的一些过滤条件。

聚合下推​

开启 Deletion Vectors 的表支持聚合下推:

SELECT COUNT(*) FROM TABLE WHERE DT = '20230101';

该查询可以在编译阶段被加速,返回非常快。

对于 Spark SQL,使用默认 metadata.stats-mode 的表可以被加速:

SELECT MIN(a), MAX(b) FROM TABLE WHERE DT = '20230101';

Min/Max 查询同样可以在编译阶段被加速,返回非常快。

通过主键过滤进行数据跳过​

对于普通的固定 bucket 表(例如 bucket = 5),主键上的过滤条件可以大幅 加速查询,减少大量文件的读取。

通过文件索引进行数据跳过​

对于经历过 full compaction 的文件,或配置了 'deletion-vectors.enabled' 的 Primary Key 表,你可以使用 文件索引,它会在读取侧通过索引过滤文件。

定义 file-index.bitmap.columns 后,数据文件索引是一个外部索引文件,Paimon 会为每个数据文件创建 对应的索引文件。如果索引文件很小,会直接存储在 manifest 中, 否则存储在数据文件所在目录。每个数据文件对应一个索引文件,索引文件有独立的文件 定义,可以包含多个列的多种类型索引。

不同的文件索引在不同场景下效率不同。例如 bloom filter 可以在点查 场景下加速查询,bitmap 会占用更多空间,但准确率更高。

  • BloomFilter:file-index.bloom-filter.columns。
  • Bitmap:file-index.bitmap.columns。
  • Range Bitmap:file-index.range-bitmap.columns。

如果你希望为已有表添加文件索引且不重写任何数据,可以使用 rewrite_file_index 过程。在 使用该过程之前,你应该在目标表上配置好相应配置。可以使用 ALTER 语句为表配置 file-index.<filter-type>.columns。

调用方式参见 flink procedures。

Bucketed Join​

固定 Bucket 表(例如 bucket = 10)可以在批量查询中必要时避免 shuffle,例如,你可以 使用以下 Spark SQL 读取 Paimon 表:

SET spark.sql.sources.v2.bucketing.enabled = true;

CREATE TABLE FACT_TABLE (order_id INT, f1 STRING) TBLPROPERTIES ('bucket'='10', 'primary-key' = 'order_id');

CREATE TABLE DIM_TABLE (order_id INT, f2 STRING) TBLPROPERTIES ('bucket'='10', 'primary-key' = 'order_id');

SELECT * FROM FACT_TABLE AS fact JOIN DIM_TABLE AS dim ON fact.order_id = dim.order_id;

spark.sql.sources.v2.bucketing.enabled 配置用于为 V2 数据源启用 bucketing。开启后, Spark 会识别 V2 数据源通过 SupportsReportPartitioning 上报的特定分布, 并在必要时尝试避免 shuffle。

如果两张表具有相同的 bucketing 策略和相同的 bucket 数量, 代价高昂的 join shuffle 就可以被避免。
