Aggregation

信息

注意:请在 Flink SQL TableConfig 中始终将 table.exec.sink.upsert-materialize 设置为 NONE。

有时用户只关心聚合后的结果。aggregation Merge Engine 按照聚合函数,将同一主键下的 每个 value 字段用最新数据逐条聚合。

每个不属于主键的字段都可以指定一个聚合函数,通过 fields.<field-name>.aggregate-function 表属性指定;未指定时默认使用 last_non_null_value 聚合。例如,考虑下面的 表定义。

  • Flink
CREATE TABLE my_table (
    product_id BIGINT,
    price DOUBLE,
    sales BIGINT,
    PRIMARY KEY (product_id) NOT ENFORCED
) WITH (
    'merge-engine' = 'aggregation',
    'fields.price.aggregate-function' = 'max',
    'fields.sales.aggregate-function' = 'sum'
);

字段 price 将按 max 函数聚合,字段 sales 将按 sum 函数聚合。给定两条 输入记录 <1, 23.0, 15> 和 <1, 30.2, 20>,最终结果将是 <1, 30.2, 35>。

聚合函数​

当前支持的聚合函数及数据类型如下:

sum​

sum 函数对多行的值进行聚合。 支持 DECIMAL、TINYINT、SMALLINT、INTEGER、BIGINT、FLOAT 和 DOUBLE 数据类型。

product​

product 函数可以跨多行计算乘积。 支持 DECIMAL、TINYINT、SMALLINT、INTEGER、BIGINT、FLOAT 和 DOUBLE 数据类型。

count​

在需要统计满足特定条件的行数的场景中,可以使用 SUM 函数来实现。把条件表示为一个 布尔值(TRUE 或 FALSE)并将其转换为数值,即可有效地统计行数。在这种方式中,TRUE 转换为 1,FALSE 转换为 0。

例如,如果你有一张 orders 表,想统计满足某个条件的行数,可以使用以下查询:

SELECT SUM(CASE WHEN condition THEN 1 ELSE 0 END) AS count
FROM orders;

max​

max 函数识别并保留最大值。 支持 BOOLEAN、CHAR、VARCHAR、BINARY、VARBINARY、DECIMAL、TINYINT、SMALLINT、INTEGER、BIGINT、FLOAT、DOUBLE、DATE、TIME、TIMESTAMP 和 TIMESTAMP_LTZ 数据类型。

min​

min 函数识别并保留最小值。 支持 BOOLEAN、CHAR、VARCHAR、BINARY、VARBINARY、DECIMAL、TINYINT、SMALLINT、INTEGER、BIGINT、FLOAT、DOUBLE、DATE、TIME、TIMESTAMP 和 TIMESTAMP_LTZ 数据类型。

last_value​

last_value 函数用最新导入的值替换之前的值。 支持所有数据类型。

last_non_null_value​

last_non_null_value 函数用最新的非 null 值替换之前的值。 支持所有数据类型。

listagg​

listagg 函数将多个字符串值拼接为一个字符串。 支持 STRING 数据类型。 每个不属于主键的字段都可以通过 fields.<field-name>.list-agg-delimiter 表属性指定一个 listagg 分隔符,否则默认使用 ","。 你可以使用 fields.<field-name>.distinct=true 对按 fields.<field-name>.list-agg-delimiter 分割后的值去重。

bool_and​

bool_and 函数判断布尔集合中的所有值是否都为 true。 支持 BOOLEAN 数据类型。

bool_or​

bool_or 函数判断布尔集合中是否至少有一个值为 true。 支持 BOOLEAN 数据类型。

first_value​

first_value 函数从数据集中取出第一个值(原文如此)。 支持所有数据类型。

first_non_null_value​

first_non_null_value 函数选择数据集中第一个非 null 值。 支持所有数据类型。

rbm32​

rbm32 函数将多个序列化的 32 位 RoaringBitmap 聚合为单个 RoaringBitmap。 支持 VARBINARY 数据类型,且必须是序列化的 32 位 RoaringBitmap。

RoaringBitmap 是一种压缩位图,能高效表示整数集合。rbm32 聚合器适用于需要合并 多个位图集合,或需要在大型整数数据集上执行集合并集操作的场景。

示例:

-- Create a table to store user visit data with bitmap aggregation
CREATE TABLE user_visits (
  user_id INT PRIMARY KEY NOT ENFORCED,
  visit_bitmap VARBINARY
) WITH (
  'merge-engine' = 'aggregation',
  'fields.visit_bitmap.aggregate-function' = 'rbm32'
);

-- Register a UDF to create RoaringBitmap from user IDs
-- CREATE TEMPORARY FUNCTION TO_BITMAP AS 'BitmapUDF';

-- Insert data with bitmap representations
INSERT INTO user_visits VALUES
  (1, TO_BITMAP(100, 101, 102)),  -- User 1 visited pages 100, 101, 102
  (2, TO_BITMAP(101, 103)),       -- User 2 visited pages 101, 103
  (3, TO_BITMAP(102, 104));       -- User 3 visited pages 102, 104

-- When the same user_id is inserted again, the bitmaps will be merged
INSERT INTO user_visits VALUES
  (1, TO_BITMAP(103, 105)),       -- User 1 also visited pages 103, 105
  (2, TO_BITMAP(104, 106));       -- User 2 also visited pages 104, 106

-- The final result will have merged bitmaps for each user
-- User 1: pages 100, 101, 102, 103, 105
-- User 2: pages 101, 103, 104, 106
-- User 3: pages 102, 104

rbm64​

rbm64 函数将多个序列化的 64 位 Roaring64Bitmap 聚合为单个 Roaring64Bitmap。 支持 VARBINARY 数据类型,且必须是序列化的 64 位 RoaringBitmap。

与 rbm32 类似,但支持 64 位整数,适用于非常大的整数值, 或需要表示超出 32 位范围(最大 2^31-1)的集合的场景。

示例:

-- Create a table to store large-scale user interaction data
CREATE TABLE user_interactions (
  session_id BIGINT PRIMARY KEY NOT ENFORCED,
  interaction_bitmap VARBINARY
) WITH (
  'merge-engine' = 'aggregation',
  'fields.interaction_bitmap.aggregate-function' = 'rbm64'
);

-- Register a UDF to create Roaring64Bitmap from large user IDs
-- CREATE TEMPORARY FUNCTION TO_BITMAP64 AS 'Bitmap64UDF';

-- Insert data with 64-bit bitmap representations
INSERT INTO user_interactions VALUES
  (1001, TO_BITMAP64(1000000001L, 1000000002L, 1000000003L)),
  (1002, TO_BITMAP64(1000000002L, 1000000004L)),
  (1003, TO_BITMAP64(1000000003L, 1000000005L));

-- Merge additional interactions
INSERT INTO user_interactions VALUES
  (1001, TO_BITMAP64(1000000004L, 1000000006L)),
  (1002, TO_BITMAP64(1000000005L, 1000000007L));

-- The final result will have merged 64-bit bitmaps for each session

rbm32 和 rbm64 聚合器的工作流程是:

  1. 将输入的 VARBINARY 数据反序列化为 RoaringBitmap 对象
  2. 执行按位或(OR)操作合并位图
  3. 将结果序列化回 VARBINARY 格式

使用 RoaringBitmap 函数:

Paimon 目前不提供用于创建位图的内置 Flink UDF。你有两个选择:

  1. 以编程方式创建位图:在应用代码中创建,并插入序列化后的字节
  2. 创建自定义 Flink UDF:将原始整数转换为序列化位图格式

以下是两种方式各自的示例:

方式 1:以编程方式创建位图(Java/Scala)

// Create bitmaps programmatically
RoaringBitmap32 bitmap1 = RoaringBitmap32.bitmapOf(100, 101, 102);
RoaringBitmap32 bitmap2 = RoaringBitmap32.bitmapOf(101, 103);
RoaringBitmap32 bitmap3 = RoaringBitmap32.bitmapOf(102, 104);

byte[] serialized1 = bitmap1.serialize();
byte[] serialized2 = bitmap2.serialize();
byte[] serialized3 = bitmap3.serialize();

INSERT INTO user_page_visits VALUES
    (1, CAST(x'...' AS VARBINARY)),  -- serialized1 bytes
    (2, CAST(x'...' AS VARBINARY)),  -- serialized2 bytes
    (3, CAST(x'...' AS VARBINARY));  -- serialized3 bytes

方式 2:自定义 Flink UDF

-- Create the aggregation table
CREATE TABLE user_page_visits (
    user_id INT PRIMARY KEY NOT ENFORCED,
    page_visits VARBINARY
) WITH (
    'merge-engine' = 'aggregation',
    'fields.page_visits.aggregate-function' = 'rbm32'
);

-- Register custom UDFs (you need to implement these)

-- Use the UDFs
INSERT INTO user_page_visits VALUES
    (1, TO_BITMAP(100, 101, 102)),
    (2, TO_BITMAP(101, 103)),
    (3, TO_BITMAP(102, 104));

-- Query with UDFs
SELECT user_id, FROM_BITMAP(page_visits) as unique_pages
FROM user_page_visits;

SELECT user_id,
       BITMAP_CONTAINS(page_visits, 101) as visited_page_101
FROM user_page_visits
WHERE user_id = 1;

UDF 实现示例(Java):

// BitmapUDF - Converts integers to serialized RoaringBitmap
public static class BitmapUDF extends ScalarFunction {
    public byte[] eval(Integer... values) {
        RoaringBitmap32 bitmap = new RoaringBitmap32();
        for (Integer value : values) {
            if (value != null) {
                bitmap.add(value);
            }
        }
        return bitmap.serialize();
    }
}

// BitmapCountUDF - Gets cardinality from serialized RoaringBitmap
public static class BitmapCountUDF extends ScalarFunction {
    public Long eval(byte[] bitmapBytes) {
        if (bitmapBytes == null) {
            return 0L;
        }
        try {
            RoaringBitmap32 bitmap = new RoaringBitmap32();
            bitmap.deserialize(ByteBuffer.wrap(bitmapBytes));
            return bitmap.getCardinality();
        } catch (IOException e) {
            throw new RuntimeException("Failed to deserialize bitmap", e);
        }
    }
}

// BitmapContainsUDF - Checks if value exists in bitmap
public static class BitmapContainsUDF extends ScalarFunction {
    public Boolean eval(byte[] bitmapBytes, Integer value) {
        if (bitmapBytes == null || value == null) {
            return false;
        }
        try {
            RoaringBitmap32 bitmap = new RoaringBitmap32();
            bitmap.deserialize(ByteBuffer.wrap(bitmapBytes));
            return bitmap.contains(value);
        } catch (IOException e) {
            throw new RuntimeException("Failed to deserialize bitmap", e);
        }
    }
}

nested_update​

nested_update 函数将多行收集到一个 array<row> 中(即所谓的"嵌套表")。支持 ARRAY<ROW> 数据类型。

使用 fields.<field-name>.nested-key=pk0,pk1,... 指定嵌套表的主键。如果没有 key,行将被追加到 array<row> 中。

使用 fields.<field-name>.nested-key-null-strategy=<merge|ignore|error> 指定当 nested-key 不满足主键语义(例如主键字段包含 null 值)时如何处理行。

  • merge(默认):即使 nested-key 不满足主键语义也合并行。与不配置该选项时的行为相同。
  • ignore:忽略 nested-key 包含 null 值的行,因为它们不满足主键语义。
  • error:如果 nested-key 包含 null 值则抛出异常,因为主键字段不能为 null。

使用 fields.<field-name>.nested-sequence-field=seq0,seq1,... 控制嵌套表的更新顺序,使用时必须配置 fields.<field-name>.nested-key。

使用 fields.<field-name>.count-limit=<Integer> 指定嵌套表中的最大行数。没有 nested-key 时,会按顺序 选取数据直到达到 limit;但如果指定了 nested-key,则无法保证聚合结果的正确性。该选项可用于 避免异常输入。

示例:

  • Flink
  -- orders table
  CREATE TABLE orders (
    order_id BIGINT PRIMARY KEY NOT ENFORCED,
    user_name STRING,
    address STRING
  );
  
  -- sub orders that have the same order_id 
  -- belongs to the same order
  CREATE TABLE sub_orders (
    order_id BIGINT,
    sub_order_id INT,
    product_name STRING,
    price BIGINT,
    PRIMARY KEY (order_id, sub_order_id) NOT ENFORCED
  );
  
  -- wide table
  CREATE TABLE order_wide (
    order_id BIGINT PRIMARY KEY NOT ENFORCED,
    user_name STRING,
    address STRING,
    sub_orders ARRAY<ROW<sub_order_id BIGINT, product_name STRING, price BIGINT>>
  ) WITH (
    'merge-engine' = 'aggregation',
    'fields.sub_orders.aggregate-function' = 'nested_update',
    'fields.sub_orders.nested-key' = 'sub_order_id'
  );
  
  -- widen
  INSERT INTO order_wide
  
  SELECT 
    order_id, 
    user_name,
    address, 
    CAST (NULL AS ARRAY<ROW<sub_order_id BIGINT, product_name STRING, price BIGINT>>) 
  FROM orders
  
  UNION ALL 
    
  SELECT 
    order_id, 
    CAST (NULL AS STRING), 
    CAST (NULL AS STRING), 
    ARRAY[ROW(sub_order_id, product_name, price)] 
  FROM sub_orders;
  
  -- query using UNNEST
  SELECT order_id, user_name, address, sub_order_id, product_name, price 
  FROM order_wide, UNNEST(sub_orders) AS so(sub_order_id, product_name, price)

nested_partial_update​

nested_partial_update 函数将多行收集到一个 array<row> 中(即所谓"嵌套表")。支持 ARRAY<ROW> 数据类型。你需要使用 fields.<field-name>.nested-key=pk0,pk1,... 指定嵌套表的主键。 每行的值通过部分更新某些列的方式写入。

使用 fields.<field-name>.nested-key-null-strategy=<merge|ignore|error> 指定当 nested-key 不满足主键语义(例如主键字段包含 null 值)时如何处理行。

  • merge(默认):即使 nested-key 不满足主键语义也合并行。与不配置该选项时的行为相同。
  • ignore:忽略 nested-key 包含 null 值的行,因为它们不满足主键语义。
  • error:如果 nested-key 包含 null 值则抛出异常,因为主键字段不能为 null。

collect​

collect 函数将元素收集到一个 Array 中。你可以设置 fields.<field-name>.distinct=true 去除重复元素。 仅支持 ARRAY 类型。

merge_map​

merge_map 函数合并输入的 map。仅支持 MAP 类型。

merge_map_with_keytime​

merge_map_with_keytime 函数基于时间戳以 key 粒度部分更新地合并输入的 map。 map 中的每个 key 都携带自己的时间戳,合并时每个 key 只保留时间戳最新的值。 仅支持 MAP<key_type, ROW<value_field, ts_field>> 类型,其中 ROW 必须至少有 2 个字段。

使用 fields.<field-name>.ts-field=<field_name_in_row> 指定 ROW 类型中时间戳字段的名称。 未指定时,默认使用 ROW 的最后一个字段作为时间戳。

当某个 key 的值为 null 时,该 key 会从 map 中移除。 当时间戳字段为 null 时,该条目会被跳过。

示例:

  • Flink
  CREATE TABLE my_table (
      biz_order_id STRING,
      key_value_map MAP\<STRING, ROW\<`value` STRING, `ts` STRING>>,
      PRIMARY KEY (biz_order_id) NOT ENFORCED
  ) WITH (
      'merge-engine' = 'aggregation',
      'fields.key_value_map.aggregate-function' = 'merge_map_with_keytime',
      'fields.key_value_map.ts-field' = 'ts'
  );

给定以下输入记录:

biz_order_idkey_value_map
1{"product_name": ("iPhone", "100"), "color": ("Black", "100")}
1{"product_name": ("iPad", "200"), "price": ("999", "200")}
1{"color": ("White", "50")}

最终结果为: {"product_name": ("iPad", "200"), "color": ("Black", "100"), "price": ("999", "200")} 注意,color 仍为 "Black",因为它的既有时间戳 "100" 大于新来的 "50"。

基数草图(cardinality sketches)类型​

Paimon 使用 Apache DataSketches 随机流式算法库来实现 sketch 模块。DataSketches 库包含多种类型的 sketch,每种都面向不同的问题而设计。Paimon 支持 HyperLogLog(HLL)和 Theta 两种基数 sketch。

HyperLogLog​

HyperLogLog(HLL)sketch 聚合器是一种非常紧凑的近似去重计数 sketch 算法。你也可以使用 HLL 聚合器计算多个 HLL sketch 的并集。

Theta​

Theta sketch 是一种支持集合运算的近似去重计数 sketch 算法。Theta sketch 可以计算集合之间的重叠,因此你能够在 sketch 对象之间计算并集、交集或差集。

选择 sketch 类型​

HLL 和 Theta sketch 都支持近似去重计数;但 HLL sketch 的结果更准确,占用的存储空间更少。Theta sketch 更灵活,但需要显著更多的内存。

针对你的使用场景选择近似算法时,请考虑以下因素:

如果使用场景是去重计数和合并 sketch 对象,使用 HLL sketch。 如果需要计算并集、交集或差集运算,使用 Theta sketch。 HLL sketch 与 Theta sketch 之间不能互相合并。

hll_sketch​

hll_sketch 函数将多个序列化的 Sketch 对象聚合为单个 Sketch。 支持 VARBINARY 数据类型。

示例:

  • Flink
  -- source table
  CREATE TABLE VISITS (
    id INT PRIMARY KEY NOT ENFORCED,
    user_id STRING
  );
  
  -- agg table
  CREATE TABLE UV_AGG (
    id INT PRIMARY KEY NOT ENFORCED,
    uv VARBINARY
  ) WITH (
    'merge-engine' = 'aggregation',
    'fields.uv.aggregate-function' = 'hll_sketch'
  );
  
  -- Register the following class as a Flink function with the name "HLL_SKETCH" 
  -- for example: create TEMPORARY function HLL_SKETCH as  'HllSketchFunction';
  -- which is used to transform input to sketch bytes array:
  --
  -- public static class HllSketchFunction extends ScalarFunction {
  --   public byte[] eval(String user_id) {
  --     HllSketch hllSketch = new HllSketch();
  --     hllSketch.update(user_id);
  --     return hllSketch.toCompactByteArray();
  --   }
  -- }
  --
  INSERT INTO UV_AGG SELECT id, HLL_SKETCH(user_id) FROM VISITS;

  -- Register the following class as a Flink function with the name "HLL_SKETCH_COUNT"
  -- for example: create TEMPORARY function HLL_SKETCH_COUNT as  'HllSketchCountFunction';
  -- which is used to get cardinality from sketch bytes array:
  -- 
  -- public static class HllSketchCountFunction extends ScalarFunction { 
  --   public Double eval(byte[] sketchBytes) {
  --     if (sketchBytes == null) {
  --       return 0d; 
  --     } 
  --     return HllSketch.heapify(sketchBytes).getEstimate(); 
  --   } 
  -- }
  --
  -- Then we can get user cardinality based on the aggregated field.
  SELECT id, HLL_SKETCH_COUNT(UV) as uv FROM UV_AGG;

theta_sketch​

theta_sketch 函数将多个序列化的 Sketch 对象聚合为单个 Sketch。 支持 VARBINARY 数据类型。

示例:

  • Flink
  -- source table
  CREATE TABLE VISITS (
    id INT PRIMARY KEY NOT ENFORCED,
    user_id STRING
  );
  
  -- agg table
  CREATE TABLE UV_AGG (
    id INT PRIMARY KEY NOT ENFORCED,
    uv VARBINARY
  ) WITH (
    'merge-engine' = 'aggregation',
    'fields.uv.aggregate-function' = 'theta_sketch'
  );
  
  -- Register the following class as a Flink function with the name "THETA_SKETCH" 
  -- for example: create TEMPORARY function THETA_SKETCH as  'ThetaSketchFunction';
  -- which is used to transform input to sketch bytes array:
  --
  -- public static class ThetaSketchFunction extends ScalarFunction {'{'}
  --   public byte[] eval(String user_id) {'{'}
  --     UpdateSketch updateSketch = UpdateSketch.builder().build();
  --     updateSketch.update(user_id);
  --     return updateSketch.compact().toByteArray();
  --   {'}'}
  -- {'}'}
  --
  INSERT INTO UV_AGG SELECT id, THETA_SKETCH(user_id) FROM VISITS;

  -- Register the following class as a Flink function with the name "THETA_SKETCH_COUNT"
  -- for example: create TEMPORARY function THETA_SKETCH_COUNT as  'ThetaSketchCountFunction';
  -- which is used to get cardinality from sketch bytes array:
  -- 
  -- public static class ThetaSketchCountFunction extends ScalarFunction {'{'} 
  --   public Double eval(byte[] sketchBytes) {'{'}
  --     if (sketchBytes == null) {'{'}
  --       return 0d; 
  --     {'}'} 
  --     return Sketches.wrapCompactSketch(Memory.wrap(sketchBytes)).getEstimate(); 
  --   {'}'} 
  -- {'}'}
  --
  -- Then we can get user cardinality based on the aggregated field.
  SELECT id, THETA_SKETCH_COUNT(UV) as uv FROM UV_AGG;
信息

对于流式查询,aggregation Merge Engine 必须与 lookup 或 full-compaction changelog producer 搭配使用。(input changelog producer 也支持,但只会返回输入记录。)

Retraction​

只有 sum、product、collect、merge_map、nested_update、last_value 和 last_non_null_value 支持 retraction(UPDATE_BEFORE 和 DELETE),其他聚合函数不支持 retraction。 如果希望某些函数忽略 retraction 消息,可以配置: 'fields.${field_name}.ignore-retract'='true'。

last_value 和 last_non_null_value 在接收 retract 消息时只是将字段置为 null。

当累加器为 null 时,product 对 retract 消息返回 null。

collect 和 merge_map 会尽最大努力处理 retraction 消息,但不 保证结果准确。处理 retraction 消息时可能出现以下行为:

  1. 如果记录乱序,可能无法正确处理 retraction 消息。例如,表使用 collect, 上游分别发送 +I['A', 'B'] 和 -U['A']。如果表先收到 -U['A'],它什么都做不了;随后收到 +I['A', 'B'],合并结果将是 +I['A', 'B'] 而不是 +I['B']。

  2. 一个上游的 retract 消息会撤回由多个上游合并而来的结果。例如,表使用 merge_map,一个上游发送 +I[1->A],另一个上游发送 +I[1->B],随后又发送 -D[1->B]。表会 先把两条插入值合并为 +I[1->B],然后 -D[1->B] 会撤回整个结果,最终 结果是一个空 map,而不是 +I[1->A]。
