数据进化(Data Evolution)

面向 Data Evolution 模式的 PyPaimon。参见 Data Evolution。

前置条件​

要使用部分列更新 / data evolution,请在创建表时同时启用以下两个配置项:

  • row-tracking.enabled: true
  • data-evolution.enabled: true

按行 ID 更新列​

你可以使用 update_by_arrow_with_row_id 更新 data evolution 表中的列。

输入数据应包含 _ROW_ID 列。更新操作会自动排序并将每个 _ROW_ID 匹配到其对应的 first_row_id,然后将具有相同 first_row_id 的行分组, 写入单独的文件。

_ROW_ID 更新的要求

  • 仅更新列:包含 _ROW_ID 以及你要更新的列(部分 schema 即可)。
import pyarrow as pa
from pypaimon import CatalogFactory, Schema

catalog = CatalogFactory.create({'warehouse': '/tmp/warehouse'})
catalog.create_database('default', False)

simple_pa_schema = pa.schema([
  ('f0', pa.int8()),
  ('f1', pa.int16()),
])
schema = Schema.from_pyarrow_schema(simple_pa_schema,
                                    options={'row-tracking.enabled': 'true', 'data-evolution.enabled': 'true'})
catalog.create_table('default.test_row_tracking', schema, False)
table = catalog.get_table('default.test_row_tracking')

# 写入全部列
write_builder = table.new_batch_write_builder()
table_write = write_builder.new_write()
table_commit = write_builder.new_commit()
expect_data = pa.Table.from_pydict({
  'f0': [-1, 2],
  'f1': [-1001, 1002]
}, schema=simple_pa_schema)
table_write.write_arrow(expect_data)
table_commit.commit(table_write.prepare_commit())
table_write.close()
table_commit.close()

# 更新部分列
write_builder = table.new_batch_write_builder()
table_update = write_builder.new_update().with_update_type(['f0'])
table_commit = write_builder.new_commit()
data2 = pa.Table.from_pydict({
  '_ROW_ID': [0, 1],
  'f0': [5, 6],
}, schema=pa.schema([
  ('_ROW_ID', pa.int64()),
  ('f0', pa.int8()),
]))
cmts = table_update.update_by_arrow_with_row_id(data2)
table_commit.commit(cmts)
table_commit.close()

# 内容应为:
#   'f0': [5, 6],
#   'f1': [-1001, 1002]

按谓词更新列​

你可以使用 update_by_predicate 执行类似 SQL 的 UPDATE ... SET ... WHERE ... 操作。赋值可以是字面量,也可以是可调用对象(callable)。callable 要求显式指定 read_columns,并且可能以多个有界批次执行。它们必须是确定性的、 无副作用的、行局部的,并且每个输入行返回一个 Arrow 值。输入 从规划本次更新所用的同一固定快照中读取。 当全局索引可用时,update_by_predicate 会以 scalar-index.search-mode=full 在配置的某一时间点扫描快照上发现匹配的 _ROW_ID 值;如果未配置, 则使用最新快照。

import pyarrow as pa
from pypaimon import CatalogFactory, Schema

catalog = CatalogFactory.create({'warehouse': '/tmp/warehouse'})
catalog.create_database('default', False)

pa_schema = pa.schema([
    ('id', pa.int32()),
    ('name', pa.string()),
    ('age', pa.int32()),
])
schema = Schema.from_pyarrow_schema(
    pa_schema,
    options={'row-tracking.enabled': 'true', 'data-evolution.enabled': 'true'},
)
catalog.create_table('default.users_update', schema, False)
table = catalog.get_table('default.users_update')

# 写入初始数据
write_builder = table.new_batch_write_builder()
write = write_builder.new_write()
commit = write_builder.new_commit()
write.write_arrow(pa.Table.from_pydict(
    {'id': [1, 2, 3], 'name': ['Alice', 'Bob', 'Charlie'], 'age': [30, 25, 28]},
    schema=pa_schema,
))
commit.commit(write.prepare_commit())
write.close()
commit.close()

# UPDATE users_update SET age = age + 1 WHERE id IN (1, 3)
write_builder = table.new_batch_write_builder()
table_update = write_builder.new_update()
predicate = table_update.new_predicate_builder().is_in('id', [1, 3])
messages = table_update.update_by_predicate(
    predicate,
    {'age': lambda rows: pa.compute.add(rows['age'], 1)},
    read_columns=['age'],
)

commit = write_builder.new_commit()
commit.commit(messages)
commit.close()

删除行​

使用 delete_by_predicate 执行类似 SQL 的 DELETE ... WHERE ... 操作。 对于行级删除,目标表除前置条件外还必须启用 deletion vector:

  • deletion-vectors.enabled: true

删除会以 deletion-vector 索引更新的形式写入。如果谓词只 引用分区列,PyPaimon 会使用分区覆盖/删除路径,而不是扫描 _ROW_ID 值;这种仅分区列的快速路径不需要 deletion vector。

schema = Schema.from_pyarrow_schema(
    pa_schema,
    options={
        'row-tracking.enabled': 'true',
        'data-evolution.enabled': 'true',
        'deletion-vectors.enabled': 'true',
    },
)
catalog.create_table('default.users_delete', schema, False)
table = catalog.get_table('default.users_delete')

# ... 写入初始数据 ...

write_builder = table.new_batch_write_builder()
table_update = write_builder.new_update()
table_commit = write_builder.new_commit()

# DELETE FROM users_delete WHERE age >= 35
predicate = table_update.new_predicate_builder().greater_or_equal('age', 35)
messages = table_update.delete_by_predicate(predicate)
table_commit.commit(messages)
table_commit.close()

如果你已经持有 _ROW_ID 值,可以使用 delete_by_row_id 直接写入 deletion vector:

messages = table_update.delete_by_row_id([0, 2, 4])
table_commit.commit(messages)

按 _ROW_ID 过滤​

需要相同的前置条件(启用 row-tracking 和 data-evolution)。在这类表上,你可以按 _ROW_ID 过滤,以在 scan 时裁剪文件。支持:equal('_ROW_ID', id)、is_in('_ROW_ID', [id1, ...])、between('_ROW_ID', low, high)。

pb = table.new_read_builder().new_predicate_builder()
rb = table.new_read_builder().with_filter(pb.equal('_ROW_ID', 0))
result = rb.new_read().to_arrow(rb.new_scan().plan().splits())

按键 Upsert​

如果你想按一个或多个业务键列对行进行 upsert(更新或插入)—— 而无需手动提供 _ROW_ID —— 请使用 upsert_by_arrow_with_key。对每个输入行:

  • 键匹配已有行 → 原地更新该行。
  • 无匹配 → 作为新行追加。

要求

  • 表必须设置 data-evolution.enabled = true 且 row-tracking.enabled = true。
  • 所有 upsert_keys 必须同时存在于表 schema 和输入数据中。
  • 对于分区表,输入数据必须包含所有分区键列。分区键在匹配时会从 upsert_keys 中自动剔除(因为每个分区是独立处理的), 因此你不需要将它们包含在 upsert_keys 中。

示例:基础 upsert

import pyarrow as pa
from pypaimon import CatalogFactory, Schema

catalog = CatalogFactory.create({'warehouse': '/tmp/warehouse'})
catalog.create_database('default', False)

pa_schema = pa.schema([
    ('id', pa.int32()),
    ('name', pa.string()),
    ('age', pa.int32()),
])
schema = Schema.from_pyarrow_schema(
    pa_schema,
    options={'row-tracking.enabled': 'true', 'data-evolution.enabled': 'true'},
)
catalog.create_table('default.users', schema, False)
table = catalog.get_table('default.users')

# 写入初始数据
write_builder = table.new_batch_write_builder()
write = write_builder.new_write()
commit = write_builder.new_commit()
write.write_arrow(pa.Table.from_pydict(
    {'id': [1, 2], 'name': ['Alice', 'Bob'], 'age': [30, 25]},
    schema=pa_schema,
))
commit.commit(write.prepare_commit())
write.close()
commit.close()

# upsert:更新 id=1,插入 id=3
write_builder = table.new_batch_write_builder()
table_update = write_builder.new_update()
table_commit = write_builder.new_commit()

upsert_data = pa.Table.from_pydict(
    {'id': [1, 3], 'name': ['Alice_v2', 'Charlie'], 'age': [31, 28]},
    schema=pa_schema,
)
cmts = table_update.upsert_by_arrow_with_key(upsert_data, upsert_keys=['id'])
table_commit.commit(cmts)
table_commit.close()

# 内容应为:
#   id=1: name='Alice_v2', age=31   (已更新)
#   id=2: name='Bob',      age=25   (未变化)
#   id=3: name='Charlie',  age=28   (新增)

示例:使用 update_cols 的部分列 upsert

将 with_update_type 与 upsert_by_arrow_with_key 组合使用,可以 只更新匹配行的指定列,同时对新键仍追加完整行:

write_builder = table.new_batch_write_builder()
table_update = write_builder.new_update().with_update_type(['age'])
table_commit = write_builder.new_commit()

upsert_data = pa.Table.from_pydict(
    {'id': [1, 4], 'name': ['ignored', 'David'], 'age': [99, 22]},
    schema=pa_schema,
)
cmts = table_update.upsert_by_arrow_with_key(upsert_data, upsert_keys=['id'])
table_commit.commit(cmts)
table_commit.close()

# id=1:只有 'age' 被更新为 99;'name' 保持 'Alice_v2'
# id=4:作为完整新行追加

示例:带复合键的分区表

partitioned_schema = pa.schema([
    ('id', pa.int32()),
    ('name', pa.string()),
    ('region', pa.string()),
])
schema = Schema.from_pyarrow_schema(
    partitioned_schema,
    partition_keys=['region'],
    options={'row-tracking.enabled': 'true', 'data-evolution.enabled': 'true'},
)
catalog.create_table('default.users_partitioned', schema, False)
table = catalog.get_table('default.users_partitioned')

# ... 写入初始数据 ...

write_builder = table.new_batch_write_builder()
table_update = write_builder.new_update()
table_commit = write_builder.new_commit()

upsert_data = pa.Table.from_pydict(
    {'id': [1, 3], 'name': ['Alice_v2', 'Charlie'], 'region': ['US', 'EU']},
    schema=partitioned_schema,
)
# 只有 upsert_keys=['id'];分区键 'region' 会被自动剔除
cmts = table_update.upsert_by_arrow_with_key(upsert_data, upsert_keys=['id'])
table_commit.commit(cmts)
table_commit.close()

注意事项

  • 执行是逐分区驱动的:同一时间只有一个分区的键集合被加载到内存。
  • 输入数据中的重复键会自动去重 —— 保留最后一次出现的值。
  • upsert 在单次提交内是原子的 —— 所有匹配的更新和新的追加都包含在同一提交中。

Merge Into​

当你的源数据需要更新或删除匹配的目标行,并可选地插入未匹配的行时, 使用 merge_into,类似于 SQL 的 MERGE INTO。 merge_into 从 TableUpdate 暴露,因此它遵循与其他 PyPaimon 更新 API 相同的提交消息生命周期。PyPaimon 的 实现在单个进程中运行,并在本地物化所需的行。

匹配的行在内部通过 _ROW_ID 更新,删除子句则通过 deletion vector 删除。只有更新子句涉及的列会被重写。 merge_into 从 WhenMatched 子句推导更新列; 不需要使用 with_update_type。

要求

  • 目标表必须设置 data-evolution.enabled = true 且 row-tracking.enabled = true。
  • 匹配删除子句要求 deletion-vectors.enabled = true。
  • source 必须是 pyarrow.Table、pandas.DataFrame 或另一个 PyPaimon 表对象。
  • on 可以是同名键列的列表,或 {target_col: source_col} (用于源键重命名的场景)。
  • 如果多个源行匹配同一个目标 _ROW_ID,merge_into 会抛出 错误。请在合并前对源数据去重。
import pyarrow as pa
from pypaimon import CatalogFactory, Schema
from pypaimon.table.data_evolution_merge_into import (
    WhenMatched,
    WhenNotMatched,
)

catalog = CatalogFactory.create({'warehouse': '/tmp/warehouse'})
catalog.create_database('default', False)

pa_schema = pa.schema([
    ('id', pa.int32()),
    ('name', pa.string()),
    ('age', pa.int32()),
])
schema = Schema.from_pyarrow_schema(
    pa_schema,
    options={'row-tracking.enabled': 'true', 'data-evolution.enabled': 'true'},
)
catalog.create_table('default.users_merge', schema, False)
table = catalog.get_table('default.users_merge')

# 写入初始数据
write_builder = table.new_batch_write_builder()
write = write_builder.new_write()
commit = write_builder.new_commit()
write.write_arrow(pa.Table.from_pydict(
    {'id': [1, 2], 'name': ['Alice', 'Bob'], 'age': [30, 25]},
    schema=pa_schema,
))
commit.commit(write.prepare_commit())
write.close()
commit.close()

# merge:更新 id=2,插入 id=3
source = pa.Table.from_pydict(
    {'id': [2, 3], 'name': ['Bob_v2', 'Charlie'], 'age': [26, 28]},
    schema=pa_schema,
)

write_builder = table.new_batch_write_builder()
table_update = write_builder.new_update()
table_commit = write_builder.new_commit()

messages = table_update.merge_into(
    source,
    on=['id'],
    when_matched=[WhenMatched.update('*')],
    when_not_matched=[WhenNotMatched(insert='*')],
)
table_commit.commit(messages)
table_commit.close()

WhenMatched 和 WhenNotMatched 子句可以使用 '*' 从源复制 同名列,或使用映射进行显式赋值:

from pypaimon.table.data_evolution_merge_into import (
    WhenMatched,
    WhenNotMatched,
    lit,
    source_col,
    target_col,
)

messages = table_update.merge_into(
    source,
    on={'id': 'source_id'},
    when_matched=[
        WhenMatched.update({
            'age': source_col('new_age'),
            'name': target_col('name'),
        }),
    ],
    when_not_matched=[
        WhenNotMatched(insert={
            'id': source_col('source_id'),
            'name': source_col('name'),
            'age': lit(0),
        }),
    ],
)

条件使用 SQL 风格的表达式,列前缀为 s.(源)和 t.(目标)。 WhenNotMatched 条件只能引用源列(s.*)。条件求值使用 PyPaimon 的 DataFusion extra,需要 Python 3.10 或更高版本, 通过 pip install 'pypaimon[datafusion]' 安装。

messages = table_update.merge_into(
    source,
    on=['id'],
    when_matched=[WhenMatched.update('*', condition='s.age > t.age')],
    when_not_matched=[WhenNotMatched(insert='*', condition='s.age > 18')],
)

使用 WhenMatched.delete() 删除匹配行:

messages = table_update.merge_into(
    source,
    on=['id'],
    when_matched=[
        WhenMatched.delete(condition='s.deleted = TRUE'),
        WhenMatched.update('*'),
    ],
)

注意事项

  • 多个子句按顺序求值;第一个匹配的条件生效。
  • 匹配子句不能更新分区键列,因为尚未实现跨分区行移动。
  • 匹配删除子句使用 deletion vector,因此目标表必须启用 deletion-vectors.enabled。
  • merge_into 可以更新和插入 Blob 列。使用 update="*" 或 insert="*" 时,源必须包含相应的 blob 列。 如果插入映射省略了某个 blob 列,该列将写入 NULL。

按分片更新列​

如果你想计算派生列(或基于其他列更新现有列)而不提供 _ROW_ID,可以使用分片扫描 + 重写工作流:

  • 只读取你需要的列(投影)
  • 按相同的行序计算新值
  • 只回写被更新的列
  • 按分片提交

这适用于回填新添加的列,或根据其他列重新计算某列。

示例:计算 d = c + b - a

import pyarrow as pa
from pypaimon import CatalogFactory, Schema

catalog = CatalogFactory.create({'warehouse': '/tmp/warehouse'})
catalog.create_database('default', False)

table_schema = pa.schema([
    ('a', pa.int32()),
    ('b', pa.int32()),
    ('c', pa.int32()),
    ('d', pa.int32()),
])

schema = Schema.from_pyarrow_schema(
    table_schema,
    options={'row-tracking.enabled': 'true', 'data-evolution.enabled': 'true'},
)
catalog.create_table('default.t', schema, False)
table = catalog.get_table('default.t')

# 写入初始数据(仅 a、b、c)
write_builder = table.new_batch_write_builder()
write = write_builder.new_write().with_write_type(['a', 'b', 'c'])
commit = write_builder.new_commit()
write.write_arrow(pa.Table.from_pydict({'a': [1, 2], 'b': [10, 20], 'c': [100, 200]}))
commit.commit(write.prepare_commit())
write.close()
commit.close()

# 分片更新:读取 (a, b, c),只写回 (d)
update = write_builder.new_update()
update.with_read_projection(['a', 'b', 'c'])
update.with_update_type(['d'])

shard_idx = 0
num_shards = 1
upd = update.new_shard_updator(shard_idx, num_shards)
reader = upd.arrow_reader()

for batch in iter(reader.read_next_batch, None):
    a = batch.column('a').to_pylist()
    b = batch.column('b').to_pylist()
    c = batch.column('c').to_pylist()
    d = [ci + bi - ai for ai, bi, ci in zip(a, b, c)]

    upd.update_by_arrow_batch(
        pa.RecordBatch.from_pydict({'d': d}, schema=pa.schema([('d', pa.int32())]))
    )

commit_messages = upd.prepare_commit()
commit = write_builder.new_commit()
commit.commit(commit_messages)
commit.close()

示例:更新现有列 c = b - a

update = write_builder.new_update()
update.with_read_projection(['a', 'b'])
update.with_update_type(['c'])

upd = update.new_shard_updator(0, 1)
reader = upd.arrow_reader()
for batch in iter(reader.read_next_batch, None):
    a = batch.column('a').to_pylist()
    b = batch.column('b').to_pylist()
    c = [bi - ai for ai, bi in zip(a, b)]
    upd.update_by_arrow_batch(
        pa.RecordBatch.from_pydict({'c': c}, schema=pa.schema([('c', pa.int32())]))
    )

commit_messages = upd.prepare_commit()
commit = write_builder.new_commit()
commit.commit(commit_messages)
commit.close()

注意事项

  • 行序很重要:你写入的批次必须与读到的批次具有相同的行数, 且在该分片内保持相同的顺序。
  • 并行度:为每个分片调用 new_shard_updator(shard_idx, num_shards) 即可运行多个分片。

并发 Compaction 恢复​

部分列更新会记录其读取的每个数据文件的行 ID 边界。 如果在 commit 之前 compaction 合并了这些文件,PyPaimon 会自动 将常规(非 BLOB 且非 VECTOR)的暂存更新文件重设基线(rebase)到最新的 文件边界,并重试提交。

恢复的界限是当前受影响的、行 ID 区间相关的数据文件总大小:

options = {
    'row-tracking.enabled': 'true',
    'data-evolution.enabled': 'true',
    'data-evolution.row-id-conflict-rewrite.max-size': '256 MB',
}

默认值为 256 MB。将该配置项设为 0 B 可禁用自动 重写。如果受影响的文件超过配置的大小,或者行 ID 已被 覆盖操作移除,提交将保持原有的 Row ID existence conflict 行为。逻辑上的并发更新仍然会被检查, 永远不会被 compaction 恢复掩盖。

当启用 deletion vector,或者同一提交中包含已有行的 BLOB 或 VECTOR 暂存文件时,不会尝试恢复。

流模式​

Data evolution 也支持流模式。操作语义与上面的批式 API 相同; 主要区别在于 builder 生命周期和必需的 commit_identifier。

  • 使用 table.new_stream_write_builder() 而不是 table.new_batch_write_builder()。
  • StreamTableWrite、StreamTableUpdate 和 StreamTableCommit 可在 多轮中复用。
  • 每轮必须使用单调递增的 commit_identifier。
  • 将同一个 commit_identifier 传给该轮的写入 prepare 步骤或更新方法, 以及对应的提交调用。

API 对应关系为:

批式 API流式 API
write.prepare_commit()write.prepare_commit(commit_identifier)
update.update_by_arrow_with_row_id(table)update.update_by_arrow_with_row_id(table, commit_identifier)
update.update_by_predicate(predicate, assignments, read_columns=...)update.update_by_predicate(predicate, assignments, commit_identifier, read_columns=...)
update.delete_by_predicate(predicate)update.delete_by_predicate(predicate, commit_identifier)
update.delete_by_row_id(row_ids)update.delete_by_row_id(row_ids, commit_identifier)
update.upsert_by_arrow_with_key(table, keys)update.upsert_by_arrow_with_key(table, keys, commit_identifier)
update.merge_into(source, on=..., when_matched=..., when_not_matched=...)update.merge_into(source, on=..., when_matched=..., when_not_matched=..., commit_identifier=...)
commit.commit(messages)commit.commit(messages, commit_identifier)

对于分片更新,从 StreamTableUpdate 创建 updater 的方式与批模式 相同。new_shard_updator(...)、arrow_reader()、 update_by_arrow_batch(...) 和 prepare_commit() 保持不变;在提交返回的 消息时传入 commit_identifier。
