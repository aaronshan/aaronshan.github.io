pypaimon 中的 Blob 存储

关于 Paimon 的 Blob 存储概念(存储模式、表配置项、SQL 用法、 Java API),请参阅 Blob 存储。

本页介绍读写 BLOB 列的 Python API。

创建表​

BLOB 列映射为 PyArrow 的 large_binary()。表必须开启 row-tracking.enabled 和 data-evolution.enabled。

from pypaimon import CatalogFactory, Schema
import pyarrow as pa

catalog = CatalogFactory.create({'warehouse': '/tmp/paimon-warehouse'})
catalog.create_database('my_db', True)

pa_schema = pa.schema([
    ('id', pa.int32()),
    ('name', pa.string()),
    ('image', pa.large_binary()),
])
schema = Schema.from_pyarrow_schema(
    pa_schema,
    options={
        'row-tracking.enabled': 'true',
        'data-evolution.enabled': 'true',
    },
)
catalog.create_table('my_db.image_table', schema, True)

写入 Blob 数据​

在 PyArrow Table 中为 blob 列传入原始字节,pypaimon 会自动将它们 写入专用的 .blob 文件。

table = catalog.get_table('my_db.image_table')
write_builder = table.new_batch_write_builder()
writer = write_builder.new_write()

with open('cat.jpg', 'rb') as f1, open('dog.jpg', 'rb') as f2:
    writer.write_arrow(pa.Table.from_pydict({
        'id': [1, 2],
        'name': ['cat', 'dog'],
        'image': [f1.read(), f2.read()],
    }, schema=pa_schema))

write_builder.new_commit().commit(writer.prepare_commit())
writer.close()

对于帧表(frame table),需要配置 video-frame-field。高层多模态 API 会创建 VideoFrameDescriptor 值,将多个完整视频打包到 .video 文件中,并将帧序号排除在普通数据文件之外,同时提供 add_video / add_videos / replace_video 用于物理视频写入。 普通的帧列更新以及所有读取操作仍然使用现有的表 API 和 BLOB API。 参见视频帧存储。

读取 Blob 数据​

批量读取(推荐)​

使用 to_arrow_batch_reader 按批次读取 blob 数据。设置 blob_parallelism 可以在每个批次内并发读取 blob:

read_builder = table.new_read_builder()
splits = read_builder.new_scan().plan().splits()
read = read_builder.new_read()

for batch in read.to_arrow_batch_reader(splits, blob_parallelism=16):
    for i in range(len(batch)):
        image_bytes = batch['image'][i].as_py()

或者将全部数据读入单个 Arrow Table:

arrow_table = read.to_arrow(splits, blob_parallelism=16)

逐行读取​

使用 row.get_blob(pos) 逐行访问 blob 列:

for row in read.to_iterator(splits):
    blob = row.get_blob(2)
    if blob is None:
        continue
    data = blob.to_data()

流式 / 部分读取​

对于真正的按需流式读取(如视频或模型权重等大型 blob), 设置 blob-as-descriptor=true,这样 blob 值会以轻量级 引用的形式保留,而不会被物化到内存中:

table = table.copy({'blob-as-descriptor': 'true'})

read_builder = table.new_read_builder()
splits = read_builder.new_scan().plan().splits()
read = read_builder.new_read()

for row in read.to_iterator(splits):
    blob = row.get_blob(2)
    if blob is None:
        continue
    with blob.new_input_stream() as stream:
        chunk = stream.read(4096)

如果不设置 blob-as-descriptor=true,blob 值会在 row.get_blob(...) 返回前被物化;此时 new_input_stream() 读取的是内存中的字节,而不是存储中的数据。

对于 data-evolution 读取,PyPaimon 会在物化投影出的标量 BLOB 负载之前, 先应用用户过滤条件、行级鉴权过滤和 limit。如果用户过滤或鉴权过滤 引用了 BLOB 值,该字段会保持立即加载。列脱敏(column masking)在负载 物化之后应用。包含 BLOB 值的 ARRAY 和 MAP 元素不会被延迟物化。

底层 API:Blob.from_bytes​

当你已经持有原始字节或描述符字节(例如来自自定义 数据源),并希望将它们包装为 Blob 时,可以使用该工厂方法:

from pypaimon.table.row.blob import Blob

# 内联字节 → BlobData(无需 file_io)
blob = Blob.from_bytes(b'hello')

# 描述符字节 → BlobRef(惰性加载;需要 file_io 来解析 URI)
file_io = table.file_io
blob = Blob.from_bytes(descriptor_bytes, file_io)

data = blob.to_data()

该工厂会根据字节内容自动分发(依据 BLOBDESC、 VIDEOFRM 或 blob-view 魔数头)。这与 Java 的 Blob.fromBytes(...) 行为一致。
