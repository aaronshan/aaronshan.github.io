SQL DDL

创建 Catalog​

Paimon Catalog 目前支持三种类型的 metastore:

  • filesystem metastore(默认),将元数据和表文件都存储在文件系统中。
  • hive metastore,额外将元数据存储在 Hive Metastore 中。用户可以直接从 Hive 访问这些表。
  • jdbc metastore,额外将元数据存储在 MySQL、Postgres 等关系型数据库中。

创建 Catalog 时的详细选项请参见 CatalogOptions。

信息

对于 REST Catalog 中的内部 Format Table,metastore.partitioned-table = true 会使 Catalog 成为分区的权威来源,这要求 Catalog(目前为 REST Catalog)中的内部表支持该能力,并且不能与 format-table.implementation = engine 组合使用。在 Paimon 表上, 该选项保持原有含义(将分区同步到 metastore);在 Format Table 上,它仅在 REST Catalog 中生效,在其他地方分区仍从文件系统中发现。

Flink 作业只能读取 Catalog 已知的分区。 在该选项启用之前写入的目录、由旧版本 writer 写入的目录,或由任何不注册所写内容的一方写入的目录均不可见;一个 Catalog 中没有任何分区的表会被读取为空表。Flink 没有用于注册分区的 SQL 命令:请使用 Spark 的 MSCK REPAIR TABLE 或 Catalog 的分区 API。当前版本的 Flink 写入时会注册其产生的分区。

Flink SQL 无法设置自定义的分区 LOCATION。在通过 Catalog API 注册自定义 location 之前,请先升级 Flink reader。

在 REST Catalog 中,对不支持 Catalog 管理分区的表(外部表,或 format-table.implementation = engine 的表)请求 Catalog 管理的分区会失败。在任何其他 Catalog 中,该选项在 Format Table 上保持其一直以来的含义——无效果——分区来自文件系统。移除该选项需要能够修改表的 Catalog;Flink 的 Format Table 路径无法做到,因此请使用其他引擎。

创建 Filesystem Catalog​

以下 Flink SQL 注册并使用一个名为 my_catalog 的 Paimon Catalog。元数据和表文件存储在 hdfs:///path/to/warehouse 下。

CREATE CATALOG my_catalog WITH (
    'type' = 'paimon',
    'warehouse' = 'hdfs:///path/to/warehouse'
);

USE CATALOG my_catalog;

你可以通过 table-default. 前缀为该 Catalog 中创建的表定义任意默认表选项。

创建 Hive Catalog​

使用 Paimon Hive Catalog 时,对 Catalog 的变更会直接影响对应的 Hive Metastore。在此类 Catalog 中创建的表也可以直接从 Hive 访问。

要使用 Hive Catalog,Database 名、表名和字段名都应当为小写。

Flink 中的 Paimon Hive Catalog 依赖 Flink Hive connector bundled jar。你应当先下载 Hive connector bundled jar 并将其加入 classpath。

Metastore 版本Bundle 名称SQL Client JAR
2.3.0 - 3.1.3Flink BundleDownload
1.2.0 - x.x.xPresto BundleDownload

以下 Flink SQL 注册并使用一个名为 my_hive 的 Paimon Hive Catalog。元数据和表文件存储在 hdfs:///path/to/warehouse 下。此外,元数据也会存储在 Hive Metastore 中。

如果你的 Hive 需要 Kerberos、LDAP、Ranger 等安全认证,或者你希望 Paimon 表由 Apache Atlas 管理(在 hive-site.xml 中设置 'hive.metastore.event.listeners')。你可以指定 hive-conf-dir 和 hadoop-conf-dir 参数,指向 hive-site.xml 文件路径。

CREATE CATALOG my_hive WITH (
    'type' = 'paimon',
    'metastore' = 'hive',
    -- 'uri' = 'thrift://<hive-metastore-host-name>:<port>', default use 'hive.metastore.uris' in HiveConf
    -- 'hive-conf-dir' = '...', this is recommended in the kerberos environment
    -- 'hadoop-conf-dir' = '...', this is recommended in the kerberos environment
    -- 'warehouse' = 'hdfs:///path/to/warehouse', default use 'hive.metastore.warehouse.dir' in HiveConf
);

USE CATALOG my_hive;

你可以通过 table-default. 前缀为该 Catalog 中创建的表定义任意默认表选项。

另外,你也可以创建 FlinkGenericCatalog。

当使用 Hive Catalog 通过 alter table 修改不兼容的列类型时,需要在 Hive Metastore 服务端(其 hive-site.xml 中,然后重启 HMS)配置 hive.metastore.disallow.incompatible.col.type.changes=false。在 Paimon Catalog 上或通过 Flink SQL SET 设置该配置只会配置客户端的 HiveConf,不会通过 Thrift 传递给远端 HMS。参见 HIVE-17832。

如果你使用的是 Hive3,请禁用 Hive ACID:

hive.strict.managed.tables=false
hive.create.as.insert.only=false
metastore.create.as.acid=false

将分区同步到 Hive Metastore​

默认情况下,Paimon 不会将新创建的分区同步到 Hive Metastore。用户在 Hive 中会看到一张未分区的表。分区下推将由过滤条件下推代替。

如果你希望在 Hive 中看到分区表,并将新创建的分区同步到 Hive Metastore,请将表属性 metastore.partitioned-table 设置为 true。另请参见 CoreOptions。

为 Hive 表添加参数​

通过表选项可以方便地定义 Hive 表参数。 以 hive. 为前缀的参数会被自动定义到 Hive 表的 TBLPROPERTIES 中。 例如,使用选项 hive.table.owner=Jon 会在建表过程中自动将参数 table.owner=Jon 添加到表属性中。

在 Properties 中设置 Location​

如果你使用对象存储,并且不希望 Hive 的 filesystem 访问 Paimon 表/database 的 location, 因为那样可能导致 "No FileSystem for scheme: s3a" 之类的错误。 你可以通过配置 location-in-properties 在表/database 的 properties 中设置 location。参见 在 properties 中设置表/database 的 location。

创建 JDBC Catalog​

使用 Paimon JDBC Catalog 时,对 Catalog 的变更会直接存储在 SQLite、MySQL、Postgres 等关系型数据库中。

目前,lock 配置仅支持 MySQL 和 SQLite。如果你使用其他类型的数据库存储 Catalog,请不要配置 lock.enabled。

Flink 中的 Paimon JDBC Catalog 需要正确添加连接数据库所需的对应 jar 包。你应当先下载 JDBC connector bundled jar 并将其加入 classpath,例如 MySQL、postgres。

数据库类型Bundle 名称SQL Client JAR
mysqlmysql-connector-javaDownload
postgrespostgresqlDownload
CREATE CATALOG my_jdbc WITH (
    'type' = 'paimon',
    'metastore' = 'jdbc',
    'uri' = 'jdbc:mysql://<host>:<port>/<databaseName>',
    'jdbc.user' = '...', 
    'jdbc.password' = '...', 
    'catalog-key'='jdbc',
    'warehouse' = 'hdfs:///path/to/warehouse'
);

USE CATALOG my_jdbc;

你可以通过 "jdbc." 前缀配置 JDBC 声明的任意连接参数,不同数据库之间的连接参数可能不同,请根据实际情况配置。

你还可以通过指定 "catalog-key" 对多个 Catalog 下的 database 进行逻辑隔离。

另外,创建 JdbcCatalog 时,你可以通过配置 "lock-key-max-length" 指定 lock key 的最大长度,默认为 255。由于该值由 {catalog-key}.{database-name}.{table-name} 组合而成,请相应调整。

JDBC Catalog 支持持久化 Paimon 视图。视图元数据存储在 Catalog 数据库中自动创建的 paimon_views 表里。视图 SQL 作为 Catalog 元数据存储,在创建视图时不会被解析。

在单个数据库内,同一个名字不能同时被表和视图使用;所有写入操作 (createTable、renameTable、createView、renameView)都会拒绝冲突的标识符。关于升级时的权限、单进程锁语义以及数据库可见性的细节,请参见 Views。

CREATE VIEW sales_view AS SELECT name, amount FROM sales WHERE amount > 100;

SHOW VIEWS;

DROP VIEW sales_view;

你可以通过 table-default. 前缀为该 Catalog 中创建的表定义任意默认表选项。

创建表​

使用 Paimon Catalog 后,你可以创建和删除表。在 Paimon Catalog 中创建的表由 Catalog 管理。 当表从 Catalog 中删除时,其表文件也会被删除。

以下 SQL 假设你已经注册并正在使用一个 Paimon Catalog。它在 Catalog 的 default 数据库中创建一张名为 my_table 的托管表,共五列,其中 dt、hh 和 user_id 是主键。

CREATE TABLE my_table (
    user_id BIGINT,
    item_id BIGINT,
    behavior STRING,
    dt STRING,
    hh STRING,
    PRIMARY KEY (dt, hh, user_id) NOT ENFORCED
);

你可以创建分区表:

CREATE TABLE my_table (
    user_id BIGINT,
    item_id BIGINT,
    behavior STRING,
    dt STRING,
    hh STRING,
    PRIMARY KEY (dt, hh, user_id) NOT ENFORCED
) PARTITIONED BY (dt, hh);
信息

如果你需要跨分区 upsert(主键不包含所有分区字段),请参见跨分区 Upsert模式。

信息

通过配置 partition.expiration-time,可以自动删除过期的分区。

指定统计信息模式​

Paimon 会自动收集数据文件的统计信息以加速查询。支持四种模式:

  • full:收集完整指标:null_count, min, max。
  • truncate(length):length 可以是任意正数,默认模式为 truncate(16),即收集 null count 和截断长度为 16 的 min/max 值。 这主要是为了避免列内容过大导致 manifest 文件膨胀。
  • counts:仅收集 null count。
  • none:禁用元数据统计信息收集。

统计信息收集模式可以通过 'metadata.stats-mode' 配置,默认为 'truncate(16)'。 你可以通过设置 'fields.{field_name}.stats-mode' 配置字段级别的模式。

对于 none 模式,默认 metadata.stats-dense-store 为 true,这会显著减小 manifest 的存储体积。但读取引擎中的 Paimon SDK 需要至少 0.9.1 或 1.0.0 及以上版本。

字段默认值​

Paimon 表目前支持通过 'fields.item_id.default-value' 在表属性中为字段设置默认值, 注意不能为分区字段和主键字段指定默认值。

Create Table As Select​

表可以通过查询结果创建并填充数据,例如,我们有这样一条 SQL:CREATE TABLE table_b AS SELECT id, name FROM table_a, 生成的表 table_b 等价于先用以下语句建表再插入数据: CREATE TABLE table_b (id INT, name STRING); INSERT INTO table_b SELECT id, name FROM table_a;

使用 CREATE TABLE AS SELECT 时,我们可以指定主键或分区,语法请参考以下 SQL。

/* For streaming mode, you need to enable the checkpoint. */

CREATE TABLE my_table (
    user_id BIGINT,
    item_id BIGINT
);
CREATE TABLE my_table_as AS SELECT * FROM my_table;

/* partitioned table */
CREATE TABLE my_table_partition (
     user_id BIGINT,
     item_id BIGINT,
     behavior STRING,
     dt STRING,
     hh STRING
) PARTITIONED BY (dt, hh);
CREATE TABLE my_table_partition_as WITH ('partition' = 'dt') AS SELECT * FROM my_table_partition;
    
/* change options */
CREATE TABLE my_table_options (
       user_id BIGINT,
       item_id BIGINT
) WITH ('file.format' = 'orc');
CREATE TABLE my_table_options_as WITH ('file.format' = 'parquet') AS SELECT * FROM my_table_options;

/* primary key */
CREATE TABLE my_table_pk (
      user_id BIGINT,
      item_id BIGINT,
      behavior STRING,
      dt STRING,
      hh STRING,
      PRIMARY KEY (dt, hh, user_id) NOT ENFORCED
);
CREATE TABLE my_table_pk_as WITH ('primary-key' = 'dt,hh') AS SELECT * FROM my_table_pk;


/* primary key + partition */
CREATE TABLE my_table_all (
      user_id BIGINT,
      item_id BIGINT,
      behavior STRING,
      dt STRING,
      hh STRING,
      PRIMARY KEY (dt, hh, user_id) NOT ENFORCED 
) PARTITIONED BY (dt, hh);
CREATE TABLE my_table_all_as WITH ('primary-key' = 'dt,hh', 'partition' = 'dt') AS SELECT * FROM my_table_all;

Create Table Like​

若要创建与另一张表具有相同 schema、分区和表属性的表,使用 CREATE TABLE LIKE。

CREATE TABLE my_table (
    user_id BIGINT,
    item_id BIGINT,
    behavior STRING,
    dt STRING,
    hh STRING,
    PRIMARY KEY (dt, hh, user_id) NOT ENFORCED
);

CREATE TABLE my_table_like LIKE my_table (EXCLUDING OPTIONS);

配合 Flink 临时表使用​

Flink 临时表仅由当前 Flink SQL 会话记录而不被管理。如果临时表被删除,其资源不会被删除。临时表也会在 Flink SQL 会话关闭时被删除。

如果你想将 Paimon Catalog 与其他表一起使用,但又不想把这些表存储到其他 Catalog 中,你可以 创建临时表。以下 Flink SQL 创建了一个 Paimon Catalog 和一张临时表,并演示了 如何同时使用两种表。

CREATE CATALOG my_catalog WITH (
    'type' = 'paimon',
    'warehouse' = 'hdfs:///path/to/warehouse'
);

USE CATALOG my_catalog;

-- Assume that there is already a table named my_table in my_catalog

CREATE TEMPORARY TABLE temp_table (
    k INT,
    v STRING
) WITH (
    'connector' = 'filesystem',
    'path' = 'hdfs:///path/to/temp_table.csv',
    'format' = 'csv'
);

SELECT my_table.k, my_table.v, temp_table.v FROM my_table JOIN temp_table ON my_table.k = temp_table.k;
