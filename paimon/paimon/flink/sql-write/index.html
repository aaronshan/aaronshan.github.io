SQL Write

语法​

INSERT { INTO | OVERWRITE } table_identifier [ part_spec ] [ column_list ] { value_expr | query };

更多信息请查阅语法文档:

Flink INSERT Statement

INSERT INTO​

使用 INSERT INTO 将记录和变更写入表。

INSERT INTO my_table SELECT ...

INSERT INTO 同时支持批模式和流模式。在流模式下,默认情况下它还会执行 compaction、 快照过期,甚至在 Flink Sink 中执行分区过期(如果已配置)。

如果有多个作业写入同一张表,可以参考独立 compaction 作业了解更多信息。

聚簇(Clustering)​

在 Paimon 中,clustering 是一个允许你在写入过程中基于某些列的值对 Append 表中的数据进行聚簇的特性。 这种数据组织方式可以显著提升下游任务读取数据的效率,因为它使数据检索更快、更有针对性。该特性仅支持 Append 表(bucket = -1) 和批执行模式。

要使用 clustering,你可以在创建表或写入表时指定要聚簇的列。下面是一个启用 clustering 的简单示例:

CREATE TABLE my_table (
    a STRING,
    b STRING,
    c STRING,
) WITH (
  'sink.clustering.by-columns' = 'a,b',
);

你也可以使用 SQL hint 动态设置 clustering 选项:

INSERT INTO my_table /*+ OPTIONS('sink.clustering.by-columns' = 'a,b') */
SELECT * FROM source;

数据使用自动选择的策略(如 ORDER、ZORDER 或 HILBERT)进行聚簇,你也可以通过设置 sink.clustering.strategy 手动指定聚簇策略。 Clustering 依赖采样和排序。如果聚簇过程耗时过长,你可以通过设置 sink.clustering.sample-factor 降低总采样数, 或者通过将 sink.clustering.sort-in-cluster 设置为 false 来禁用排序步骤。

关于上述配置的更多信息,可以参考 FlinkConnectorOptions。

覆盖整个表​

对于非分区表,Paimon 支持覆盖整个表。 (对于禁用了 dynamic-partition-overwrite 选项的分区表也同样适用。)

使用 INSERT OVERWRITE 覆盖整个非分区表。

INSERT OVERWRITE my_table SELECT ...

覆盖一个分区​

对于分区表,Paimon 支持覆盖某个分区。

使用 INSERT OVERWRITE 覆盖一个分区。

INSERT OVERWRITE my_table PARTITION (key1 = value1, key2 = value2, ...) SELECT ...

动态覆盖​

Flink 的默认覆盖模式是动态分区覆盖(即 Paimon 只删除被覆盖数据中出现的分区)。 你可以配置 dynamic-partition-overwrite 将其改为静态覆盖。

-- MyTable is a Partitioned Table

-- Dynamic overwrite
INSERT OVERWRITE my_table SELECT ...

-- Static overwrite (Overwrite whole table)
INSERT OVERWRITE my_table /*+ OPTIONS('dynamic-partition-overwrite' = 'false') */ SELECT ...

清空表​

  • Flink 1.17-
  • Flink 1.18+

你可以使用 INSERT OVERWRITE 插入空数据来清空表。

INSERT OVERWRITE my_table /*+ OPTIONS('dynamic-partition-overwrite'='false') */ SELECT * FROM my_table WHERE false;
TRUNCATE TABLE my_table;

对于通过 Paimon 读取的 Format Table(format-table.implementation = paimon,默认值), TRUNCATE TABLE 会删除数据文件但保留分区:分区目录仍然存在,而且在 metastore.partitioned-table = true 时,它们在 Catalog 中的注册信息也会保留,只是统计信息被替换为零。 该设置同时使 Catalog 成为表拥有哪些分区的权威答案,因此 truncate 会清空这些注册信息,而未注册的目录则不受影响。Flink 没有 TRUNCATE TABLE ... PARTITION 语法;请使用 Spark 的。

清空分区​

目前,Paimon 支持两种清空分区的方式。

  1. 与清空表类似,你可以使用 INSERT OVERWRITE 向分区插入空数据来清空分区数据。

  2. 方式 #1 不支持删除多个分区。如果你需要删除多个分区,可以通过 flink run 提交 drop_partition 作业。

-- Syntax
INSERT OVERWRITE my_table /*+ OPTIONS('dynamic-partition-overwrite'='false') */ 
PARTITION (key1 = value1, key2 = value2, ...) SELECT selectSpec FROM my_table WHERE false;

-- The following SQL is an example:
-- table definition
CREATE TABLE my_table (
    k0 INT,
    k1 INT,
    v STRING
) PARTITIONED BY (k0, k1);

-- you can use
INSERT OVERWRITE my_table /*+ OPTIONS('dynamic-partition-overwrite'='false') */ 
PARTITION (k0 = 0) SELECT k1, v FROM my_table WHERE false;

-- or
INSERT OVERWRITE my_table /*+ OPTIONS('dynamic-partition-overwrite'='false') */ 
PARTITION (k0 = 0, k1 = 0) SELECT v FROM my_table WHERE false;

更新表​

信息

重要的表属性设置:

  1. 仅主键表支持该特性。
  2. MergeEngine 需要是 deduplicate 或 partial-update 才能支持该特性。
  3. 不支持更新主键。

目前,Paimon 在 Flink 1.17 及更高版本中支持使用 UPDATE 更新记录。你可以在 Flink 的 batch 模式下执行 UPDATE。

-- Syntax
UPDATE table_identifier SET column1 = value1, column2 = value2, ... WHERE condition;

-- The following SQL is an example:
-- table definition
CREATE TABLE my_table (
	a STRING,
	b INT,
	c INT,
	PRIMARY KEY (a) NOT ENFORCED
) WITH ( 
	'merge-engine' = 'deduplicate' 
);

-- you can use
UPDATE my_table SET b = 1, c = 2 WHERE a = 'myTable';

从表中删除数据​

  • Flink 1.17+
信息

重要的表属性设置:

  1. 主键表支持该特性。支持以下 MergeEngine:
    • deduplicate。
    • 开启了 'partial-update.remove-record-on-delete' 选项的 partial-update。
  2. 使用 Flink 1.17 及更高版本时,Data Evolution 模式下的 append 表在启用 row tracking 和 deletion vectors 且 bucket 为 -1 时也支持该特性。
  3. 流模式不支持从表中删除数据。
-- Syntax
DELETE FROM table_identifier WHERE conditions;

-- The following SQL is an example:
-- table definition
CREATE TABLE my_table (
    id BIGINT NOT NULL,
    currency STRING,
    rate BIGINT,
    dt String,
    PRIMARY KEY (id, dt) NOT ENFORCED
) PARTITIONED BY (dt) WITH ( 
    'merge-engine' = 'deduplicate' 
);

-- you can use
DELETE FROM my_table WHERE currency = 'UNKNOWN';

分区标记完成(Partition Mark Done)​

对于分区表,每个分区可能需要被调度以触发下游的批计算。因此, 需要选择一个时机来表示分区已经可以调度,并尽量减少调度期间的数据漂移。 我们将这个过程称为"Partition Mark Done"(分区标记完成)。

标记完成的示例:

CREATE TABLE my_partitioned_table (
    f0 INT,
    f1 INT,
    f2 INT,
    ...
    dt STRING
) PARTITIONED BY (dt) WITH (
    'partition.timestamp-formatter'='yyyyMMdd',
    'partition.timestamp-pattern'='$dt',
    'partition.time-interval'='1 d',
    'partition.idle-time-to-done'='15 m',
    'partition.mark-done-action'='done-partition'
);

你也可以自定义 PartitionMarkDoneAction 来标记分区完成。

  • partition.mark-done-action: custom
  • partition.mark-done-action.custom.class: 实现 PartitionMarkDoneAction 接口的自定义类(例如 org.apache.paimon.CustomPartitionMarkDoneAction)。

定义一个实现 PartitionMarkDoneAction 接口的类 CustomPartitionMarkDoneAction。

package org.apache.paimon;

public class CustomPartitionMarkDoneAction implements PartitionMarkDoneAction {
    
    @Override
    public void markDone(String partition) {
        // do something.
    }

    @Override
    public void close() {}
}

Paimon 还支持 http-report 分区标记完成 action,该 action 会将分区上报到远端 http 服务。

  • partition.mark-done-action: http-report
  • partition.mark-done-action.http.url : Action 会将分区上报到该远程 http 服务。
  • partition.mark-done-action.http.params : 请求体 JSON 中 http client 请求的自定义参数。

Http Post 请求体:

{
    "table": "table fullName",
    "path": "table location path",
    "partition": "mark done partition",
    "params" : "custom params"
}

Http 响应体:

{
    "result": "success"
}
  1. 首先,你需要定义分区的时间解析格式以及分区之间的时间间隔,以便确定何时可以将分区正确地标记为完成。
  2. 其次,你需要定义 idle-time,它决定分区在多长时间内没有新数据之后被标记为完成。
  3. 第三,默认情况下,标记完成会创建 _SUCCESS 文件,_SUCCESS 文件的内容是一个 JSON,包含 creationTime 和 modificationTime,它们可以帮助你了解是否存在延迟数据。你也可以配置其他 action,例如 'done-partition', 对于分区 'dt=20240501',会生成 'dt=20240501.done' 的 done 分区。
