Procedures

本节介绍 Paimon 提供的所有 Spark procedures。

Procedure Name Explanation Example
compact 压缩文件。参数:
  • table: 目标表标识符。不能为空。
  • partitions: 分区过滤器。逗号(",")表示 "AND",分号(";")表示 "OR"。如果要压缩 date=01 且 day=01 的单个分区,需要写成 'date=01,day=01'。留空表示所有分区。(不能与 "where" 同时使用)
  • where: 分区谓词。留空表示所有分区。(不能与 "partitions" 同时使用)
  • order_strategy: 取值为 'order'、'zorder'、'hilbert' 或 'none'。留空表示 'none'。
  • order_by: 需要排序的列。当 'order_strategy' 为 'none' 时留空。
  • options: 表的额外动态选项。优先级高于原有 `tableProp`,低于 `procedureArg`。
  • partition_idle_time: 用于对超过 'partition_idle_time' 未收到任何新数据的分区执行全量 compaction。只会压缩这些分区。此参数不能与 order compact 一起使用。
  • compact_strategy: 决定如何挑选要合并的文件,默认值由运行时执行模式决定。'full' 策略仅支持批模式,所有文件都会被选中合并。'minor' 策略:根据指定条件挑选需要合并的文件集。
    		•  SET spark.sql.shuffle.partitions=10; --set the compact parallelism

    CALL sys.compact(table => 'T', partitions => 'p=0;p=1', order_strategy => 'zorder', order_by => 'a,b')

    CALL sys.compact(table => 'T', where => 'p>0 and p<3', order_strategy => 'zorder', order_by => 'a,b')

    CALL sys.compact(table => 'T', where => 'dt>10 and h<20', order_strategy => 'zorder', order_by => 'a,b', options => 'target-file-size=128m')

    CALL sys.compact(table => 'T', partition_idle_time => '60s')

    CALL sys.compact(table => 'T', compact_strategy => 'minor')
    materialize_deletion_vectors 将 deletion vectors 应用到 unaware-bucket Data Evolution 表的最新状态,并为存活 的行分配新的 row ID。受影响的全局索引会被删除。Spark 以有界批次处理,直到所有匹配的 deletion vectors 都被物化。在快照过期之前,历史快照和 tag 可能仍保留被替换的文件。参数:
  • table: 目标表标识符。不能为空。
  • partitions: 分区过滤器。不能与 where 同时使用。
  • options: 表的额外动态选项。
  • where: 分区谓词。不能与 partitions 同时使用。
    		•  CALL sys.materialize_deletion_vectors(table => 'T')

    CALL sys.materialize_deletion_vectors(table => 'T', partitions => 'dt=2026-08-12')
    compact_database 压缩一个或多个数据库中的所有表。参数:
  • including_databases: 匹配要压缩数据库的正则表达式。留空表示匹配所有数据库(即 '.*')。
  • including_tables: 匹配要压缩表标识符('db.table' 形式)的正则表达式。留空表示匹配所有表(即 '.*')。
  • excluding_tables: 匹配要从压缩中排除的表标识符的正则表达式。
  • options: 表的额外动态选项。优先级高于原有 `tableProp`,低于 `procedureArg`。
    		•  -- compact all databases
    CALL sys.compact_database()

    -- compact some databases (accept regular expression)
    CALL sys.compact_database(including_databases => 'db1|db2')

    -- compact some tables (accept regular expression)
    CALL sys.compact_database(including_databases => 'db1', including_tables => 'db1.table1|db1.table2')

    -- exclude some tables (accept regular expression)
    CALL sys.compact_database(including_databases => 'db1', including_tables => '.*', excluding_tables => '.*ignore_table')

    -- set table options
    CALL sys.compact_database(including_databases => 'db1', options => 'target-file-size=128m')
    compact_chain_table 通过将快照分支和增量分支合并到快照分支来压缩 chain 表。参数:
  • table: 目标 chain 表标识符。不能为空。
  • partition: 分区规格格式(例如 'dt="20250810",hour="22"')。不能为空。
  • overwrite: 如果该分区在快照分支中已存在,是否覆盖。默认为 false。可选。
    		•  CALL sys.compact_chain_table(table => 'default.T', partition => 'dt="20250810",hour="22"')
    expire_snapshots 使快照过期。参数:
  • table: 目标表标识符。不能为空。
  • retain_max: 保留的已完成快照的最大数量。
  • retain_min: 保留的已完成快照的最小数量。
  • older_than: 早于此时间戳的快照将被移除。
  • max_deletes: 一次可删除的快照最大数量。
  • options: 表的额外动态选项。优先级高于原有 `tableProp`,低于 `procedureArg`。
    		•  CALL sys.expire_snapshots(table => 'default.T', retain_max => 10, options => 'snapshot.expire.limit=1')
    expire_partitions 使分区过期。参数:
  • table: 目标表标识符。不能为空。
  • expiration_time: 分区的过期间隔。分区的生命周期超过该值即过期。分区时间从分区值中提取。
  • timestamp_formatter: 用于将字符串格式化为时间戳的格式器。
  • timestamp_pattern: 用于从分区中提取时间戳的模式。
  • expire_strategy: 指定分区过期的策略,可选值:'values-time' 或 'update-time',默认为 'values-time'。
  • max_expires: 过期分区的最大数量限制,可选。
  • options: 表的额外动态选项。优先级高于原有 `tableProp`,低于 `procedureArg`。
    		•  CALL sys.expire_partitions(table => 'default.T', expiration_time => '1 d', timestamp_formatter => 'yyyy-MM-dd', timestamp_pattern => '$dt', expire_strategy => 'values-time', options => 'partition.expiration-max-num=2')
    create_tag 基于给定快照创建 tag。参数:
  • table: 目标表标识符。不能为空。
  • tag: 新 tag 的名称。不能为空。
  • snapshot(Long): 新 tag 所基于的快照 id。
  • time_retained: 新建 tag 的最大保留时长。
    		•  -- based on snapshot 10 with 1d
    CALL sys.create_tag(table => 'default.T', tag => 'my_tag', snapshot => 10, time_retained => '1 d')

    -- based on the latest snapshot
    CALL sys.create_tag(table => 'default.T', tag => 'my_tag')
    create_tag_from_timestamp 基于给定时间戳创建 tag。参数:
  • table: 目标表标识符。不能为空。
  • tag: 新 tag 的名称。
  • timestamp (Long): 查找 commit 时间大于该时间戳的第一个快照。
  • time_retained : 新建 tag 的最大保留时长。
    		•  CALL sys.create_tag_from_timestamp(`table` => 'default.T', `tag` => 'my_tag', `timestamp` => 1724404318750, time_retained => '1 d')
    rename_tag 将 tag 重命名为新名称。参数:
  • table: 目标表标识符。不能为空。
  • tag: tag 的名称。不能为空。
  • target_tag: 改名后的新 tag 名称。不能为空。
    		•  CALL sys.rename_tag(table => 'default.T', tag => 'tag1', target_tag => 'tag2')
    replace_tag 用新的 tag 信息替换已有 tag。参数:
  • table: 目标表标识符。不能为空。
  • tag: 已有 tag 的名称。不能为空。
  • snapshot(Long): tag 所基于的快照 id,可选。
  • time_retained: 已有 tag 的最大保留时长,可选。
    		•  CALL sys.replace_tag(table => 'default.T', tag => 'tag1', snapshot => 10, time_retained => '1 d')
    delete_tag 删除 tag。参数:
  • table: 目标表标识符。不能为空。
  • tag: 要删除的 tag 名称。指定多个 tag 时分隔符为 ','。
    		•  CALL sys.delete_tag(table => 'default.T', tag => 'my_tag')
    expire_tags 按时间使 tag 过期。参数:
  • table: 目标表标识符。不能为空。
  • older_than: tagCreateTime 早于该时间的 tag 将被移除。
    		•  CALL sys.expire_tags(table => 'default.T', older_than => '2024-09-06 11:00:00')
    trigger_tag_automatic_creation 触发 tag 自动创建。参数:
  • table: 目标表标识符。不能为空。
    		•  CALL sys.trigger_tag_automatic_creation(table => 'default.T')
    rollback 回滚到目标表的指定版本,注意 version/snapshot/tag 必须设置其中一个。参数:
  • table: 目标表标识符。不能为空。
  • version: 要回滚到的快照 id 或 tag 名称,version 将被废弃(Deprecated)。
  • snapshot: 要回滚到的快照。
  • tag: 要回滚到的 tag。
    		•  CALL sys.rollback(table => 'default.T', version => 'my_tag')

    CALL sys.rollback(table => 'default.T', version => 10)

    CALL sys.rollback(table => 'default.T', tag => 'tag1') CALL sys.rollback(table => 'default.T', snapshot => 2)
    rollback_to_timestamp 回滚到早于或等于指定时间戳的快照。参数:
  • table: 目标表标识符。不能为空。
  • timestamp: 回滚到早于或等于该时间戳的快照。
    		•  CALL sys.rollback_to_timestamp(table => 'default.T', timestamp => 1730292023000)
    rollback_to_watermark 回滚到早于或等于指定 watermark 的快照。参数:
  • table: 目标表标识符。不能为空。
  • watermark: 回滚到早于或等于该 watermark 的快照。
    		•  CALL sys.rollback_to_watermark(table => 'default.T', watermark => 1730292023000)
    purge_files 通过 purge files 清空表。参数:
  • table: 目标表标识符。不能为空。
    		•  CALL sys.purge_files(table => 'default.T')
    migrate_database 将数据库中的所有 Hive 表迁移为 Paimon 表。参数:
  • source_type: 待迁移源数据库的类型,例如 hive。不能为空。
  • database: 待迁移源数据库的名称。不能为空。
  • options: 迁移目标 Paimon 表的表选项。
  • options_map: 以 map 形式添加键值选项的选项 map。
  • parallelism: 迁移过程的并行度,默认为机器核数。
    		•  CALL sys.migrate_database(source_type => 'hive', database => 'db01', options => 'file.format=parquet', options_map => map('k1','v1'), parallelism => 6)
    migrate_table 将 Hive 表迁移为 Paimon 表。参数:
  • source_type: 待迁移源表的类型,例如 hive。不能为空。
  • table: 待迁移源表的名称。不能为空。
  • options: 迁移目标 Paimon 表的表选项。
  • target_table: 迁移目标 Paimon 表的名称。不设置时与源表同名。
  • delete_origin: 设置了 target_table 时,可用 delete_origin 决定迁移后是否从 HMS 删除源表元数据。默认为 true。
  • options_map: 以 map 形式添加键值选项的选项 map。
  • parallelism: 迁移过程的并行度,默认为机器核数。
    		•  CALL sys.migrate_table(source_type => 'hive', table => 'default.T', options => 'file.format=parquet', options_map => map('k1','v1'), parallelism => 6)
    remove_orphan_files 移除孤儿数据文件和元数据文件。参数:
  • table: 目标表标识符。不能为空,可以使用 database_name.* 清理整个数据库。
  • older_than: 为避免删除新写入的文件,该 procedure 默认只删除 1 天前的孤儿文件。此参数可修改该间隔。
  • dry_run: 为 true 时,仅查看孤儿文件,不实际删除。默认为 false。
  • parallelism: 并发删除文件的最大数量。默认为 Java 虚拟机可用的处理器数量。
  • mode: 孤儿文件清理 procedure 的模式(local 或 distributed)。默认为 distributed。
    		•  CALL sys.remove_orphan_files(table => 'default.T', older_than => '2023-10-31 12:00:00')

    CALL sys.remove_orphan_files(table => 'default.*', older_than => '2023-10-31 12:00:00')

    CALL sys.remove_orphan_files(table => 'default.T', older_than => '2023-10-31 12:00:00', dry_run => true)

    CALL sys.remove_orphan_files(table => 'default.T', older_than => '2023-10-31 12:00:00', dry_run => true, parallelism => 5)

    CALL sys.remove_orphan_files(table => 'default.T', older_than => '2023-10-31 12:00:00', dry_run => true, parallelism => 5, mode => 'local')
    remove_unexisting_files 从 manifest 条目中移除不存在的数据文件的 procedure。详细使用场景请参阅 Java docs。参数:
  • table: 目标表标识符。不能为空,可以使用 database_name.* 清理整个数据库。
  • dry_run (可选): 只检查哪些文件会被移除,而不真正移除。默认为 false。
  • parallelism (可选): 检查 manifest 中文件的并行度。

    • 注意,使用该 procedure 的风险由用户自行承担,在 Java docs 所列场景之外使用可能会导致数据丢失。     		-- remove unexisting data files in the table `mydb.myt`
    CALL sys.remove_unexisting_files(table => 'mydb.myt')

    -- only check what files will be removed, but not really remove them (dry run)
    CALL sys.remove_unexisting_files(table => 'mydb.myt', dry_run = true)
    repair 将文件系统中的信息同步到 Metastore。参数:
  • database_or_table: 留空,或目标数据库名,或目标表标识符;指定多个时分隔符为 ','。
    		•  CALL sys.repair('test_db.T')

    CALL sys.repair('test_db.T,test_db01,test_db.T2')
    repair_earliest_snapshot 修复表的最早快照 hint。参数:
  • table: 目标表标识符。不能为空。
  • snapshot_id: 要设置为最早快照的快照 ID。
    		•  CALL sys.repair_earliest_snapshot(table => 'test_db.T', snapshot_id => 10)
    create_branch 创建分支。参数:
  • table: 目标表标识符或分支标识符。不能为空。
  • branch: 要创建的分支名称。
  • tag: 新 tag 的名称。不能为空。
  • ignoreIfExists: 分支已存在时忽略,默认为 false。
    		•  CALL sys.create_branch(table => 'test_db.T', branch => 'test_branch')

    CALL sys.create_branch(table => 'test_db.T', branch => 'test_branch', tag => 'my_tag')

    CALL sys.create_branch(table => 'test_db.T$branch_existBranchName', branch => 'test_branch', tag => 'my_tag')
    delete_branch 删除分支。参数:
  • table: 目标表标识符。不能为空。
  • branch: 要删除的分支名称。指定多个分支时分隔符为 ','。
    		•  CALL sys.delete_branch(table => 'test_db.T', branch => 'test_branch')
    rename_branch 重命名分支。参数:
  • table: 目标表标识符。不能为空。
  • from_branch: 要重命名的分支名称。
  • to_branch: 分支的新名称。
    		•  CALL sys.rename_branch(table => 'test_db.T', from_branch => 'test_branch', to_branch => 'new_branch')
    fast_forward 将分支 fast-forward 到 main 分支。参数:
  • table: 目标表标识符。不能为空。
  • branch: 要合并的分支名称。
    		•  CALL sys.fast_forward(table => 'test_db.T', branch => 'test_branch')
    merge_branch 将源分支的数据文件合并到目标分支,仅适用于 append-only 表。 表必须以 'branch-merge.enabled' = 'true' 创建。该选项通过拒绝 compaction 和 INSERT OVERWRITE 来强制纯追加的表历史,且与 deletion vectors 不兼容。 要求源和目标之间具有兼容的 schema 历史以及一致的 row-tracking 设置。参数:
  • table: 表标识符。不能为空。
  • source_branch: 合并来源的源分支名称。不能为空。
  • target_branch(可选): 合并目标的目标分支名称。默认为 'main'。
    		•  CALL sys.merge_branch(table => 'test_db.T', source_branch => 'branch1')

    CALL sys.merge_branch(table => 'test_db.T', source_branch => 'branch1', target_branch => 'branch2')
    reset_consumer 重置或删除 consumer。参数:
  • table: 目标表标识符。不能为空。
  • consumerId: 要重置或删除的 consumer。
  • nextSnapshotId (Long): consumer 的新下一个快照 id。
    		•  -- reset the new next snapshot id in the consumer
    CALL sys.reset_consumer(table => 'default.T', consumerId => 'myid', nextSnapshotId => 10)

    -- delete consumer
    CALL sys.reset_consumer(table => 'default.T', consumerId => 'myid')
    clear_consumers 清理 consumers。参数:
  • table: 目标表标识符。不能为空。
  • includingConsumers: 要清理的 consumers。
  • excludingConsumers: 不清理的 consumers。
    		•  -- clear all consumers in the table
    CALL sys.clear_consumers(table => 'default.T')

    -- clear some consumers in the table (accept regular expression)
    CALL sys.clear_consumers(table => 'default.T', includingConsumers => 'myid.*')

    -- clear all consumers except excludingConsumers in the table (accept regular expression)
    CALL sys.clear_consumers(table => 'default.T', includingConsumers => '', excludingConsumers => 'myid1.*')

    -- clear all consumers with includingConsumers and excludingConsumers (accept regular expression)
    CALL sys.clear_consumers(table => 'default.T', includingConsumers => 'myid.*', excludingConsumers => 'myid1.*')
    mark_partition_done 将分区标记为 done。参数:
  • table: 目标表标识符。不能为空。
  • partitions: 需要标记为 done 的分区,指定多个分区时分隔符为 ';'。
    		•  -- mark single partition done
    CALL sys.mark_partition_done(table => 'default.T', partitions => 'day=2024-07-01')

    -- mark multiple partitions done
    CALL sys.mark_partition_done(table => 'default.T', partitions => 'day=2024-07-01;day=2024-07-02')
    compact_manifest 压缩 manifest。参数:
  • table: 目标表标识符。不能为空。
  • options: 表的额外动态选项。优先级高于原有 `tableProp`,低于 `procedureArg`。
  • dry_run (Boolean, 可选): 为 true 时,仅记录 manifest 元数据统计信息而不实际压缩。启用 manifest sort 时,日志还会包含 manifest sort 构建的每个 level 的 manifest 文件数量。结果输出到应用日志;SQL 返回值仍为 `true`。
  • manifest_sort_enabled (Boolean, 可选): 本次调用是否使用 manifest sort 重写。
  • manifest_sort_partition_field (String, 可选): 用于排序 manifest 条目的分区字段。默认为第一个分区字段。
  • manifest_sort_max_rewrite_size (String, 可选): 一次 sort pass 重写的最大 manifest 大小。
    		•  CALL sys.compact_manifest(`table` => 'default.T')
    CALL sys.compact_manifest(`table` => 'default.T', dry_run => true)
    CALL sys.compact_manifest(`table` => 'default.T', manifest_sort_enabled => true, manifest_sort_partition_field => 'dt', manifest_sort_max_rewrite_size => '1 gb')
    alter_view_dialect 修改 view 的方言。参数:
  • view: 目标 view 标识符。不能为空。
  • action: 定义变更动作,例如 add、update、drop。不能为空。
  • engine: 当引擎不是 spark 时需要定义。
  • query: 方言对应的查询,action 为 add 和 update 时不能为空。
    		•  -- add dialect in the view
    CALL sys.alter_view_dialect('view_identifier', 'add', 'spark', 'query')
    CALL sys.alter_view_dialect(`view` => 'view_identifier', `action` => 'add', `query` => 'query')

    -- update dialect in the view
    CALL sys.alter_view_dialect('view_identifier', 'update', 'spark', 'query')
    CALL sys.alter_view_dialect(`view` => 'view_identifier', `action` => 'update', `query` => 'query')

    -- drop dialect in the view
    CALL sys.alter_view_dialect('view_identifier', 'drop', 'spark')
    CALL sys.alter_view_dialect(`view` => 'view_identifier', `action` => 'drop')
    create_function 创建函数。参数:
  • function: 目标函数标识符。不能为空。
  • inputParams: 函数的输入参数。
  • returnParams: 函数的返回参数。
  • deterministic: 函数是否是确定性的。
  • comment: 函数的注释。
  • options: 函数的额外动态选项。
    		•  CALL sys.create_function(`function` => 'function_identifier',
    `inputParams` => '[{"id": 0, "name":"length", "type":"INT"}, {"id": 1, "name":"width", "type":"INT"}]',
    `returnParams` => '[{"id": 0, "name":"area", "type":"BIGINT"}]',
    `deterministic` => true,
    `comment` => 'comment',
    `options` => 'k1=v1,k2=v2'
    )
    alter_function 修改函数。参数:
  • function: 目标函数标识符。不能为空。
  • change: 函数的变更内容。
    		•  CALL sys.alter_function(`function` => 'function_identifier',
    `change` => '{"action" : "addDefinition", "name" : "spark", "definition" : {"type" : "lambda", "definition" : "(Integer length, Integer width) -> { return (long) length * width; }", "language": "JAVA" } }'
    )
    drop_function 删除函数。参数:
  • function: 目标函数标识符。不能为空。
    		•  CALL sys.drop_function(`function` => 'function_identifier')
    rewrite_file_index 重写表的文件索引。参数:
  • table: 目标表标识符。不能为空。
  • where: 分区谓词。留空表示所有分区。
    		•  CALL sys.rewrite_file_index(table => "t")
    CALL sys.rewrite_file_index(table => "t", where => "day = '2025-08-17'")
    create_global_index 为指定列创建全局索引文件。表必须设置 row-tracking.enabled=true。参数:
  • table: 目标表标识符。不能为空。
  • index_column: 要建索引的列名。不能为空。
  • index_type: 要构建的索引类型,例如 'btree'、'bitmap' 或 'fm'。不能为空。
  • partitions: 分区过滤器,用于限定建索引的分区。逗号(",")表示 "AND",分号(";")表示 "OR"。留空表示所有分区。
  • options: 表的额外动态选项。优先级高于原有 `tableProp`,低于 `procedureArg`。
    		•  CALL sys.create_global_index(table => 'default.T', index_column => 'name', index_type => 'btree')

    CALL sys.create_global_index(table => 'default.T', index_column => 'tag', index_type => 'bitmap', options => 'sorted-index.records-per-range=1000000')

    CALL sys.create_global_index(table => 'default.T', index_column => 'content', index_type => 'fm')

    CALL sys.create_global_index(table => 'default.T', index_column => 'name', index_type => 'btree', partitions => 'pt=p1;pt=p2')

    CALL sys.create_global_index(table => 'default.T', index_column => 'content', index_type => 'full-text', options => 'full-text.tokenizer=ngram,full-text.ngram.min-gram=2,full-text.ngram.max-gram=2')

    CALL sys.create_global_index(table => 'default.T', index_column => 'content', index_type => 'full-text', options => 'full-text.tokenizer=jieba')

    CALL sys.create_global_index(table => 'default.T', index_column => 'content', index_type => 'full-text', options => 'full-text.tokenizer=simple,full-text.stem=true,full-text.remove-stop-words=true')
    drop_global_index 删除指定列的全局索引文件。参数:
  • table: 目标表标识符。不能为空。
  • index_column: 已建索引的列名。不能为空。
  • index_type: 要删除的索引类型,例如 'btree'。不能为空。
  • partitions: 分区过滤器,用于限定删除索引的分区。逗号(",")表示 "AND",分号(";")表示 "OR"。留空表示所有分区。
  • dry_run: 为 true 时,返回将被删除的索引文件数量而不提交任何变更。默认为 false。
    		•  CALL sys.drop_global_index(table => 'default.T', index_column => 'name', index_type => 'btree', partitions => 'pt=p1')

    -- Preview what would be dropped without deleting
    CALL sys.drop_global_index(table => 'default.T', index_column => 'name', index_type => 'btree', dry_run => true)
    reassign_row_id 当分区 row-id 范围重叠时,为 data evolution 表重新分配 row ID。表必须设置 row-tracking.enabled=true 且 data-evolution.enabled=true。参数:
  • table: 目标表标识符。不能为空。
  • partitions: 分区过滤器,用于限定重新分配的分区。逗号(",")表示 "AND",分号(";")表示 "OR"。留空表示所有分区。
    		•  CALL sys.reassign_row_id(table => 'default.T')

    CALL sys.reassign_row_id(table => 'default.T', partitions => 'dt=2026-05-19')
    copy 复制表文件。参数:
  • source_table: 源表标识符。不能为空。
  • target_table: 目标表标识符。不能为空。
  • where: 分区谓词。留空表示所有分区。
    		•  CALL sys.copy(source_table => "t1", target_table => "t1_copy")
    CALL sys.copy(source_table => "t1", target_table => "t1_copy", where => "day = '2025-08-17'")
    rescale 通过改变 bucket 数量来对表的分区进行 rescale。参数:
  • table: 目标表标识符。不能为空。
  • bucket_num: rescale 后的目标 bucket 数量。默认值为表当前的 bucket 数量。postpone bucket 表必填。
  • partitions: 分区过滤器。留空表示所有分区。(不能与 "where" 同时使用)
  • where: 分区谓词。留空表示所有分区。(不能与 "partitions" 同时使用)
    		•  CALL sys.rescale(table => 'default.T', bucket_num => 16, partitions => 'dt=20250217,hh=08;dt=20250217,hh=09')
