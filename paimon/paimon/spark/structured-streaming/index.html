Structured Streaming

Paimon 支持使用 Spark Structured Streaming 进行流式数据处理,同时支持流式写入和流式查询。

流式写入​

信息

Paimon Structured Streaming 仅支持 append 和 complete 两种模式。

// Create a paimon table if not exists.
spark.sql(s"""
           |CREATE TABLE T (k INT, v STRING)
           |TBLPROPERTIES ('primary-key'='k', 'bucket'='3')
           |""".stripMargin)

// Here we use MemoryStream to fake a streaming source.
val inputData = MemoryStream[(Int, String)]
val df = inputData.toDS().toDF("k", "v")

// Streaming Write to paimon table.
val stream = df
  .writeStream
  .outputMode("append")
  .option("checkpointLocation", "/path/to/checkpoint")
  .format("paimon")
  .start("/path/to/paimon/sink/table")

流式写入同样支持 Write merge schema。

流式查询​

信息

Paimon 流式读取目前要求 Spark 3.3+。

Paimon 支持丰富的流式读取 scan 模式,列表如下:

Scan Mode Description
latest
 对于流式 source,持续读取最新变更,开始时不生成快照。
latest-full
 对于流式 source,首次启动时生成表的最新快照,然后继续读取最新变更。
from-timestamp
 对于流式 source,从 "scan.timestamp-millis" 指定的时间戳开始持续读取变更,开始时不生成快照。
from-snapshot
 对于流式 source,从 "scan.snapshot-id" 指定的快照开始持续读取变更,开始时不生成快照。
from-snapshot-full
 对于流式 source,首次启动时生成 "scan.snapshot-id" 指定的表快照,并持续读取变更。
default
 如果指定了 "scan.snapshot-id",等价于 from-snapshot;如果指定了 "timestamp-millis",等价于 from-timestamp;否则等价于 latest-full。

一个使用默认 scan 模式的简单示例:

// no any scan-related configs are provided, that will use latest-full scan mode.
val query = spark.readStream
  .format("paimon")
  // by table name
  .table("table_name") 
  // or by location
  // .load("/path/to/paimon/source/table")
  .writeStream
  .format("console")
  .start()

Consumer 进度​

你可以为流式查询分配一个 Paimon Consumer。Consumer 记录表侧的、 快照级别的恢复位置,并在正常的快照过期期间充当防护(fence)。对于 changelog 生命周期 解耦的表,启用 consumer.changelog-only 会使 Consumer 保护长生命周期的 changelog 而不是快照。

在启动查询之前,将 Consumer 生命周期配置为表属性:

ALTER TABLE table_name SET TBLPROPERTIES (
  'consumer.expiration-time' = '1 d'
);
val query = spark.readStream
  .format("paimon")
  .option("consumer-id", "my-consumer")
  .table("table_name")
  .writeStream
  .format("console")
  .option("checkpointLocation", "/path/to/spark/checkpoint")
  .start()

Spark checkpoint 和 Paimon Consumer 进度的粒度不同:

  • 当 Spark checkpoint 可用时,Spark 使用它进行精确的微批次 恢复。
  • 没有该 checkpoint 的新查询从 Consumer 位置开始。这种 恢复是保守的:如果查询在处理完某个快照之后、更新 Consumer 之前失败, 可能会重放一个已完成的快照。

Paimon 只从 Spark 成功提交微批次的回调中更新 Consumer。当一个微批次在某个增量快照的中途结束时,Consumer 可能会在该快照处被创建或刷新,使该快照整体保持受保护并可被重放。 只有在包含某个快照最后一个 split 的微批次提交后,Consumer 才会越过该快照。 Consumer 更新失败会被传播,使运行中的查询失败,Consumer 停留在之前 的保守位置。

Spark 永远不会将 Consumer 进度推过未完成的快照。未完成的 初始全量快照不会创建 Consumer,因为从该快照进行 Consumer 恢复会使用 增量扫描。consumer.mode 不会选择不同的 Spark source 实现。

从旧版 Spark checkpoint 恢复的 offset 不含快照完成 元数据。对于这些 offset,Spark 会记录警告并保持 Consumer 不变, 而不是在没有快照完成证据的情况下将其推进。

如果 Consumer 不存在,则使用配置的启动选项。例如, 默认的 latest-full 模式会先读取全量快照,并且仅在该快照完全提交后 才创建 Consumer。如果 Consumer 已经存在,其下一个快照优先于启动选项, 并以增量方式读取,除非启用了 consumer.ignore-progress。

备注

Spark 可能在构造后面的微批次时调用 source 的 commit 回调。 因此 Consumer 可能暂时落后于最新成功的批次,特别是在查询空闲 或最后一个可用批次之后。这是安全的,只会导致保守的重放。

Consumer 文件的作用域限定在被读取的 branch。每个 (table, branch, consumer-id) 组合使用一个活跃的 Spark 查询。 不支持多个并发查询共享同一个 Consumer,因为更快的查询可能将共享 位置推过较慢查询仍需要的数据。

请根据最长预期的快照处理时间、故障恢复时间和空闲间隔来配置 consumer.expiration-time。符合条件的 Spark source commit 回调会刷新 Consumer 文件,但没有独立的基于定时器的 Spark 心跳。过期的 Consumer 文件 由非 write-only 的表 commit 清理。write-only 的写入端不执行 Consumer 过期, 因此过期的 Consumer ID 必须显式管理,或由独立的非 write-only 维护进程管理。

初始全量扫描在完成之前没有 Consumer 保留防护,因此 快照保留时间应足够覆盖该扫描。如果其快照先过期,没有 Spark checkpoint 的重启将根据启动选项执行新的初始全量扫描。

当过期的数据迫使已记录 Spark 批次的恢复在全量扫描和增量扫描 之间切换时,Paimon 会使查询失败,而不是将两种计划组合起来。此时应使用新的 checkpoint 启动新查询,以重新应用启动选项。

Paimon Structured Streaming 还支持多种流式读取模式,可以支持多种 trigger 和多种读取限制。

支持以下读取限制:

Key Default Type Description
read.stream.maxFilesPerTrigger
 (none) Integer 单个批次返回的最大文件数。
read.stream.maxBytesPerTrigger
 (none) Long 单个批次返回的最大字节数。
read.stream.maxRowsPerTrigger
 (none) Long 单个批次返回的最大行数。
read.stream.minRowsPerTrigger
 (none) Long 单个批次返回的最小行数,与 read.stream.maxTriggerDelayMs 一起用于创建 MinRowsReadLimit。
read.stream.maxTriggerDelayMs
 (none) Long 相邻两个批次之间的最大延迟,与 read.stream.minRowsPerTrigger 一起用于创建 MinRowsReadLimit。

示例一

使用 org.apache.spark.sql.streaming.Trigger.AvailableNow() 和 Paimon 定义的 maxBytesPerTrigger。

// Trigger.AvailableNow()) processes all available data at the start
// of the query in one or multiple batches, then terminates the query.
// That set read.stream.maxBytesPerTrigger to 128M means that each
// batch processes a maximum of 128 MB of data.
val query = spark.readStream
  .format("paimon")
  .option("read.stream.maxBytesPerTrigger", "134217728")
  .table("table_name")
  .writeStream
  .format("console")
  .trigger(Trigger.AvailableNow())
  .start()

示例二

使用 org.apache.spark.sql.connector.read.streaming.ReadMinRows。

// It will not trigger a batch until there are more than 5,000 pieces of data,
// unless the interval between the two batches is more than 300 seconds.
val query = spark.readStream
  .format("paimon")
  .option("read.stream.minRowsPerTrigger", "5000")
  .option("read.stream.maxTriggerDelayMs", "300000")
  .table("table_name")
  .writeStream
  .format("console")
  .start()

微批次写入的列​

foreachBatch 消费者可以检查当前微批次所纳入的数据文件写入了哪些 Paimon field ID。使用传给 foreachBatch 的原始 Dataset 调用 PaimonSparkMicroBatchMetadata.writtenColumnIds。Paimon 在调用该方法时才惰性解析文件元数据。

import org.apache.paimon.spark.PaimonSparkMicroBatchMetadata
import org.apache.spark.sql.{Dataset, Row}

val query = spark.readStream
  .format("paimon")
  .table("table_name")
  .writeStream
  .option("checkpointLocation", "/path/to/checkpoint")
  .foreachBatch { (batch: Dataset[Row], _: Long) =>
    val writtenColumnIds = PaimonSparkMicroBatchMetadata.writtenColumnIds(batch)
    if (!writtenColumnIds.isPresent) {
      // Metadata is unavailable; conservatively process all columns.
    } else {
      val fieldIds = writtenColumnIds.get()
      // Process the exact set of written Paimon field IDs.
    }
  }
  .start()

存在值的 Optional 包含完整、不可变的已写入 field ID 列表,按升序排列。该列表可以为空;这表示已知的空集合,而不是未知元数据。

空的 Optional 表示元数据不可用,例如因为文件或 schema 无法解析、微批次为空、Dataset 不是来自恰好只有一个不同的 Paimon 流式 source 的查询的原始批次,或其血缘不完整或有歧义。空的 Optional 并不表示没有列被写入;调用方必须回退为处理所有列。

Paimon Structured Streaming 支持以 changelog 形式读取行(在行中增加 rowkind 列来表示其变更类型), 有两种方式:

  • 通过系统 audit_log 表直接流式读取
  • 将 read.changelog 设置为 true(默认为 false),然后使用表 location 进行流式读取

示例:

// Option 1
val query1 = spark.readStream
  .format("paimon")
  .table("`table_name$audit_log`")
  .writeStream
  .format("console")
  .start()

// Option 2
val query2 = spark.readStream
  .format("paimon")
  .option("read.changelog", "true")
  .table("table_name")
  .writeStream
  .format("console")
  .start()

/*
+I   1  Hi
+I   2  Hello
*/
