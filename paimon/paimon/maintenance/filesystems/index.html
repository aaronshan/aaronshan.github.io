文件系统

Apache Paimon 使用与 Apache Flink 相同的可插拔文件系统。如果使用 Flink 作为计算引擎,用户可以遵循 标准插件机制 来配置插件结构。但是对于 Spark 或 Hive 等其他引擎,(Flink 提供的)opt jar 可能会产生冲突而无法直接使用。让用户去修复类冲突并不方便,因此 Paimon 提供了自包含、跨引擎统一的 FileSystem 可插拔 jar,方便用户从 Spark/Hive 侧查询表。

支持的文件系统​

文件系统URI Scheme可插拔描述
本地文件系统file://否内置支持
HDFShdfs://否内置支持,需确保集群处于 Hadoop 环境中
Aliyun OSSoss://是
S3s3://是
腾讯云对象存储cosn://是
Microsoft Azure Storageabfs://是
Huawei OBSobs://是
Google Cloud Storagegs://是
Aliyun OSS-HDFS (DLS)dls://是需要 paimon-jindodls 和 paimon-jindo jar,以及环境中的 Jindo SDK(见 OSS)

依赖​

推荐你直接下载 jar:下载链接。

你也可以从源码手动构建打包好的 jar。

要从源码构建,请先克隆 git 仓库。

使用以下命令构建 shaded jar。

mvn clean install -DskipTests

你可以在 ./paimon-filesystems/paimon-${fs}/target/paimon-${fs}-2.1-SNAPSHOT.jar 下找到构建出的 shaded jar。

HDFS​

访问 HDFS 不需要任何额外的依赖,因为你已经处理好了 Hadoop 依赖。

HDFS 配置​

对于 HDFS,最重要的是能够读取到你的 HDFS 配置。

  • Flink
  • Hive/Spark

如果你已经处于 Hadoop 环境中,可能什么都不用做。否则,请选择以下方式之一来配置你的 HDFS:

  1. 设置环境变量 HADOOP_HOME 或 HADOOP_CONF_DIR。
  2. 在 Paimon catalog 中配置 'hadoop-conf-dir'。
  3. 在 Paimon catalog 中通过前缀 'hadoop.' 配置 Hadoop 选项。

推荐使用第一种方式。

如果你不希望包含环境变量的值,可以将 hadoop-conf-loader 配置为 option。

HDFS 配置可以直接通过计算集群获取,详情参见 Hive 和 Spark 的集群配置。

Paimon-Hadoop Uber 包​

如果你想在一个没有 Hadoop 依赖的应用中读写 Hadoop 集群上的 Paimon 表, 可以使用 Paimon Hadoop uber jar。

下载 paimon-hadoop-uber-2.1-SNAPSHOT.jar。

将 paimon-hadoop-uber-2.1-SNAPSHOT.jar 放入你应用的 classpath 目录。

Hadoop 兼容文件系统(HCFS)​

当 Hadoop 库位于 classpath 上时,所有 Hadoop 文件系统都会自动可用。

通过这种方式,Paimon 无缝支持所有实现了 org.apache.hadoop.fs.FileSystem 接口的 Hadoop 文件系统,以及所有 Hadoop 兼容文件系统(HCFS)。

  • HDFS
  • Alluxio(配置细节见下文)
  • XtreemFS
  • …

Hadoop 配置必须在 core-site.xml 文件中包含所需文件系统实现的条目。

要支持 Alluxio,请在 core-site.xml 文件中添加以下条目:

<property>
  <name>fs.alluxio.impl</name>
  <value>alluxio.hadoop.FileSystem</value>
</property>

Kerberos​

  • Flink
  • Spark
  • Hive
  • Trino/JavaAPI

在你的 catalog 配置中配置以下选项:

  • security.kerberos.login.keytab:包含用户凭证的 Kerberos keytab 文件的绝对路径。 请确保它被拷贝到每台机器上。
  • security.kerberos.login.principal:与 keytab 关联的 Kerberos principal 名称。

并在程序的 java 属性中配置以下选项:

  • java.security.krb5.conf:Kerberos 配置文件的绝对路径。 请确保它被拷贝到每台机器上。

推荐使用 Spark Kerberos Keytab。

一种直观的方式是配置 Hive 的 kerberos 认证。

在你的 catalog 配置中配置以下三个选项:

  • security.kerberos.login.keytab:包含用户凭证的 Kerberos keytab 文件的绝对路径。 请确保它被拷贝到每台机器上。
  • security.kerberos.login.principal:与 keytab 关联的 Kerberos principal 名称。
  • security.kerberos.login.use-ticket-cache:true 或 false,表示是否从你的 Kerberos ticket 缓存中读取。

对于 JavaAPI:

SecurityContext.install(catalogOptions);

HDFS HA​

确保 hdfs-site.xml 和 core-site.xml 包含必要的 HA 配置。

HDFS ViewFS​

确保 hdfs-site.xml 和 core-site.xml 包含必要的 ViewFs 配置。

OSS​

下载 paimon-oss-2.1-SNAPSHOT.jar。

  • Flink
  • Spark
  • Hive
  • Trino
信息

如果你已经通过 Flink 配置了 OSS 访问(通过 Flink FileSystem), 这里可以跳过以下配置。

将 paimon-oss-2.1-SNAPSHOT.jar 放入 Flink home 的 lib 目录,然后创建 catalog:

CREATE CATALOG my_catalog WITH (
    'type' = 'paimon',
    'warehouse' = 'oss://<bucket>/<path>',
    'fs.oss.endpoint' = 'oss-cn-hangzhou.aliyuncs.com',
    'fs.oss.accessKeyId' = 'xxx',
    'fs.oss.accessKeySecret' = 'yyy'
);
信息

如果你已经通过 Spark 配置了 OSS 访问(通过 Hadoop FileSystem),这里可以跳过以下配置。

将 paimon-oss-2.1-SNAPSHOT.jar 与 paimon-spark-2.1-SNAPSHOT.jar 一起放入 Spark 的 jars 目录,然后像下面这样启动:

spark-sql \
  --conf spark.sql.extensions=org.apache.paimon.spark.extensions.PaimonSparkSessionExtensions \
  --conf spark.sql.catalog.paimon=org.apache.paimon.spark.SparkCatalog \
  --conf spark.sql.catalog.paimon.warehouse=oss://<bucket>/<path> \
  --conf spark.sql.catalog.paimon.fs.oss.endpoint=oss-cn-hangzhou.aliyuncs.com \
  --conf spark.sql.catalog.paimon.fs.oss.accessKeyId=xxx \
  --conf spark.sql.catalog.paimon.fs.oss.accessKeySecret=yyy
信息

如果你已经通过 Hive 配置了 OSS 访问(通过 Hadoop FileSystem),这里可以跳过以下配置。

注意:你需要确保 Hive metastore 能够访问 oss。

将 paimon-oss-2.1-SNAPSHOT.jar 与 paimon-hive-connector-2.1-SNAPSHOT.jar 一起放入 Hive 的 auxlib 目录,然后像下面这样启动:

SET paimon.fs.oss.endpoint=oss-cn-hangzhou.aliyuncs.com;
SET paimon.fs.oss.accessKeyId=xxx;
SET paimon.fs.oss.accessKeySecret=yyy;

然后从 hive metastore 读取表,表可以由 Flink 或 Spark 创建,参见 Catalog with Hive Metastore

SELECT * FROM test_table;
SELECT COUNT(1) FROM test_table;

从 0.8 版本开始,paimon-trino 使用 trino filesystem 作为基础的文件读写系统。我们强烈建议你在 trino 中使用 jindo-sdk。

你可以在这里找到如何在 trino 上配置 jindo sdk。 请注意:

  • 解压插件 jar 并寻找放置位置时,使用 paimon 替代 hive-hadoop2。
  • 你可以在配置 hive.config.resources 中的 paimon.properties 里指定 core-site.xml。
  • Presto 和 Jindo 使用相同的配置方法。

如果你的环境中有 jindo sdk 依赖,可以使用 Jindo Fs 连接 OSS。Jindo 有更好的读写效率。

下载 paimon-jindo-2.1-SNAPSHOT.jar。

服务端加密​

Paimon 可以通过三个与 OSS 请求头一一对应的键,在其执行的写入操作(PutObject、rename/commit 使用的服务端 CopyObject,以及分块上传初始化)上标记 OSS 服务端加密请求头:

# 加密方式:AES256、KMS 或 SM4(对应 x-oss-server-side-encryption)
fs.oss.server-side-encryption: KMS
# 客户主密钥 CMK 的 key id,仅在使用 KMS 时有效(对应 x-oss-server-side-encryption-key-id)
fs.oss.server-side-encryption-key-id: your-cmk-key-id
# 数据加密算法 SM4,仅在使用 KMS 时有效(对应 x-oss-server-side-data-encryption)
fs.oss.server-side-data-encryption: SM4

当设置了其中任意一个键时,Paimon 会在其写入路径上接管 SSE 请求头(这些键优先于 hadoop-aliyun 原生的 fs.oss.server-side-encryption-algorithm)。指定 key id 或 SM4 数据加密要求 fs.oss.server-side-encryption=KMS(未设置时默认为 KMS),否则将被拒绝。

Paimon 使用共享的 trino filesystem 作为基础的读写系统。

请参考 Trino S3 在 trino 中配置 S3 文件系统。

兼容 S3 的对象存储​

S3 文件系统也支持使用兼容 S3 的对象存储,例如 MinIO、腾讯云 COS 和 IBM 的 Cloud Object Storage。只需将 endpoint 配置为对象存储服务的提供商即可。

s3.endpoint: your-endpoint-hostname

配置 Path Style 访问​

某些兼容 S3 的对象存储默认可能没有启用 virtual host 风格的寻址,例如出于测试目的使用独立部署的 MinIO 时。 在这种情况下,你必须提供以下属性来启用 path style 访问。

s3.path.style.access: true

S3A 性能​

为 S3AFileSystem 调优性能请参见Tune Performance。

如果你遇到以下异常:

Caused by: org.apache.http.conn.ConnectionPoolTimeoutException: Timeout waiting for connection from pool.

请尝试在 catalog 选项中配置:fs.s3a.connection.maximum=1000。
