管理 Snapshot

本节将介绍与 snapshot 相关的管理和行为。

过期 Snapshot​

Paimon writer 每次提交会生成一到两个 snapshot。每个 snapshot 可能会新增一些数据文件,或将一些旧数据文件标记为已删除。然而,被标记的数据文件并没有被真正删除,因为 Paimon 还支持回溯到更早 snapshot 的时间旅行。只有当 snapshot 过期时,它们才会被删除。

目前,过期操作由 Paimon writer 在提交新变更时自动执行。通过过期旧 snapshot,不再使用的旧数据文件和元数据文件可以被删除,从而释放磁盘空间。

Snapshot 过期由以下表属性控制。

选项是否必填默认值类型描述
snapshot.time-retained
否1 hDuration已完成 snapshot 保留的最大时间。
snapshot.num-retained.min
否10Integer已完成 snapshot 保留的最小数量。必须大于或等于 1。
snapshot.num-retained.max
否Integer.MAX_VALUEInteger已完成 snapshot 保留的最大数量。必须大于或等于最小数量。
snapshot.expire.execution-mode
否syncEnum指定过期操作的执行模式。
snapshot.expire.limit
否10Integer单次允许过期的最大 snapshot 数量。
snapshot.clean-empty-directories
否falseBoolean是否尝试删除 snapshot 过期过程中数据文件被删除后留下的空目录(例如分区和 bucket 目录)。默认为 false:保留空目录。开启该选项有注意事项:HDFS 可能在 NameNode 中打印异常,而对象存储(OSS/S3)可能因列举和删除目录标记所需的额外前缀操作而出现性能问题。

当 snapshot 数量小于 snapshot.num-retained.min 时,不会有任何 snapshot 过期(即使满足 snapshot.time-retained 条件);此后将使用 snapshot.num-retained.max 和 snapshot.time-retained 来控制 snapshot 过期,直到剩余 snapshot 满足条件。

请注意,snapshot 过期也是物理删除分区过期所丢弃数据文件的机制。然而,数据文件被删除后留下的空分区和 bucket 目录默认不会被移除。要清理它们,请启用 snapshot.clean-empty-directories(见上面的选项)。该选项默认关闭,因为在对象存储(OSS/S3)上,删除目录标记所需的前缀操作开销可能很大。

请注意,保留时间过短或保留数量过少可能导致:

  • 批处理查询找不到文件。例如,表比较大,批处理查询需要读取 10 分钟, 但 10 分钟前的 snapshot 已经过期,此时批处理查询将读取一个已删除的 snapshot。
  • 表文件的流式读取作业重启失败。 作业重启时,它记录的 snapshot 可能已经过期。(你可以使用 Consumer Id 在 snapshot 过期保留时间较短的情况下保护流式读取)。

默认情况下,Paimon 会同步删除过期的 snapshot。当需要删除的文件过多时, 它们可能无法被快速删除,从而反压到上游算子。为避免这种情况, 用户可以将 snapshot.expire.execution-mode 设置为 async 来使用异步过期模式。 然而,如果你的作业运行在批处理模式下,不建议使用异步过期模式, 因为过期任务可能无法成功完成。

手动过期 Snapshot​

手动过期表的 snapshot。

  • Flink SQL
  • Flink Action
  • Spark

运行以下命令:

-- for Flink 1.18
CALL sys.expire_snapshots('database_name.table_name', 2)
-- for Flink 1.19 and later
CALL sys.expire_snapshots(`table` => 'database_name.table_name', retain_max => 2)
CALL sys.expire_snapshots(`table` => 'database_name.table_name', older_than => '2024-01-01 12:00:00')
CALL sys.expire_snapshots(`table` => 'database_name.table_name', older_than => '2024-01-01 12:00:00', retain_min => 10)
CALL sys.expire_snapshots(`table` => 'database_name.table_name', older_than => '2024-01-01 12:00:00', max_deletes => 10, options => 'snapshot.expire.limit=1')

运行以下命令:

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    expire_snapshots \
    --warehouse <warehouse-path> \
    --identifier <identifier> \
    --older_than <timestamp> \
    --version <snapshot-id> \
    --max_deletes <max-deletes> \
    --retain_max <retain-max> \
    --retain_min <retain-min> \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]]

运行以下 SQL:

CALL sys.expire_snapshots(table => 'database_name.table_name', retain_max => 10, options => 'snapshot.expire.limit=1');

回滚到 Snapshot​

将表回滚到指定的 snapshot ID。

  • Flink SQL
  • Flink Action
  • Java API
  • Spark

运行以下命令:

CALL sys.rollback_to(`table` => 'database_name.table_name', snapshot_id => <snasphot-id>);

运行以下命令:

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    rollback_to \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table <table-name> \
    --version <snapshot-id> \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]]
import org.apache.paimon.table.Table;

public class RollbackTo {

    public static void main(String[] args) {
        // 回滚前:
        // snapshot-3
        // snapshot-4
        // snapshot-5
        // snapshot-6
        // snapshot-7
      
        table.rollbackTo(5);
        
        // 回滚后:
        // snapshot-3
        // snapshot-4
        // snapshot-5
    }
}

运行以下 SQL:

CALL sys.rollback(table => 'database_name.table_name', snapshot => snasphot_id);

回滚到 Snapshot 并作为最新状态​

通过将某个特定 snapshot id 的状态物化为一个新的最新 snapshot,将表回滚到该状态。与 rollback_to 不同,此操作不会删除 snapshot id 大于目标 snapshot 的 snapshot 或 tag。

  • Flink SQL

运行以下命令:

CALL sys.rollback_to_as_latest(`table` => 'database_name.table_name', snapshot_id => <snapshot-id>);
备注

对新的最新 snapshot 进行批处理和时间旅行读取是正确的,因为它指向目标 snapshot 的索引 manifest。然而,对于使用 deletion vector 的表,如果一次回滚与当前最新状态的唯一差异是 deletion vector 变化(数据文件完全相同),则会产生一个空的数据增量,因此不保证能被 流式 overwrite 读取端观察到——这与普通的 deletion vector 删除一样,只能通过 changelog producer 进行流式读取。

清理孤儿文件(Orphan Files)​

Paimon 文件只有在 snapshot 过期时才会被物理删除。然而,删除文件时可能发生一些意外错误, 因此可能存在不再被任何 Paimon snapshot 使用的文件(即所谓的"孤儿文件")。你可以 提交一个 remove_orphan_files 作业来清理它们:

  • Spark SQL/Flink SQL
  • Flink Action
CALL sys.remove_orphan_files(`table` => 'my_db.my_table', [older_than => '2023-10-31 12:00:00'])

CALL sys.remove_orphan_files(`table` => 'my_db.*', [older_than => '2023-10-31 12:00:00'])
<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    remove_orphan_files \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table <table-name> \
    [--older_than <timestamp>] \
    [--dry_run <false/true>] \
    [--parallelism <parallelism>]

为避免删除其他写入作业刚刚新增的文件,该 action 默认只删除 1 天之前的孤儿文件。 该时间间隔可以通过 --older_than 修改。例如:

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    remove_orphan_files \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table T \
    --older_than '2023-10-31 12:00:00'

表名可以是 *,表示清理数据库中的所有表。
