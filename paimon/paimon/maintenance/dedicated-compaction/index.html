独立 Compaction

Paimon 的 Snapshot 管理支持多个 Writer 并发写入。

信息

对于 S3 类的对象存储,其 'RENAME' 操作不具备原子语义。我们需要配置 Hive metastore 并为 catalog 开启 'lock.enabled' 选项。

默认情况下,Paimon 支持对不同分区的并发写入。推荐的模式是:流式作业将记录写入 Paimon 的最新分区,同时批处理作业(overwrite)将记录写入历史分区。

到目前为止,一切都运转良好。但如果你需要多个 Writer 向同一个分区写入记录,情况就会稍微复杂一些。例如,你不想使用 UNION ALL,而是有多个流式作业向一张 'partial-update' 表写入记录。请参考下面的"独立 Compaction 作业"。

独立 Compaction 作业​

默认情况下,Paimon Writer 会在写入记录时按需执行 Compaction。这对大多数使用场景已经足够了。

Compaction 会将一些数据文件标记为"已删除"(并非真正删除,更多信息请参见 过期 Snapshot)。 如果多个 Writer 标记了同一个文件,在提交变更时就会发生冲突。Paimon 会自动解决冲突,但这可能导致作业重启。

为避免这些坏处,用户也可以选择在 Writer 中跳过 Compaction,并运行一个专门用于 Compaction 的独立作业。由于 Compaction 只由独立作业执行,Writer 可以持续写入记录而无需暂停,也不会发生任何冲突。

要在 Writer 中跳过 Compaction,请将以下表属性设置为 true。

选项是否必填默认值类型描述
write-only
否falseBoolean如果设置为 true,Compaction 和 Snapshot 过期将被跳过。该选项与独立 Compaction 作业配合使用。

要运行独立 Compaction 作业,请按照以下说明操作。

  • Flink SQL
  • Flink Action Jar

运行以下 SQL:

CALL sys.compact(
  `table` => 'default.T', 
  partitions => 'p=0', 
  options => 'sink.parallelism=4',
  `where` => 'dt>10 and h<20'
);

运行以下命令为该表提交一个 Compaction 作业。

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    compact \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table <table-name> \
    [--partition <partition-name>] \
    [--buckets <bucket-ids-or-ranges>] \
    [--compact_strategy <minor / full>] \
    [--table_conf <table_conf>] \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]]

示例:压缩表

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    compact \
    --warehouse s3:///path/to/warehouse \
    --database test_db \
    --table test_table \
    --partition dt=20221126,hh=08 \
    --partition dt=20221127,hh=09 \
    --table_conf sink.parallelism=10 \
    --compact_strategy minor \
    --catalog_conf s3.endpoint=https://****.com \
    --catalog_conf s3.access-key=***** \
    --catalog_conf s3.secret-key=*****
  • --compact_strategy 决定如何挑选需要合并的文件,默认值由运行时执行模式决定:流模式使用 minor 策略,批模式使用 full 策略。
    • full:仅支持批模式。所有文件都会被选中进行合并。
    • minor:根据指定条件挑选需要合并的文件集合。

你可以使用 -D execution.runtime-mode=batch 或 -yD execution.runtime-mode=batch(用于 ON-YARN 场景)来控制批处理或流式模式。如果你提交的是批处理作业,当前表的所有文件都会被压缩;如果你提交的是流式作业,该作业将持续监控表的新变更并按需执行 Compaction。

更多 compact action 的用法,请参见

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    compact --help

压缩指定的 Bucket​

对于固定 bucket 的表,独立 Compaction 可以针对选定的 bucket 执行。sys.compact 过程在 Flink SQL 和 Spark SQL 中均可用。该表达式支持单个 ID、逗号分隔的多个 ID、闭区间,或它们的组合,例如 0、0,2,5、0-9 和 0-9,20。

CALL sys.compact(`table` => 'default.T', partitions => 'dt=20221126', compact_strategy => 'full', buckets => '0-1,3');

等价的 Flink Action 命令为:

<FLINK_HOME>/bin/flink run -Dexecution.runtime-mode=batch \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar compact \
    --warehouse s3:///path/to/warehouse --database test_db --table test_table \
    --partition dt=20221126 --compact_strategy full --buckets 0-1,3

buckets 仅支持固定 bucket 的表(bucket > 0)。每个 ID 必须在 0(含)到配置的 bucket 数量(不含)之间。分区过滤条件可以与 bucket 过滤条件组合使用。Sort Compact、动态 bucket 表、unaware-bucket 表以及 postpone-bucket 表不支持 bucket 选择。

信息

同样,默认是同步 Compaction,这可能导致 checkpoint 超时。你可以配置 table_conf 来使用异步 Compaction。

数据库级 Compaction 作业​

你可以运行以下命令为多个数据库提交 Compaction 作业。

  • Flink SQL
  • Flink Action Jar

运行以下 SQL:

CALL sys.compact_database(
  including_databases => 'includingDatabases', 
  mode => 'mode', 
  including_tables => 'includingTables', 
  excluding_tables => 'excludingTables', 
  table_options => 'tableOptions'
)

-- 示例
CALL sys.compact_database(
  including_databases => 'db1|db2', 
  mode => 'combined', 
  including_tables => 'table_.*', 
  excluding_tables => 'ignore', 
  table_options => 'sink.parallelism=4'
)
<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    compact_database \
    --warehouse <warehouse-path> \
    --including_databases <database-name|name-regular-expr> \
    [--including_tables <paimon-table-name|name-regular-expr>] \
    [--excluding_tables <paimon-table-name|name-regular-expr>] \
    [--mode <compact-mode>] \
    [--compact_strategy <minor / full>] \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]] \
    [--table_conf <paimon-table_conf> [--table_conf <paimon-table_conf> ...]]
  • --including_databases 用于指定要压缩哪个数据库。在 compact 模式下,你需要指定一个数据库名;在 compact_database 模式下,你可以指定多个数据库,支持正则表达式。
  • --including_tables 用于指定要压缩哪些源表,多个表之间必须用 '|' 分隔,格式为 databaseName.tableName,支持正则表达式。例如,指定 "--including_tables db1.t1|db2.+" 表示压缩表 'db1.t1' 以及 db2 数据库中的所有表。
  • --excluding_tables 用于指定哪些源表不需要压缩。用法与 "--including_tables" 相同。如果两者都指定了,"--excluding_tables" 的优先级高于 "--including_tables"。
  • --mode 用于指定 Compaction 模式。可选值:
    • "divided"(未指定时的默认模式):为每张表启动一个 sink,新表的 Compaction 需要重启作业。
    • "combined":为所有表启动一个合并的 sink,新表会被自动压缩。
  • --catalog_conf 是 Paimon catalog 的配置。每个配置应以 key=value 格式指定。catalog 配置的完整列表请参见这里。
  • --table_conf 是 Compaction 的配置。每个配置应以 key=value 格式指定。关键配置如下:
配置键默认值类型描述
continuous.discovery-interval10 sDuration持续读取的发现间隔。
sink.parallelism(none)Integer为 sink 定义自定义并行度。默认情况下,如果未定义该选项,规划器将结合全局配置为每条语句单独推导并行度。

你可以使用 -D execution.runtime-mode=batch 来控制批处理或流式模式。如果你提交的是批处理作业,当前表的所有文件都会被压缩;如果你提交的是流式作业,该作业将持续监控表的新变更并按需执行 Compaction。

信息

如果你只想提交 Compaction 作业而不想等待作业完成,应该以 detached 模式提交。

信息

你可以设置 --mode combined,使新增的表无需重启作业即可被压缩。

示例 1:压缩数据库

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    compact_database \
    --warehouse s3:///path/to/warehouse \
    --including_databases test_db \
    --catalog_conf s3.endpoint=https://****.com \
    --catalog_conf s3.access-key=***** \
    --catalog_conf s3.secret-key=*****

示例 2:以 combined 模式压缩数据库

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    compact_database \
    --warehouse s3:///path/to/warehouse \
    --including_databases test_db \
    --mode combined \
    --catalog_conf s3.endpoint=https://****.com \
    --catalog_conf s3.access-key=***** \
    --catalog_conf s3.secret-key=***** \
    --table_conf continuous.discovery-interval=*****

更多 compact_database action 的用法,请参见

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    compact_database --help

Sort Compact​

如果你的表配置了动态 bucket 主键表 或 append 表, 你可以触发一次按指定列排序的 Compaction 来加速查询。

  • Flink SQL
  • Flink Action Jar

运行以下 SQL:

-- sort compact table
CALL sys.compact(`table` => 'default.T', order_strategy => 'zorder', order_by => 'a,b')
<FLINK_HOME>/bin/flink run \
    -D execution.runtime-mode=batch \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    compact \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table <table-name> \
    --order_strategy <orderType> \
    --order_by <col1,col2,...> \
    [--partition <partition-name>] \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]] \
    [--table_conf <paimon-table-dynamic-conf> [--table_conf <paimon-table-dynamic-conf>] ...]

Sort Compact 中新增了两个配置:

{{ $ref := ref . "maintenance/configurations.md" }}
Configuration Description
--order_strategy
 the order strategy now support "zorder" and "hilbert" and "order". For example: --order_strategy zorder
--order_by
 Specify the order columns. For example: --order_by col0, col1

排序并行度与 sink 并行度相同,你可以通过添加 --table_conf sink.parallelism=<value> 配置来动态指定。

信息

Sort Compact 目前仅支持 bucket=-1 和批处理模式。

历史分区 Compaction​

你可以运行以下命令,为一段时间内没有收到任何新数据的分区提交 Compaction 作业。这些分区中的小文件将被全量压缩。

信息

该功能目前仅支持批处理模式。

针对单表​

适用于单张表。

  • Flink SQL
  • Flink Action Jar

运行以下 SQL:

-- history partition compact table
CALL sys.compact(`table` => 'default.T', partition_idle_time => '1 d')
<FLINK_HOME>/bin/flink run \
    -D execution.runtime-mode=batch \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    compact \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table <table-name> \
    --partition_idle_time <partition-idle-time> \
    [--partition <partition-name>] \
    [--compact_strategy <minor / full>] \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]] \
    [--table_conf <paimon-table-dynamic-conf> [--table_conf <paimon-table-dynamic-conf>] ...]

Historical Partition Compact 中新增了一个配置:

  • --partition_idle_time:用于对 partition_idle_time 时间内没有收到任何新数据的分区执行全量 Compaction,只有这些分区会被压缩。

针对数据库​

适用于多个数据库中的多张表。

  • Flink SQL
  • Flink Action Jar

运行以下 SQL:

-- history partition compact table
CALL sys.compact_database(
  including_databases => 'includingDatabases', 
  mode => 'mode', 
  including_tables => 'includingTables',
  excluding_tables => 'excludingTables',
  table_options => 'tableOptions',
  partition_idle_time => 'partition_idle_time'
);

示例:压缩数据库中各表的历史分区

-- history partition compact table
CALL sys.compact_database(
  includingDatabases => 'test_db', 
  mode => 'combined', 
  partition_idle_time => '1 d'
);
<FLINK_HOME>/bin/flink run \
    -D execution.runtime-mode=batch \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    compact_database \
    --warehouse <warehouse-path> \
    --including_databases <database-name|name-regular-expr> \
    --partition_idle_time <partition-idle-time> \
    [--including_tables <paimon-table-name|name-regular-expr>] \
    [--excluding_tables <paimon-table-name|name-regular-expr>] \
    [--mode <compact-mode>] \
    [--compact_strategy <minor / full>] \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]] \
    [--table_conf <paimon-table_conf> [--table_conf <paimon-table_conf> ...]]

示例:压缩数据库中各表的历史分区

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    compact_database \
    --warehouse s3:///path/to/warehouse \
    --including_databases test_db \
    --partition_idle_time 1d \
    --catalog_conf s3.endpoint=https://****.com \
    --catalog_conf s3.access-key=***** \
    --catalog_conf s3.secret-key=*****

在 Compaction 作业中跳过已过期的分区​

当分区过期配置为 partition.expiration-strategy = values-time 时,Compaction 作业可能会浪费资源去压缩那些已经过期、即将被删除的分区。

你可以设置 compaction.skip-expired-partitions = true,让 Compaction 作业跳过这些已过期的分区,避免对即将删除的数据做不必要的 Compaction 工作。

信息

该选项要求表上配置了 partition.expiration-strategy = values-time。它仅支持固定 bucket 或动态 bucket 模式的主键表。Unaware bucket(append-only)表以及 combined 模式下的 compact_database 不受支持——在这些情况下该选项会被静默忽略。

即使启用了该选项,在 Compaction 提交阶段,过期分区仍可能作为提交其余活跃分区所触发分区过期的副作用而被删除。这是预期行为——该选项避免了对过期分区不必要的 Compaction IO,但并不阻止这些分区被过期处理。

针对单表​

  • Flink SQL
  • Spark SQL
  • Flink Action Jar

运行以下 SQL:

-- skip expired partitions compact table
CALL sys.compact(`table` => 'default.T', options => 'compaction.skip-expired-partitions=true')

运行以下 SQL:

-- skip expired partitions compact table
CALL sys.compact(table => 'default.T', options => 'compaction.skip-expired-partitions=true')
<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    compact \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table <table-name> \
    --table_conf compaction.skip-expired-partitions=true \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]]

针对数据库​

  • Flink SQL
  • Spark SQL
  • Flink Action Jar

运行以下 SQL:

-- skip expired partitions compact database
CALL sys.compact_database(
  including_databases => 'includingDatabases',
  mode => 'divided',
  table_options => 'compaction.skip-expired-partitions=true'
)

运行以下 SQL:

-- skip expired partitions compact database
CALL sys.compact_database(
  including_databases => 'default',
  options => 'compaction.skip-expired-partitions=true'
)
<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    compact_database \
    --warehouse <warehouse-path> \
    --including_databases <database-name|name-regular-expr> \
    --mode divided \
    --table_conf compaction.skip-expired-partitions=true \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]]
