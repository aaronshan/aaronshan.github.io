调整 Bucket 数量

由于 bucket 总数对性能影响很大,Paimon 允许用户通过 ALTER TABLE 命令调整 bucket 数量, 并通过 INSERT OVERWRITE 重组数据布局,而无需重建表/分区。执行 overwrite 作业时, 框架会自动使用旧的 bucket 数量扫描数据,并按照当前的 bucket 数量对记录进行哈希。

调整覆盖(Rescale Overwrite)​

-- 调整 bucket 总数
ALTER TABLE table_identifier SET ('bucket' = '...');

-- 重组表/分区的数据布局
INSERT OVERWRITE table_identifier [PARTITION (part_spec)]
SELECT ... 
FROM table_identifier
[WHERE part_spec];

请注意:

  • ALTER TABLE 只修改表的元数据,不会重组或重新格式化现有数据。 重组现有数据必须通过 INSERT OVERWRITE 实现。
  • 调整 bucket 数量不会影响读取和正在运行的写入作业。
  • 一旦 bucket 数量改变,任何新调度的、向尚未重组的现有表/分区写入的 INSERT INTO 作业 都会抛出 TableException,报错信息类似: 
    Try to write table/partition ... with a new bucket num ..., 
    but the previous bucket num is ... Please switch to batch mode, 
    and perform INSERT OVERWRITE to rescale current data layout first.
  • 对于分区表,不同分区可以有不同的 bucket 数量。例如: 
    ALTER TABLE my_table SET ('bucket' = '4');
    INSERT OVERWRITE my_table PARTITION (dt = '2022-01-01')
    SELECT * FROM ...;

    ALTER TABLE my_table SET ('bucket' = '8');
    INSERT OVERWRITE my_table PARTITION (dt = '2022-01-02')
    SELECT * FROM ...;
  • 在 overwrite 期间,请确保没有其他作业在写同一张表/分区。

使用场景​

调整 bucket 有助于应对吞吐量的突增。假设有一个每日运行的流式 ETL 任务来同步交易数据, 该表的 DDL 和数据管道如下所示。

-- table DDL
CREATE TABLE verified_orders (
    trade_order_id BIGINT,
    item_id BIGINT,
    item_price DOUBLE,
    dt STRING,
    PRIMARY KEY (dt, trade_order_id, item_id) NOT ENFORCED 
) PARTITIONED BY (dt)
WITH (
    'bucket' = '16'
);

-- 例如来自一张 kafka 表
CREATE temporary TABLE raw_orders(
    trade_order_id BIGINT,
    item_id BIGINT,
    item_price BIGINT,
    gmt_create STRING,
    order_status STRING
) WITH (
    'connector' = 'kafka',
    'topic' = '...',
    'properties.bootstrap.servers' = '...',
    'format' = 'csv'
    ...
);

-- 以 bucket 数 = 16 流式写入
INSERT INTO verified_orders
SELECT trade_order_id,
       item_id,
       item_price,
       DATE_FORMAT(gmt_create, 'yyyy-MM-dd') AS dt
FROM raw_orders
WHERE order_status = 'verified';

该管道在过去几周一直运行良好。然而,最近数据量增长很快, 作业的延迟持续上升。为了提升数据时效性,用户可以:

  • 以 savepoint 暂停流式作业(参见 Suspended State 和 Stopping a Job Gracefully Creating a Final Savepoint) 
    $ ./bin/flink stop \
          --savepointPath /tmp/flink-savepoints \
          $JOB_ID
  • 增大 bucket 数量 
    -- 扩容
    ALTER TABLE verified_orders SET ('bucket' = '32');
  • 切换到批处理模式,overwrite 流式作业正在写入的当前分区 
    SET 'execution.runtime-mode' = 'batch';
    -- 假设今天是 2022-06-22
    -- 情形 1:没有更新历史分区的迟到事件,因此 overwrite 今天的分区即可
    INSERT OVERWRITE verified_orders PARTITION (dt = '2022-06-22')
    SELECT trade_order_id,
           item_id,
           item_price
    FROM verified_orders
    WHERE dt = '2022-06-22';

    -- 情形 2:存在更新历史分区的迟到事件,但范围不超过 3 天
    INSERT OVERWRITE verified_orders
    SELECT trade_order_id,
           item_id,
           item_price,
           dt
    FROM verified_orders
    WHERE dt IN ('2022-06-20', '2022-06-21', '2022-06-22');
  • overwrite 作业完成后,切换回流式模式。此时,可以从 savepoint 恢复流式作业,并连同 bucket 数量一起增大并行度 (参见从 savepoint 启动 SQL 作业) 
    SET 'execution.runtime-mode' = 'streaming';
    SET 'execution.savepoint.path' = <savepointPath>;

    INSERT INTO verified_orders
    SELECT trade_order_id,
         item_id,
         item_price,
         DATE_FORMAT(gmt_create, 'yyyy-MM-dd') AS dt
    FROM raw_orders
    WHERE order_status = 'verified';
