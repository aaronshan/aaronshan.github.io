管理分区

Paimon 提供了多种管理分区的方式,包括按不同策略过期历史分区,或将分区标记为完成(done)以通知下游应用该分区已写入完毕。

分区过期​

你可以在创建分区表时设置 partition.expiration-time。Paimon 流式 sink 会定期检查分区状态,并按时间删除过期的分区。

如何判断一个分区是否过期:你可以在创建分区表时设置 partition.expiration-strategy, 该策略决定如何提取分区时间,并将其与当前时间比较,判断存活时间 是否已超过 partition.expiration-time。过期策略支持的取值有:

  • values-time:该策略将从分区值中提取的时间与当前时间比较, 此策略为默认策略。
  • update-time:该策略将分区的最后更新时间与当前时间比较。 什么场景适合这个策略:
    • 你的分区值不是日期格式。
    • 你只想保留最近 n 天/月/年内有更新的数据。
    • 数据初始化时导入了大量历史数据。
信息

注意: 分区过期后是逻辑删除,最新的 snapshot 无法再查询到它的数据。但 文件系统中的文件不会被立即物理删除,何时删除取决于对应的 snapshot 何时过期。 参见过期 Snapshot。

另外,即使数据文件因 snapshot 过期而被物理删除,空的分区目录默认不会被移除。 要清理空目录,请在表上设置 'snapshot.clean-empty-directories' = 'true'。请注意, 在对象存储(如 OSS、S3)上这可能导致性能问题,因此该选项默认为 false。

单分区字段的示例:

values-time 策略。

CREATE TABLE t (...) PARTITIONED BY (dt) WITH (
    'partition.expiration-time' = '7 d',
    'partition.expiration-check-interval' = '1 d',
    'partition.timestamp-formatter' = 'yyyyMMdd'   -- this is required in `values-time` strategy.
);
-- 假设当前日期是 2024-07-09,那么 2024-07-02 之前的日期将过期。
insert into t values('pk', '2024-07-01');

-- 多分区字段的示例
CREATE TABLE t (...) PARTITIONED BY (other_key, dt) WITH (
    'partition.expiration-time' = '7 d',
    'partition.expiration-check-interval' = '1 d',
    'partition.timestamp-formatter' = 'yyyyMMdd',
    'partition.timestamp-pattern' = '$dt'
);

update-time 策略。

CREATE TABLE t (...) PARTITIONED BY (dt) WITH (
    'partition.expiration-time' = '7 d',
    'partition.expiration-check-interval' = '1 d',
    'partition.expiration-strategy' = 'update-time'
);

-- 该分区的最后更新时间是现在,因此不会过期。
insert into t values('pk', '2024-01-01');
-- 支持非日期格式的分区。
insert into t values('pk', 'par-1');

更多选项:

选项 默认值 类型 描述
partition.expiration-strategy
 values-time String 指定分区过期的过期策略。 可选值:
  • values-time:将从分区值中提取的时间与当前时间比较。
  • update-time:将分区的最后更新时间与当前时间比较。
    		•
    partition.expiration-check-interval
    		 1 h Duration 分区过期的检查间隔。
    partition.expiration-time
    		 (none) Duration 分区的过期时长。分区的存活时间超过该值时将被过期。分区时间从分区值中提取。
    partition.timestamp-formatter
    		 (none) String 用于从字符串格式化时间戳的格式器。它可以与 'partition.timestamp-pattern' 配合使用,按指定的值创建格式器。
    • 默认格式器为 'yyyy-MM-dd HH:mm:ss' 和 'yyyy-MM-dd'。
    • 支持多分区字段,如 '$year-$month-$day $hour:00:00'。
    • timestamp-formatter 兼容 Java 的 DateTimeFormatter。
    partition.timestamp-pattern
    		 (none) String 你可以指定一个 pattern 来从分区中获取时间戳。格式器 pattern 由 'partition.timestamp-formatter' 定义。
    • 默认从第一个字段读取。
    • 如果分区中的时间戳是一个名为 'dt' 的单字段,你可以使用 '$dt'。
    • 如果时间戳分布在 year、month、day、hour 多个字段中,你可以使用 '$year-$month-$day $hour:00:00'。
    • 如果时间戳位于 dt 和 hour 字段中,你可以使用 '$dt $hour:00:00'。
    end-input.check-partition-expire
    		 false Boolean 是否在批处理模式或有界流作业结束后检查分区过期。

    分区标记完成(Partition Mark Done)​

    你可以使用选项 'partition.mark-done-action' 配置当分区需要标记完成时执行的动作。

    • success-file:向目录中添加 '_success' 文件。
    • done-partition:向 metastore 中添加 'xxx.done' 分区。
    • mark-event:向 metastore 标记分区事件。
    • http-report:向远程 http 服务器上报分区标记完成。
    • custom:使用策略类创建自定义的分区标记策略。 这些动作可以同时配置:'done-partition,success-file,mark-event,custom'。

    Paimon 的分区标记完成既可以由流式写入触发,也可以由批处理写入触发。

    流式标记完成​

    你可以使用选项 'partition.idle-time-to-done' 设置分区空闲多久后标记完成。当一个分区 在该时长内没有新数据时,标记完成动作将被触发,表示数据已就绪。

    默认情况下,Flink 使用处理时间(process time)作为空闲时间来触发分区标记完成。你也可以使用 watermark 来触发分区标记完成。这会在数据延迟时使分区标记完成的时间更准确。你可以 通过设置 'partition.mark-done-action.mode' = 'watermark' 来启用。

    批处理标记完成​

    对于批处理模式,你可以通过设置 'partition.end-input-to-done'='true', 在输入结束时触发分区标记完成,本批次写入的所有分区都将被标记为完成。
