    同步表​

    通过在 Flink DataStream 作业中使用 MongoDBSyncTableAction,或直接通过 flink run,用户可以将 MongoDB 中的一个集合同步到一个 Paimon 表中。

    如需通过 flink run 使用该功能,执行以下 shell 命令。

    <FLINK_HOME>/bin/flink run \
        /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
        mongodb_sync_table \
        --warehouse <warehouse-path> \
        --database <database-name> \
        --table <table-name> \
        [--partition_keys <partition_keys>] \
        [--computed_column <'column-name=expr-name(args[, ...])'> [--computed_column ...]] \
        [--mongodb_conf <mongodb-cdc-source-conf> [--mongodb_conf <mongodb-cdc-source-conf> ...]] \
        [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]] \
        [--table_conf <paimon-table-sink-conf> [--table_conf <paimon-table-sink-conf> ...]]
    <ConfigTable html={mongodbSyncTableHtml} />

    以下几点需要注意:

    1. mongodb_conf 在 MongoDB CDC source 配置之上引入了 schema.start.mode 参数。schema.start.mode 提供两种模式:dynamic(默认)和 specified。 在 dynamic 模式下,MongoDB 的 Schema 信息会按一层进行解析,这构成了 Schema 变更演进的基础。 在 specified 模式下,将按照指定的规则进行同步。 可以通过配置 field.name 指定同步字段,并配置 parser.path 指定这些字段的 JSON 解析路径。 两者的区别在于,specified 模式要求用户明确指定要使用的字段,并基于这些字段创建映射表。 而 dynamic 模式则确保 Paimon 和 MongoDB 的顶层字段始终保持一致,无需关注具体字段。 当需要使用嵌套字段中的值时,需要对数据表做进一步处理。
    2. mongodb_conf 引入了 default.id.generation 参数,作为对 MongoDB CDC source 配置的增强。default.id.generation 设置为 true 和 false 时表现为两种不同的行为。 当 default.id.generation 设置为 true 时,MongoDB CDC source 遵循默认的 _id 生成策略,即剥离外层 $oid 嵌套,提供更简洁的标识符。该模式简化了 _id 的表示,使其更直接、更易用。 相反,当 default.id.generation 设置为 false 时,MongoDB CDC source 保留原始的 _id 结构,不做任何额外处理。该模式让用户可以灵活地使用 MongoDB 提供的原始 _id 格式,保留诸如 $oid 之类的嵌套元素。 两者之间的选择取决于用户的偏好:前者提供更干净、更简洁的 _id,后者则直接呈现 MongoDB 的 _id 结构。

    1. 同步的表必须将 _id 设置为主键。 这是因为 MongoDB 的变更事件在消息中记录的是更新前的内容。 因此,我们只能将其转换为 Flink 的 UPSERT Changelog 流。 UPSERT 流要求有唯一键,这就是我们必须将 _id 声明为主键的原因。 将其他列声明为主键是不可行的,因为删除操作只包含 _id 和分片键(sharding key),不包含其他键和值。

    2. MongoDB Change Streams 被设计为返回没有任何数据类型定义的简单 JSON 文档。这是因为 MongoDB 是面向文档的数据库,其核心特性之一是动态 Schema,文档可以包含不同的字段,字段的数据类型也可以是灵活的。因此,Change Streams 中缺少数据类型定义是为了保持这种灵活性和可扩展性。 出于这个原因,我们将同步 MongoDB 到 Paimon 的所有字段数据类型设置为 String,以解决无法获取数据类型的问题。

    如果你指定的 Paimon 表不存在,该 action 会自动创建这张表。其 Schema 将从 MongoDB 集合推导而来。

    示例 1:将集合同步到一个 Paimon 表中

    <FLINK_HOME>/bin/flink run \
        /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
        mongodb_sync_table \
        --warehouse hdfs:///path/to/warehouse \
        --database test_db \
        --table test_table \
        --partition_keys pt \
        --computed_column '_year=year(age)' \
        --mongodb_conf hosts=127.0.0.1:27017 \
        --mongodb_conf username=root \
        --mongodb_conf password=123456 \
        --mongodb_conf database=source_db \
        --mongodb_conf collection=source_table1 \
        --catalog_conf metastore=hive \
        --catalog_conf uri=thrift://hive-metastore:9083 \
        --table_conf bucket=4 \
        --table_conf changelog-producer=input \
        --table_conf sink.parallelism=4

    示例 2:按照指定的字段映射将集合同步到一个 Paimon 表中。

    <FLINK_HOME>/bin/flink run \
        /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
        mongodb_sync_table \
        --warehouse hdfs:///path/to/warehouse \
        --database test_db \
        --table test_table \
        --partition_keys pt \
        --mongodb_conf hosts=127.0.0.1:27017 \
        --mongodb_conf username=root \
        --mongodb_conf password=123456 \
        --mongodb_conf database=source_db \
        --mongodb_conf collection=source_table1 \
        --mongodb_conf schema.start.mode=specified \
        --mongodb_conf field.name=_id,name,description \
        --mongodb_conf parser.path=$._id,$.name,$.description \
        --catalog_conf metastore=hive \
        --catalog_conf uri=thrift://hive-metastore:9083 \
        --table_conf bucket=4 \
        --table_conf changelog-producer=input \
        --table_conf sink.parallelism=4

    同步数据库​

    通过在 Flink DataStream 作业中使用 MongoDBSyncDatabaseAction,或直接通过 flink run,用户可以将整个 MongoDB 数据库同步到一个 Paimon 数据库中。

    如需通过 flink run 使用该功能,执行以下 shell 命令。

    <FLINK_HOME>/bin/flink run \
        /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
        mongodb_sync_database \
        --warehouse <warehouse-path> \
        --database <database-name> \
        [--table_prefix <paimon-table-prefix>] \
        [--table_suffix <paimon-table-suffix>] \
        [--including_tables <mongodb-table-name|name-regular-expr>] \
        [--excluding_tables <mongodb-table-name|name-regular-expr>] \
        [--partition_keys <partition_keys>] \
        [--primary_keys <primary-keys>] \
        [--mongodb_conf <mongodb-cdc-source-conf> [--mongodb_conf <mongodb-cdc-source-conf> ...]] \
        [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]] \
        [--table_conf <paimon-table-sink-conf> [--table_conf <paimon-table-sink-conf> ...]]
    <ConfigTable html={mongodbSyncDatabaseHtml} />

    所有待同步的集合都需要将 _id 设置为主键。 对于每个待同步的 MongoDB 集合,如果对应的 Paimon 表不存在,该 action 会自动创建这张表。 其 Schema 将从所有指定的 MongoDB 集合推导而来。如果 Paimon 表已存在,则会将其 Schema 与所有指定的 MongoDB 集合的 Schema 进行对比。 任务启动后创建的任何 MongoDB 表都会被自动纳入同步。

    示例 1:同步整个数据库

    <FLINK_HOME>/bin/flink run \
        /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
        mongodb_sync_database \
        --warehouse hdfs:///path/to/warehouse \
        --database test_db \
        --mongodb_conf hosts=127.0.0.1:27017 \
        --mongodb_conf username=root \
        --mongodb_conf password=123456 \
        --mongodb_conf database=source_db \
        --catalog_conf metastore=hive \
        --catalog_conf uri=thrift://hive-metastore:9083 \
        --table_conf bucket=4 \
        --table_conf changelog-producer=input \
        --table_conf sink.parallelism=4

    示例 2:同步指定的表。

    <FLINK_HOME>/bin/flink run \
    --fromSavepoint savepointPath \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    mongodb_sync_database \
    --warehouse hdfs:///path/to/warehouse \
    --database test_db \
    --mongodb_conf hosts=127.0.0.1:27017 \
    --mongodb_conf username=root \
    --mongodb_conf password=123456 \
    --mongodb_conf database=source_db \
    --catalog_conf metastore=hive \
    --catalog_conf uri=thrift://hive-metastore:9083 \
    --table_conf bucket=4 \
    --including_tables 'product|user|address|order|custom'
