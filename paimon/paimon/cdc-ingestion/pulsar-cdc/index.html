Pulsar CDC

准备 Pulsar Bundled Jar​

flink-connector-pulsar-*.jar

支持的格式​

Flink 提供了多种 Pulsar CDC 格式:Canal Json、Debezium Json、Debezium Avro、Ogg Json、Maxwell Json 和普通 Json。 如果 Pulsar Topic 中的消息是使用变更数据捕获(CDC)工具从另一个数据库捕获的变更事件,那么你可以使用 Paimon Pulsar CDC,将解析出的 INSERT、UPDATE、DELETE 消息写入 Paimon 表。

格式 是否支持
Canal CDC True
Debezium CDC True
Maxwell CDC True
OGG CDC True
JSON True
信息

JSON 数据源可能会缺失部分信息。例如,Ogg 和 Maxwell 格式标准不包含字段 类型;当你将 JSON 数据源写入 Flink Pulsar sink 时,只会保留数据和行类型,其他信息会被丢弃。 同步作业会尽最大努力按如下方式处理该问题:

  1. 如果缺失字段类型,Paimon 默认使用 'STRING' 类型。
  2. 如果缺失数据库名或表名,则无法执行数据库同步,但仍可执行表同步。
  3. 如果缺失主键,作业可能会创建无主键表。在表同步时,你可以在提交作业时指定主键。

同步表​

通过在 Flink DataStream 作业中使用 PulsarSyncTableAction,或直接通过 flink run,用户可以将 Pulsar 某个 Topic 中的一张或多张表同步到一个 Paimon 表中。

如需通过 flink run 使用该功能,执行以下 shell 命令。

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    pulsar_sync_table \
    --warehouse <warehouse-path> \
    --database <database-name> \
    --table <table-name> \
    [--partition_keys <partition_keys>] \
    [--primary_keys <primary-keys>] \
    [--type_mapping to-string] \
    [--computed_column <'column-name=expr-name(args[, ...])'> [--computed_column ...]] \
    [--pulsar_conf <pulsar-source-conf> [--pulsar_conf <pulsar-source-conf> ...]] \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]] \
    [--table_conf <paimon-table-sink-conf> [--table_conf <paimon-table-sink-conf> ...]]
<ConfigTable html={pulsarSyncTableHtml} />

如果你指定的 Paimon 表不存在,该 action 会自动创建这张表。其 Schema 将从指定的 Pulsar Topic 中所有表推导而来,即从 Topic 中获取最早的非 DDL 数据并解析出 Schema。如果 Paimon 表已存在,则会将其 Schema 与指定的 Pulsar Topic 中所有表的 Schema 进行对比。

示例 1:

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    pulsar_sync_table \
    --warehouse hdfs:///path/to/warehouse \
    --database test_db \
    --table test_table \
    --partition_keys pt \
    --primary_keys pt,uid \
    --computed_column '_year=year(age)' \
    --pulsar_conf topic=order \
    --pulsar_conf value.format=canal-json \
    --pulsar_conf pulsar.client.serviceUrl=pulsar://127.0.0.1:6650 \
    --pulsar_conf pulsar.admin.adminUrl=http://127.0.0.1:8080 \
    --pulsar_conf pulsar.consumer.subscriptionName=paimon-tests \
    --catalog_conf metastore=hive \
    --catalog_conf uri=thrift://hive-metastore:9083 \
    --table_conf bucket=4 \
    --table_conf changelog-producer=input \
    --table_conf sink.parallelism=4

如果在启动同步作业时 Pulsar Topic 中没有消息,你必须在提交作业前手动创建表。你可以只定义分区键和主键, 其余列将由同步作业自动添加。

注意:在这种情况下你不应使用 --partition_keys 或 --primary_keys,因为这些键在建表时已定义, 无法修改。此外,如果你指定了计算列,还应该定义计算列所使用的所有参数列。

示例 2: 如果你想同步一张主键为 'id INT' 的表,并希望计算分区键 'part=date_format(create_time,yyyy-MM-dd)', 你可以先创建这样一张表(其他列可以省略):

CREATE TABLE test_db.test_table (
    id INT,                 -- primary key
    create_time TIMESTAMP,  -- the argument of computed column part
    part STRING,            -- partition key
    PRIMARY KEY (id, part) NOT ENFORCED
) PARTITIONED BY (part);

然后提交同步作业:

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    pulsar_sync_table \
    --warehouse hdfs:///path/to/warehouse \
    --database test_db \
    --table test_table \
    --computed_column 'part=date_format(create_time,yyyy-MM-dd)' \
    ... (other conf)

示例 3: 对于某些追加型数据(如日志数据),可以将其视为只有 INSERT 操作类型的特殊 CDC 数据,因此你可以使用 'format=json' 将这类数据同步到 Paimon 表。

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    kafka_sync_table \
    --warehouse hdfs:///path/to/warehouse \
    --database test_db \
    --table test_table \
    --partition_keys pt \
    --computed_column 'pt=date_format(event_tm, yyyyMMdd)' \
    --kafka_conf properties.bootstrap.servers=127.0.0.1:9020 \
    --kafka_conf topic=test_log \
    --kafka_conf properties.group.id=123456 \
    --kafka_conf value.format=json \
    --catalog_conf metastore=hive \
    --catalog_conf uri=thrift://hive-metastore:9083 \
    --table_conf sink.parallelism=4

同步数据库​

通过在 Flink DataStream 作业中使用 PulsarSyncDatabaseAction,或直接通过 flink run,用户可以将多个 Topic 或一个 Topic 同步到一个 Paimon 数据库中。

如需通过 flink run 使用该功能,执行以下 shell 命令。

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    pulsar_sync_database \
    --warehouse <warehouse-path> \
    --database <database-name> \
    [--table_prefix <paimon-table-prefix>] \
    [--table_suffix <paimon-table-suffix>] \
    [--including_tables <table-name|name-regular-expr>] \
    [--excluding_tables <table-name|name-regular-expr>] \
    [--type_mapping to-string] \
    [--partition_keys <partition_keys>] \
    [--primary_keys <primary-keys>] \
    [--pulsar_conf <pulsar-source-conf> [--pulsar_conf <pulsar-source-conf> ...]] \
    [--catalog_conf <paimon-catalog-conf> [--catalog_conf <paimon-catalog-conf> ...]] \
    [--table_conf <paimon-table-sink-conf> [--table_conf <paimon-table-sink-conf> ...]]
<ConfigTable html={pulsarSyncDatabaseHtml} />

只有带主键的表才会被同步。

该 action 会为所有表构建一个单一的合并 sink。对于每个待同步的 Pulsar Topic 中的表,如果 对应的 Paimon 表不存在,该 action 会自动创建这张表,其 Schema 将从指定的 Pulsar Topic 中所有表推导 而来。如果 Paimon 表已存在且其 Schema 与从 Pulsar 记录解析出的 Schema 不同,该 action 会尝试执行 Schema 演进。

示例

从单个 Pulsar Topic 同步到 Paimon 数据库。

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    pulsar_sync_database \
    --warehouse hdfs:///path/to/warehouse \
    --database test_db \
    --pulsar_conf topic=order \
    --pulsar_conf value.format=canal-json \
    --pulsar_conf pulsar.client.serviceUrl=pulsar://127.0.0.1:6650 \
    --pulsar_conf pulsar.admin.adminUrl=http://127.0.0.1:8080 \
    --pulsar_conf pulsar.consumer.subscriptionName=paimon-tests \
    --catalog_conf metastore=hive \
    --catalog_conf uri=thrift://hive-metastore:9083 \
    --table_conf bucket=4 \
    --table_conf changelog-producer=input \
    --table_conf sink.parallelism=4

从多个 Pulsar Topic 同步到 Paimon 数据库。

<FLINK_HOME>/bin/flink run \
    /path/to/paimon-flink-action-2.1-SNAPSHOT.jar \
    pulsar_sync_database \
    --warehouse hdfs:///path/to/warehouse \
    --database test_db \
    --pulsar_conf topic=order,logistic_order,user \
    --pulsar_conf value.format=canal-json \
    --pulsar_conf pulsar.client.serviceUrl=pulsar://127.0.0.1:6650 \
    --pulsar_conf pulsar.admin.adminUrl=http://127.0.0.1:8080 \
    --pulsar_conf pulsar.consumer.subscriptionName=paimon-tests \
    --catalog_conf metastore=hive \
    --catalog_conf uri=thrift://hive-metastore:9083 \
    --table_conf bucket=4 \
    --table_conf changelog-producer=input \
    --table_conf sink.parallelism=4

额外的 pulsar_config​

以下是一些构建 Flink Pulsar Source 时有用的选项,但 flink-pulsar-connector 文档中并未提供。它们是:

键 默认值 类型 说明
value.format (none) String 定义 value 数据编码的格式标识。
topic (none) String 读取数据的 Topic 名称。也支持用分号分隔的 Topic 列表, 如 'topic-1;topic-2'。注意,"topic-pattern" 和 "topic" 只能指定其中一个。
topic-pattern (none) String 用于匹配读取 Topic 名称的正则表达式。作业开始运行时,消费者将订阅所有名称匹配 该正则表达式的 Topic。注意,"topic-pattern" 和 "topic" 只能指定其中一个。
pulsar.startCursor.fromMessageId EARLIEST String 使用单条消息的唯一标识来定位起始位置。常见格式是三元组 '<long>ledgerId,<long>entryId,<int>partitionIndex'。特殊情况下,可以设置为 EARLIEST(-1, -1, -1)或 LATEST(Long.MAX_VALUE, Long.MAX_VALUE, -1)。
pulsar.startCursor.fromPublishTime (none) Long 使用消息的发布时间定位起始位置。
pulsar.startCursor.fromMessageIdInclusive true Boolean 是否包含给定的 message id。该选项仅在 message id 不是 EARLIEST 或 LATEST 时生效。
pulsar.stopCursor.atMessageId (none) String 当 message id 等于或大于指定的 message id 时停止消费。等于 指定 message id 的消息不会被消费。常见格式是三元组 '<long>ledgerId,<long>entryId,<int>partitionIndex'。 特殊情况下,可以设置为 LATEST(Long.MAX_VALUE, Long.MAX_VALUE, -1)。
pulsar.stopCursor.afterMessageId (none) String 当 message id 大于指定的 message id 时停止消费。等于 指定 message id 的消息会被消费。常见格式是三元组 '<long>ledgerId,<long>entryId,<int>partitionIndex'。 特殊情况下,可以设置为 LATEST(Long.MAX_VALUE, Long.MAX_VALUE, -1)。
pulsar.stopCursor.atEventTime (none) Long 当消息的事件时间大于或等于指定时间戳时停止消费。 事件时间等于指定时间戳的消息不会被消费。
pulsar.stopCursor.afterEventTime (none) Long 当消息的事件时间大于指定时间戳时停止消费。 事件时间等于指定时间戳的消息会被消费。
pulsar.source.unbounded true Boolean 用于指定流是否有界。
schema.registry.url (none) String 当配置 "value.format=debezium-avro" 时,需要使用 Confluence schema registry 模型进行 Apache Avro 序列化,此时你需要提供 schema registry URL。
