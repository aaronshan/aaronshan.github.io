Full-Text 索引

Full-Text 索引让 Paimon 通过 Global Index 框架对字符串列执行 top-k 文本 检索。索引类型为 full-text。Paimon 侧的集成模块是 paimon-full-text, 底层由独立的 paimon-full-text-index 原生库支撑。

搜索 API 把表列名与查询分开传入。查询本身是 paimon-full-text-index 接受的 JSON 字符串。

全文索引由原生引擎进行评分,可以直接使用,也可以在 Hybrid Search 中与向量路由组合使用。

构建 Full-Text 索引​

在 STRING、CHAR 或 VARCHAR 列上构建全文索引。原生文本索引会跳过 null 值,而 row-id 覆盖范围仍由 Paimon 跟踪。

  • SQL
  • Python SDK
CALL sys.create_global_index(
    table => 'db.my_table',
    index_column => 'content',
    index_type => 'full-text'
);

使用 ngram 分词器处理短字符片段或类子串查找:

CALL sys.create_global_index(
    table => 'db.my_table',
    index_column => 'content',
    index_type => 'full-text',
    options => 'full-text.tokenizer=ngram,full-text.ngram.min-gram=2,full-text.ngram.max-gram=3'
);

使用 jieba 进行中文分词:

CALL sys.create_global_index(
    table => 'db.my_table',
    index_column => 'content',
    index_type => 'full-text',
    options => 'full-text.tokenizer=jieba'
);
table = catalog.get_table("db.my_table")

added_files = table.create_global_index(
    "content",
    index_type="full-text",
)
print(added_files)

使用 ngram 分词器处理短字符片段或类子串查找:

added_files = table.create_global_index(
    "content",
    index_type="full-text",
    options={
        "full-text.tokenizer": "ngram",
        "full-text.ngram.min-gram": "2",
        "full-text.ngram.max-gram": "3",
    },
)
print(added_files)

在构建或查询全文索引之前,先安装 PyPaimon 的 full-text 扩展:

pip install 'pypaimon[full-text]'

所有原生全文配置项在 Paimon 中都必须使用公开的 full-text. 前缀。 Paimon 会剥掉一次该前缀,把剩余的键传给原生库。例如,应设置 full-text.tokenizer=ngram,而不是 tokenizer=ngram。

支持的全文索引配置项:

配置项默认值说明
full-text.tokenizerdefault原生全文索引使用的分词器。支持的值为 default、simple、whitespace、raw、ngram 和 jieba。
full-text.ngram.min-gram3ngram 分词器的最小 gram 长度。
full-text.ngram.max-gram3ngram 分词器的最大 gram 长度。
full-text.ngram.prefix-onlyfalsengram 分词器是否只产出前缀 ngram。
full-text.jieba.search-modetruejieba 分词器是否使用搜索模式。
full-text.jieba.ordinal-positiontruejieba 分词器是否使用序号位置。
full-text.lower-casetrue可配置的分词器是否将产出的词项转为小写。
full-text.max-token-length40可配置的分词器保留的最大词项长度。
full-text.ascii-foldingtrue是否将非 ASCII 拉丁字符归一化为 ASCII。
full-text.stemtrue是否应用词干提取(stemming)。
full-text.languageenglish词干提取和内置停用词过滤器使用的语言。
full-text.remove-stop-wordstrue是否移除所配置语言的内置停用词。
full-text.stop-words空以分号分隔的自定义停用词。需要 full-text.remove-stop-words=true。
full-text.with-positiontrue是否存储词项位置。短语查询需要保持启用。

默认分词器使用英文全文默认值:小写化、词干提取、停用词移除、ASCII 归一化、最大词项长度 40,并存储位置。仅在不需要短语搜索时才设置 full-text.with-position=false。

分词器设置存储在全局索引文件的元数据中。已有的索引文件会保留其构建时 使用的分词器配置,即使后续的索引构建使用了不同的配置。

删除 Full-Text 索引​

  • SQL
  • Python SDK
CALL sys.drop_global_index(
    table => 'db.my_table',
    index_column => 'content',
    index_type => 'full-text'
);
table = catalog.get_table("db.my_table")

dropped_files = table.drop_global_index(
    "content",
    index_type="full-text",
)
print(dropped_files)

你也可以将删除限制在指定分区,或只统计匹配的文件而不提交:

matched_files = table.drop_global_index(
    "content",
    index_type="full-text",
    partitions=[{"dt": "2026-06-18"}, {"dt": "2026-06-19"}],
    dry_run=True,
)
print(matched_files)

全文搜索​

Spark SQL 使用 full_text_search(table_name, column, query, limit) 表值 函数。column 参数是要搜索的 Paimon 表列。query 参数作为 JSON 字符串 传给原生全文读取器。

  • Spark SQL
  • Java API
  • Python SDK
-- Search for the top 10 rows matching any query term.
SELECT id, content, __paimon_search_score
FROM full_text_search(
    'my_table',
    'content',
    '{"match":{"query":"paimon lake format"}}',
    10
);

-- Require all query terms.
SELECT id, content, __paimon_search_score
FROM full_text_search(
    'my_table',
    'content',
    '{"match":{"query":"paimon lake format","operator":"And"}}',
    10
);

-- Phrase query. The index must be built with full-text.with-position=true.
SELECT id, content, __paimon_search_score
FROM full_text_search(
    'my_table',
    'content',
    '{"match_phrase":{"query":"paimon lake"}}',
    10
);

Spark 通过 __paimon_search_score 元数据列暴露评分。

Table table = catalog.getTable(identifier);

GlobalIndexResult result =
        table.newFullTextSearchBuilder()
                .withQuery("content", "{\"match\":{\"query\":\"paimon lake\"}}")
                .withLimit(10)
                .executeLocal();

ReadBuilder readBuilder = table.newReadBuilder();
TableScan.Plan plan = readBuilder.newScan().withGlobalIndexResult(result).plan();
try (RecordReader<InternalRow> reader = readBuilder.newRead().createReader(plan)) {
    reader.forEachRemaining(row -> System.out.println(row));
}
table = catalog.get_table("db.my_table")

result = (
    table.new_full_text_search_builder()
    .with_query("content", '{"match":{"query":"paimon lake"}}')
    .with_limit(10)
    .execute_local()
)

read_builder = table.new_read_builder()
plan = read_builder.new_scan().with_global_index_result(result).plan()
pa_table = read_builder.new_read().to_arrow(plan.splits())
print(pa_table)

默认情况下,full-text-index.search-mode=fast 只搜索已索引的 row 区间。 当 full-text-index.search-mode 为 full 或 detail 时,Paimon 还会 通过读取原始行并为被搜索列构建临时原生全文索引,来覆盖未索引的 row 区间。

查询 DSL​

查询 DSL 是带有一个顶层查询类型的 JSON 对象。下面的示例可在 Spark SQL、 Java、Python 或混合检索路由中作为 JSON 字符串使用。

Match​

match 用于常规词项搜索。默认操作符为 Or。

{
  "match": {
    "query": "paimon lake format",
    "operator": "And"
  }
}
字段是否必填默认值说明
query是N/A查询文本。
operator否Or查询词项的组合方式。支持的值为 Or 和 And。
boost否1.0该查询的评分乘数。
fuzziness否0模糊匹配的编辑距离。使用整数或 auto。
max_expansions否50最大模糊扩展数。也接受 maxExpansions。
prefix_length否0必须精确匹配的前导字符数。也接受 prefixLength。

Phrase​

match_phrase 用于有顺序的词项。短语搜索需要位置信息,因此索引必须以 full-text.with-position=true 构建。

{
  "match_phrase": {
    "query": "paimon lake",
    "slop": 1
  }
}
字段是否必填默认值说明
query是N/A短语文本。
slop否0匹配短语时允许的位置移动数。

Boolean​

boolean 用于组合嵌套查询。

{
  "boolean": {
    "must": [
      {"match": {"query": "paimon"}}
    ],
    "should": [
      {"match_phrase": {"query": "lake format"}}
    ],
    "must_not": [
      {"match": {"query": "vector"}}
    ]
  }
}
字段是否必填默认值说明
must否空必须匹配的查询。
should否空可以匹配并贡献评分的查询。
must_not否空用于排除匹配行的查询。

原生读取器还接受由 occurrence/query 对组成的 queries 数组,例如 ["Must", {"match": {"query": "paimon"}}]。

Multi Match​

multi_match 在一次查询中搜索多个原生文本字段。

{
  "multi_match": {
    "query": "paimon search",
    "columns": ["title", "body"],
    "boosts": [2.0, 1.0]
  }
}

当前 Paimon 全局索引的构建路径为一个表列创建一个全文索引。要搜索多个 Paimon 表列,请为每一列创建一个全文索引,并用 Hybrid Search 组合它们。multi_match 适用于由写入了多个原生文本字段的适配器所提供的 原生多字段索引。

Boost 降权​

使用 boost 降低同时匹配负面查询的行的排名。

{
  "boost": {
    "positive": {
      "match": {
        "query": "paimon"
      }
    },
    "negative": {
      "match": {
        "query": "vector"
      }
    },
    "negative_boost": 0.3
  }
}
字段是否必填默认值说明
positive是N/A贡献主要评分的查询。
negative是N/A用于降低匹配行排名的查询。
negative_boost否0.5应用于同时匹配 negative 的行的正数乘数。

注意事项​

  • 表列通过 full_text_search(..., column, query, limit)、 withQuery(column, query) 或 with_query(column, query) 提供。
  • JSON 查询内部的可选 column 字段属于原生 paimon-full-text-index DSL。大多数 Paimon 用户应省略它,改为通过 Paimon API 传入 Paimon 表列。
  • 查询字符串必须是原生全文读取器能够理解的有效 JSON。无效的查询语法 会在搜索时报错。
  • limit 必须为正数。全文结果按评分顺序返回,可由混合检索的 ranker 与向量结果合并。
