混合检索

混合检索(Hybrid Search)在一次请求中查询多个带评分的路由,并在读取表行之前对 结果进行排序。路由可以是向量搜索路由或全文搜索路由,因此混合检索可以组合多个 向量索引、多个全文索引,或向量与全文索引的混合。当一张表为同一条记录存储了多 种可搜索的表示时(如标题 Embedding、正文 Embedding 和内容文本),这尤其有用。

在运行混合检索之前,请为查询用到的每个向量列或文本列创建全局索引:

CALL sys.create_global_index(
    table => 'db.my_table',
    index_column => 'title_embedding',
    index_type => 'ivf-pq',
    options => 'ivf-pq.distance.metric=cosine,ivf-pq.nlist=256,ivf-pq.pq.m=16'
);

CALL sys.create_global_index(
    table => 'db.my_table',
    index_column => 'body_embedding',
    index_type => 'ivf-pq',
    options => 'ivf-pq.distance.metric=cosine,ivf-pq.nlist=256,ivf-pq.pq.m=16'
);

CALL sys.create_global_index(
    table => 'db.my_table',
    index_column => 'content',
    index_type => 'full-text'
);

在 Spark SQL 中,使用 hybrid_search(table_name, vector_routes, full_text_routes, limit[, ranker]) 表值函数。第四个参数是最终返回的排序结果数。可选的第五个参数选择 ranker。 支持的 ranker 有 rrf、weighted_score 和 mrr;默认为 rrf。

各 ranker 组合路由评分的方式不同:

Ranker适用场景说明
rrf组合评分尺度不同的路由倒数排名融合(Reciprocal rank fusion)使用各路由内部的排名顺序,因此向量和全文评分无需归一化。
weighted_score按归一化评分(而非仅按排名)为路由加权先把每条路由的评分做 min-max 归一化到 [0, 1],再按路由 weight 加权求和,因此由各路由的权重(而非原始评分大小)控制其影响力。暴露的 __paimon_search_score 因此是单次查询内取值于 [0, 权重之和] 的相对值,而不是原始的相似度或 BM25 评分。
mrr强调各路由中排名靠前的命中加权倒数排名融合,对每条路由返回的每一行累加 weight / rank,其中 rank 从 1 开始。

第二个参数是由 named_struct 创建的向量路由配置数组:

字段是否必填默认值说明
field 或 vector_column是N/A要搜索的向量列。
query_vector是N/A该路由的查询向量。
limit否最终 limit排序之前从该向量列取回的 Top K 结果数。
weight否1.0结果排序时该路由的权重。
options否空 map路由专属的向量搜索配置项,如 ivf.nprobe 和 diskann.l_search。

第三个参数是由 named_struct 创建的全文路由配置数组:

字段是否必填默认值说明
column是N/A要搜索的文本列。
query是N/A该路由的全文查询字符串。
limit否最终 limit排序之前从该文本列取回的 Top K 结果数。
weight否1.0结果排序时该路由的权重。
options否空 map为将来全文搜索配置项保留。当前只接受空 map。

在每个路由数组内部,每个 named_struct 应使用相同的字段,因为 Spark 要求 数组元素具有相同的 struct 类型。全文路由的 options 目前是保留字段;当 需要保持 struct 类型一致时,请传 map()。

当每条路由都应贡献足够的候选用于排序时,把路由的 limit 设为大于最终 limit 的值。例如,最终 limit 为 10 时,路由 limit 取 50 或 100 可以让 ranker 有更多的候选可合并。

  • Java API

向量路由和全文路由可以一起搜索:

SELECT id, __paimon_search_score
FROM hybrid_search(
  'my_table',
  array(
    named_struct(
      'field', 'title_embedding',
      'query_vector', array(1.0f, 0.0f, 0.0f),
      'limit', 50,
      'weight', 2.0f,
      'options', map('ivf.nprobe', '32'))),
  array(
    named_struct(
      'column', 'content',
      'query', '{"match":{"query":"paimon search"}}',
      'limit', 50,
      'weight', 1.0f,
      'options', map())),
  10,
  'rrf');

要在不使用全文路由的情况下搜索两个向量索引,第三个参数传 array():

SELECT id, __paimon_search_score
FROM hybrid_search(
  'my_table',
  array(
    named_struct(
      'field', 'title_embedding',
      'query_vector', array(1.0f, 0.0f, 0.0f),
      'limit', 50,
      'weight', 2.0f,
      'options', map('ivf.nprobe', '32')),
    named_struct(
      'field', 'body_embedding',
      'query_vector', array(0.0f, 1.0f, 0.0f),
      'limit', 50,
      'weight', 1.0f,
      'options', map('ivf.nprobe', '32'))),
  array(),
  10,
  'weighted_score');

需要加权倒数排名融合时使用 mrr:

SELECT id, __paimon_search_score
FROM hybrid_search(
  'my_table',
  array(
    named_struct(
      'field', 'title_embedding',
      'query_vector', array(1.0f, 0.0f, 0.0f),
      'limit', 50,
      'weight', 2.0f,
      'options', map('ivf.nprobe', '32'))),
  array(),
  10,
  'mrr');

Spark SQL 会添加 __paimon_search_score 列来暴露排序后的评分。

Table table = catalog.getTable(identifier);

HybridSearchBuilder searchBuilder =
        table.newHybridSearchBuilder()
                .addVectorRoute(
                        "title_embedding",
                        new float[] {1.0f, 0.0f, 0.0f},
                        50,
                        2.0f,
                        java.util.Collections.singletonMap("ivf.nprobe", "32"))
                .addFullTextRoute(
                        "content",
                        "{\"match\":{\"query\":\"paimon search\"}}",
                        50,
                        1.0f,
                        java.util.Collections.emptyMap())
                .withLimit(10)
                .withRrfRanker();
GlobalIndexResult result = searchBuilder.executeLocal();

ReadBuilder readBuilder = table.newReadBuilder();
TableScan.Plan plan = readBuilder.newScan().withGlobalIndexResult(result).plan();
try (RecordReader<InternalRow> reader = readBuilder.newRead().createReader(plan)) {
    reader.forEachRemaining(row -> {
        System.out.println("id=" + row.getInt(0));
    });
}

GlobalIndexResult vectorOnlyResult =

对于 Java,使用 Table.newHybridSearchBuilder() 直接配置路由、最终 limit 和 ranker。VectorSearch 和 HybridSearch 是内部的下推表示。

table = catalog.get_table("db.my_table")

result = (
    table.new_hybrid_search_builder()
    .add_vector_route(
        "title_embedding",
        [1.0, 0.0, 0.0],
        limit=50,
        weight=2.0,
        options={"ivf.nprobe": "32"},
    )
    .add_full_text_route(
        "content",
        '{"match":{"query":"paimon search"}}',
        limit=50,
        weight=1.0,
    )
    .with_limit(10)
    .with_rrf_ranker()
    .execute_local()
)

read_builder = table.new_read_builder()
scan = read_builder.new_scan().with_global_index_result(result)
plan = scan.plan()
table_read = read_builder.new_read()
pa_table = table_read.to_arrow(plan.splits())
print(pa_table)
