主键表

让我们通过一个简单的示例,了解如何在 Flink 和 Spark 中使用 Iceberg connector 查询 Paimon 表。 在尝试本示例之前,请确保你的计算引擎已经支持 Iceberg。 如果尚未配置 Iceberg,请参阅 Iceberg 文档:

  • Flink:Preparation when using Flink SQL Client
  • Spark:Using Iceberg in Spark 3
  • Flink SQL
  • Spark SQL
CREATE CATALOG paimon_catalog WITH (
    'type' = 'paimon',
    'warehouse' = '<path-to-warehouse>'
);

CREATE TABLE paimon_catalog.`default`.orders (
    order_id BIGINT,
    status STRING,
    payment DOUBLE,
    PRIMARY KEY (order_id) NOT ENFORCED
) WITH (
    'metadata.iceberg.storage' = 'hadoop-catalog',
    'compaction.optimization-interval' = '1ms' -- 注意:此选项仅用于测试,更多信息请参见下文"时效性"部分
);

INSERT INTO paimon_catalog.`default`.orders VALUES (1, 'SUBMITTED', CAST(NULL AS DOUBLE)), (2, 'COMPLETED', 200.0), (3, 'SUBMITTED', CAST(NULL AS DOUBLE));

CREATE CATALOG iceberg_catalog WITH (
    'type' = 'iceberg',
    'catalog-type' = 'hadoop',
    'warehouse' = '<path-to-warehouse>/iceberg',
    'cache-enabled' = 'false' -- 禁用 iceberg catalog 缓存以便快速看到结果
);

SELECT * FROM iceberg_catalog.`default`.orders WHERE status = 'COMPLETED';
/*
+----+----------------------+--------------------------------+--------------------------------+
| op |             order_id |                         status |                        payment |
+----+----------------------+--------------------------------+--------------------------------+
| +I |                    2 |                      COMPLETED |                          200.0 |
+----+----------------------+--------------------------------+--------------------------------+
*/

INSERT INTO paimon_catalog.`default`.orders VALUES (1, 'COMPLETED', 100.0);

SELECT * FROM iceberg_catalog.`default`.orders WHERE status = 'COMPLETED';
/*
+----+----------------------+--------------------------------+--------------------------------+
| op |             order_id |                         status |                        payment |
+----+----------------------+--------------------------------+--------------------------------+
| +I |                    1 |                      COMPLETED |                          100.0 |
| +I |                    2 |                      COMPLETED |                          200.0 |
+----+----------------------+--------------------------------+--------------------------------+
*/

使用以下命令行启动 spark-sql。

spark-sql --jars <path-to-paimon-jar> \
    --conf spark.sql.catalog.paimon_catalog=org.apache.paimon.spark.SparkCatalog \
    --conf spark.sql.catalog.paimon_catalog.warehouse=<path-to-warehouse> \
    --packages org.apache.iceberg:iceberg-spark-runtime-<iceberg-version> \
    --conf spark.sql.catalog.iceberg_catalog=org.apache.iceberg.spark.SparkCatalog \
    --conf spark.sql.catalog.iceberg_catalog.type=hadoop \
    --conf spark.sql.catalog.iceberg_catalog.warehouse=<path-to-warehouse>/iceberg \
    --conf spark.sql.catalog.iceberg_catalog.cache-enabled=false \ # 禁用 iceberg catalog 缓存以便快速看到结果
    --conf spark.sql.extensions=org.apache.paimon.spark.extensions.PaimonSparkSessionExtensions,org.apache.iceberg.spark.extensions.IcebergSparkSessionExtensions

运行以下 Spark SQL 创建 Paimon 表、插入/更新数据,并使用 Iceberg catalog 查询。

CREATE TABLE paimon_catalog.`default`.orders (
    order_id BIGINT,
    status STRING,
    payment DOUBLE
) TBLPROPERTIES (
    'primary-key' = 'order_id',
    'metadata.iceberg.storage' = 'hadoop-catalog',
    'compaction.optimization-interval' = '1ms' -- 注意:此选项仅用于测试,更多信息请参见下文"时效性"部分
);

INSERT INTO paimon_catalog.`default`.orders VALUES (1, 'SUBMITTED', CAST(NULL AS DOUBLE)), (2, 'COMPLETED', 200.0), (3, 'SUBMITTED', CAST(NULL AS DOUBLE));

SELECT * FROM iceberg_catalog.`default`.orders WHERE status = 'COMPLETED';
/*
2       COMPLETED       200.0
*/

INSERT INTO paimon_catalog.`default`.orders VALUES (1, 'COMPLETED', 100.0);

SELECT * FROM iceberg_catalog.`default`.orders WHERE status = 'COMPLETED';
/*
2       COMPLETED       200.0
1       COMPLETED       100.0
*/

Paimon 主键表将数据文件组织为 LSM 树,因此查询前必须在内存中合并数据文件。 然而,Iceberg reader 无法合并数据文件,所以它们只能查询 LSM 树最高层的数据文件。 最高层的数据文件由全量 compaction 过程产生。 所以结论是,对于主键表,Iceberg reader 只能查询全量 compaction 之后的数据。

默认情况下,Paimon 不保证以怎样的频率执行全量 compaction。 你可以配置以下表选项,强制 Paimon 在若干次提交后执行全量 compaction。

选项默认值类型描述
compaction.optimization-interval
(none)Duration按时间间隔持续触发全量 compaction。作业启动后的第一次 compaction 始终是全量 compaction。
full-compaction.delta-commits
(none)Integer在若干次增量提交后持续触发全量 compaction。仅在 Flink 中实现。

注意,全量 compaction 是一个消耗资源的过程,因此该表选项的值不应设置得过小。 我们建议每小时执行一到两次全量 compaction。

Deletion Vector 支持​

Paimon 中的 Deletion Vectors 用于存储每个文件中被删除的记录。 在 deletion-vector 模式下,Paimon reader 可以在读取阶段直接过滤掉不需要的记录,而无需合并数据。 幸运的是,Iceberg 在 Version 3 中已经支持 deletion vectors。 这意味着如果 Iceberg reader 能够识别 Paimon 的 deletion vectors,即使不具备合并数据文件的能力,它也能读取 Paimon 的全部数据。 通过将 Paimon 的 deletion vectors 同步到 Iceberg,Iceberg reader 和 Paimon reader 可以实现真正的实时同步。

满足以下条件时,Paimon 会为 Iceberg 构建 deletion vectors 元数据:

  • 'deletion-vectors.enabled' 和 'deletion-vectors.bitmap64' 都应设置为 true。因为 Paimon 中只有 64 位 bitmap 实现的 deletion vector 与 Iceberg 兼容。
  • 'metadata.iceberg.format-version'(默认值为 2)应设置为 3。因为 Iceberg 仅在 V3 中支持 deletion vector。
  • Iceberg 版本应为 1.8.0+。
  • JDK 版本应为 11+。Iceberg 自 1.7.0 版本起已停止支持 JDK 8。

示例如下:

  • Flink SQL
-- flink version: 1.20.1

CREATE CATALOG paimon_catalog WITH (
    'type' = 'paimon',
    'warehouse' = '<path-to-warehouse>'
);

-- 创建一张带主键并启用 deletion vector 的 Paimon 表
CREATE TABLE paimon_catalog.`default`.T
(
    pt  INT
    ,k  INT
    ,v  INT
    ,PRIMARY KEY (pt, k) NOT ENFORCED
)PARTITIONED BY (pt)
WITH (
    'metadata.iceberg.storage' = 'hadoop-catalog'
    ,'metadata.iceberg.format-version' = '3'
    ,'deletion-vectors.enabled' = 'true'
    ,'deletion-vectors.bitmap64' = 'true'
);

INSERT INTO paimon_catalog.`default`.T
VALUES (1, 9, 90), (1, 10, 100), (1, 11, 110), (2, 20, 200)
;

-- iceberg version: 1.8.1
CREATE CATALOG iceberg_catalog WITH (
    'type' = 'iceberg',
    'catalog-type' = 'hadoop',
    'warehouse' = '<path-to-warehouse>/iceberg',
    'cache-enabled' = 'false' -- 禁用 iceberg catalog 缓存以便快速看到结果
);

SELECT * FROM iceberg_catalog.`default`.T;
/*
+------------+------------+------------+
|         pt |          k |          v |
+------------+------------+------------+
|          2 |         20 |        200 |
|          1 |          9 |         90 |
|          1 |         10 |        100 |
|          1 |         11 |        110 |
+------------+------------+------------+
*/

-- 再次插入一些数据,这会生成 deletion vectors
INSERT INTO paimon_catalog.`default`.T
VALUES (1, 10, 101), (2, 20, 201), (1, 12, 121)
;

-- 在 Paimon 中查询 deletion-vector 索引
SELECT * FROM paimon_catalog.`default`.`T$table_indexes` WHERE index_type='DELETION_VECTORS';
/*
+------------+-----------+-------------------+------------------------   -----+------------+------------+--------------------------------+
|  partition |    bucket |        index_type |                      file_name |  file_size |  row_count |                      dv_ranges |
+------------+-----------+-------------------+------------------------   -----+------------+------------+--------------------------------+
|        {1} |         0 |  DELETION_VECTORS | index-4ae44c5d-2fc6-40b0-9ff0~ |         43 |          1 | [(data-968fdf3a-2f44-41df-89b~ |
+------------+-----------+-------------------+------------------------   -----+------------+------------+--------------------------------+
*/

-- 在 Iceberg 中查询,更新被成功读取
SELECT * FROM iceberg_catalog.`default`.T;
/*
+------------+------------+------------+
|         pt |          k |          v |
+------------+------------+------------+
|          1 |          9 |         90 |
|          1 |         11 |        110 |
|          2 |         20 |        201 |
|          1 |         10 |        101 |
|          1 |         12 |        121 |
+------------+------------+------------+
*/

信息

注 1:如有必要,请将 deletion vector 的实现升级为 64 位 bitmap。

如果你的 Paimon 表已经处于 deletion-vector 模式,但 deletion vector 使用的是 32 位 bitmap, 而你希望将 deletion-vector 元数据同步到 Iceberg,则需要将 deletion vector 的实现升级为 64 位 bitmap。 你可以按照以下步骤升级到 64 位 deletion-vector:

  1. 停止 Paimon 表的所有写入作业。
  2. 对 Paimon 表执行一次全量 compaction。
  3. 运行 ALTER TABLE tableName SET ('deletion-vectors.bitmap64' = 'true') 升级到 64 位 deletion vector。
  4. 重启写入作业。如果满足上述所有条件,deletion vector 元数据将同步到 Iceberg。
信息

注 2:如有必要,请将 Iceberg 的 format version 升级到 3。

你可以通过设置 'metadata.iceberg.format-version' = '3' 将 Iceberg 的 format version 从 2 升级到 3。 这将在不使用基础元数据的情况下重新创建 Iceberg 元数据。
