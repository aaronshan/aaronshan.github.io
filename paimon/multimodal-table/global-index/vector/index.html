Vector 索引

Vector 索引为向量相似度搜索场景提供近似最近邻(ANN)搜索,适用于推荐系统、 图片检索和 RAG(Retrieval Augmented Generation)等应用。

支持的向量索引类型:

索引类型说明
ivf-flat使用原始向量存储的 IVF 索引。
ivf-pq使用乘积量化(product quantization)的 IVF 索引。
ivf-sq使用 8 位标量量化残差的 IVF 索引。
ivf-rq使用旋转残差量化的 IVF 索引。
diskannpaimon-vindex DiskANN 索引,基于图遍历并持久化重排向量。

根据你需要的取舍选择索引类型:

索引类型适用场景
ivf-flat在存储和内存可接受时,IVF 家族中召回率最高。
ivf-pq在可接受更强量化损失时,IVF 文件最小。
ivf-sq每个向量维度仅占一个字节,紧凑索引吞吐高。
ivf-rq在可接受额外扫描开销时,紧凑 IVF 中召回率更高。
diskann高召回的不可变集合,从本地 SSD 或完整的本地缓存提供查询。

关于索引选型指导、存储架构和原生 API 细节,参见 paimon-vindex 文档。

升级 paimon-vindex 索引到 0.3.0

paimon-vindex 0.3.0 无法读取 0.2.x 写入的实验性 ivf-hnsw-flat 和 ivf-hnsw-sq 文件。在移除旧运行时之前,请把这些索引重建为 ivf-flat、 ivf-pq、ivf-sq、ivf-rq 或 diskann。在升级被确认接受之前,保留源 向量或一份兼容 0.2 的索引副本。

构建 Vector 索引​

  • SQL
  • Python SDK
-- Create IVF-PQ vector index on 'embedding' column
CALL sys.create_global_index(
    table => 'db.my_table',
    index_column => 'embedding',
    index_type => 'ivf-pq',
    options => 'ivf-pq.distance.metric=cosine,ivf-pq.nlist=256,ivf-pq.pq.code-ratio=0.0625'
);

-- Create a paimon-vindex DiskANN vector index
CALL sys.create_global_index(
    table => 'db.my_table',
    index_column => 'embedding',
    index_type => 'diskann',
    options => 'diskann.dimension=768,diskann.distance.metric=l2,diskann.build-preset=balanced'
);
table = catalog.get_table("db.my_table")

# Create IVF-PQ vector index on 'embedding' column.
added_files = table.create_global_index(
    "embedding",
    index_type="ivf-pq",
    options={
        "ivf-pq.dimension": "768",
        "ivf-pq.distance.metric": "cosine",
        "ivf-pq.nlist": "256",
        "ivf-pq.pq.code-ratio": "0.0625",
    },
)
print(added_files)

你也可以只构建指定分区,或调整非有序全局索引使用的 row-id 分片大小:

added_files = table.create_global_index(
    "embedding",
    index_type="ivf-flat",
    partitions=[{"dt": "2026-06-18"}, {"dt": "2026-06-19"}],
    options={
        "ivf-flat.dimension": "768",
        "global-index.row-count-per-shard": "100000",
    },
)
print(added_files)

PyPaimon 向量索引构建支持 paimon-vindex 0.4.0 的标识符 ivf-flat、ivf-pq、 ivf-sq、ivf-rq 和 diskann。在 Python 中构建或查询 paimon-vindex 索引之前, 请先安装 paimon-vindex==0.4.0 或 pypaimon[vindex]。

对于 ARRAY<FLOAT> 向量列,使用 <index-type>.dimension 为 paimon-vindex 索引 指定向量维度。对于 VECTOR<FLOAT> 列,Paimon 使用列类型中的维度。

删除 Vector 索引​

  • SQL
  • Python SDK
CALL sys.drop_global_index(
    table => 'db.my_table',
    index_column => 'embedding',
    index_type => 'ivf-pq'
);
table = catalog.get_table("db.my_table")

dropped_files = table.drop_global_index("embedding", index_type="ivf-pq")
print(dropped_files)

你也可以将删除限制在指定分区,或只统计匹配的文件而不提交:

matched_files = table.drop_global_index(
    "embedding",
    index_type="ivf-pq",
    partitions=[{"dt": "2026-06-18"}, {"dt": "2026-06-19"}],
    dry_run=True,
)
print(matched_files)

支持的 paimon-vindex 配置项:

配置项默认值说明
<index-type>.dimension128ARRAY<FLOAT> 列的向量维度。对 VECTOR<FLOAT> 列忽略。
<index-type>.distance.metricinner_product距离度量。支持的值:l2、cosine、inner_product。
<index-type>.train.sample-ratio1.0原生索引训练的向量采样比例。必须大于 0 且小于等于 1。更低的值可减少训练内存和构建开销,但可能降低索引质量。
<index-type>.nlist自动四种 IVF 类型的聚类数。省略时,paimon-vindex 根据分片内的非空向量数推定。
<index-type>.pq.code-ratio0.0625ivf-pq 和 diskann 的相对 PQ 编码预算。
<index-type>.pq.m自动ivf-pq 和 diskann 所用 PQ 子向量数的专家级覆盖设置。
ivf-pq.pq.use-opq自动显式启用或禁用 OPQ。未显式设置时,target-recall 大于等于 0.9 会启用它。
ivf-rq.rq.bits4持久化的 IVF-RQ 残差宽度。支持的值为 1 到 8;修改它需要重建索引。
<index-type>.target-recall未设置ivf-pq 和 diskann 使用的构建策略提示。请在留出(query hold-out)集上验证实际召回率。
<index-type>.max-bytes-per-vector未设置ivf-pq、ivf-rq 和 diskann 的存储目标和保守的预检上限。

额外的 paimon-vindex DiskANN 构建配置项:

配置项默认值说明
diskann.build-presetbalanced一致的 fast_build、balanced 或 high_recall 构建策略。
diskann.deployment-profile未设置用于选择存储布局的部署目标。
diskann.pq.bits8常驻 PQ 编码宽度。支持的值为 4 和 8。
diskann.max-degree64图的最大出度。
diskann.build-search-list-sizemax(100, max-degree)图构建期间的候选宽度。
diskann.alpha1.2鲁棒剪枝(robust-prune)阈值。
diskann.seed42可复现的初始化和构建顺序种子。
diskann.memory-budget-bytes8 GiB用于选择普通构建或分片构建的内部图构建内存估计。
diskann.storage-layoutauto显式的 compact 或 interleaved 布局覆盖。
diskann.raw-vector-encodingauto显式的 f32 或 f16 持久化重排向量编码。
diskann.build-distanceauto显式的乘积量化或全精度构建遍历覆盖。

按字段配置项​

上述配置项也可以在表级别(在 TBLPROPERTIES 中)设置,此时它们被同一索引 类型的所有向量列共享。当一张表有多个向量列时,可以用 fields.<field-name>.<option> 把某个配置项限定到单个列。字段级形式对该列 优先于列无关的配置项。<field-name> 必须与存储的表列名完全一致。字段级 向量配置项不包含索引类型前缀;例如,使用 fields.image_embedding.nlist 为 image_embedding 列覆盖共享的 ivf-pq.nlist 配置:

  • SQL
  • Python SDK
CREATE TABLE my_table (
    id INT,
    title_embedding ARRAY<FLOAT>,
    image_embedding ARRAY<FLOAT>
) TBLPROPERTIES (
    'row-tracking.enabled' = 'true',
    'data-evolution.enabled' = 'true',
    'global-index.enabled' = 'true',
    -- per-column dimensions
    'fields.title_embedding.dimension' = '768',
    'fields.image_embedding.dimension' = '512',
    -- shared by every ivf-pq column, overridden only for 'image_embedding'
    'ivf-pq.nlist' = '256',
    'fields.image_embedding.nlist' = '512',
    -- per-column training sample ratio
    'fields.image_embedding.train.sample-ratio' = '0.5'
);
import pyarrow as pa

from pypaimon import Schema

schema = Schema.from_pyarrow_schema(
    pa.schema([
        pa.field("id", pa.int32()),
        pa.field("title_embedding", pa.list_(pa.float32())),
        pa.field("image_embedding", pa.list_(pa.float32())),
    ]),
    options={
        "row-tracking.enabled": "true",
        "data-evolution.enabled": "true",
        "global-index.enabled": "true",
        "fields.title_embedding.dimension": "768",
        "fields.image_embedding.dimension": "512",
        "ivf-pq.nlist": "256",
        "fields.image_embedding.nlist": "512",
    },
)

catalog.create_table("db.my_table", schema, ignore_if_exists=False)

使用上述配置时,title_embedding 以 nlist=256 建立索引,而 image_embedding 使用 nlist=512,并用一半的非空向量进行训练。

向量搜索​

查询期的配置项随每次向量搜索请求传入:

配置项默认值说明
ivf.nprobe自动显式指定要探测的 IVF 聚类数。省略时,paimon-vindex 根据索引、top_k 和过滤选择性推导探测宽度。
ivf.max_initial_filter_expansion_factor禁用正整数,限制由过滤驱动的初始自动 IVF 探测宽度扩张。系数为 1 表示禁用初始过滤扩张。当过滤后的结果不足 top_k 个时,渐进式重试仍可能探测更多聚类。
ivf.refine_factor禁用取回 top_k * refine_factor 个 IVF 候选,并用 Paimon 表中存储的原始向量对其重排。对于 ivf-pq、ivf-sq、ivf-rq 等压缩索引,当召回率比延迟更重要时最有用。
ivf_pq.batch_table_reuseautoIVF-PQ 批量搜索的距离表复用模式:auto、on 或 off。其他索引类型和标量搜索会忽略该项。
ivf_pq.batch_table_reuse.max_bytes512 MiB正的长整型,限制 IVF-PQ 批量距离表复用所用的内存。当可复用的表超出预算时,搜索回退为直接构建距离表。
diskann.l_search自动paimon-vindex DiskANN 的图候选宽度。自动值在可用时使用校准结果,否则为 max(100, 2 * top_k)。

构建期和查询期必须使用相同的距离度量。搜索配置项可以按查询传入,因此高召回 查询可以使用更大的 ivf.nprobe 或 diskann.l_search,而延迟敏感的查询使用 更小的值。不要在同一次查询中同时设置两者。

ivf.max_initial_filter_expansion_factor 只适用于自动 IVF 搜索,不能与 ivf.nprobe 或 diskann.l_search 组合使用。更低的系数会减少初始过滤搜索的 工作量,但与不设上限的自动搜索相比,可能降低 Recall@K。渐进式扩张只在返回的 有效结果不足 top_k 个时发生;如果设了上限的初始搜索已经填满 top_k,探测 就会停止。

ivf.refine_factor 也可以用 refine_factor、rerank_factor 以及带连字符的 拼写(如 ivf.refine-factor)配置。设置 ivf.refine_factor=1 仍会对索引候选 执行原始向量重排;不设置则跳过重排阶段。

  • Flink SQL (Procedure)
  • Java API
  • Python SDK
-- Search for top-5 nearest neighbors
SELECT * FROM vector_search('my_table', 'embedding', array(1.0f, 2.0f, 3.0f), 5);

与 Spark 的表值函数不同,Flink 使用 CALL 过程执行向量搜索。 该过程以字符串形式返回 JSON 序列化的行。

-- Search for top-5 nearest neighbors
CALL sys.vector_search(
    `table` => 'db.my_table',
    vector_column => 'embedding',
    query_vector => '1.0,2.0,3.0',
    top_k => 5
);

-- With projection (only return specific columns)
CALL sys.vector_search(
    `table` => 'db.my_table',
    vector_column => 'embedding',
    query_vector => '1.0,2.0,3.0',
    top_k => 5,
    projection => 'id,name,__paimon_search_score',
    options => 'ivf.nprobe=32',
    `where` => 'id > 100'
);
Table table = catalog.getTable(identifier);

// Step 1: Build vector search
float[] queryVector = {1.0f, 2.0f, 3.0f};
GlobalIndexResult result = table.newVectorSearchBuilder()
        .withVector(queryVector)
        .withLimit(5)
        .withVectorColumn("embedding")
        .withOption("ivf.nprobe", "16")
        .executeLocal();

// Step 2: Read matching rows using the search result
ReadBuilder readBuilder = table.newReadBuilder();
TableScan.Plan plan = readBuilder.newScan().withGlobalIndexResult(result).plan();
try (RecordReader<InternalRow> reader = readBuilder.newRead().createReader(plan)) {
    reader.forEachRemaining(row -> {
        System.out.println("id=" + row.getInt(0) + ", name=" + row.getString(1));
    });
}

批量结果与输入向量的顺序保持一致。

float[][] queryVectors = {
    {1.0f, 2.0f, 3.0f},
    {3.0f, 2.0f, 1.0f}
};
List<GlobalIndexResult> batchResults = table.newBatchVectorSearchBuilder()
        .withVectors(queryVectors)
        .withLimit(5)
        .withVectorColumn("embedding")
        .executeBatchLocal();
// batchResults.get(i) corresponds to queryVectors[i].

对于 Java,使用 Table.newVectorSearchBuilder() 生成全局索引结果,然后把 结果传给 TableScan.withGlobalIndexResult。

table = catalog.get_table("db.my_table")

# Step 1: Build vector search
result = (
    table.new_vector_search_builder()
    .with_vector_column("embedding")
    .with_query_vector([1.0, 2.0, 3.0])
    .with_limit(5)
    .with_option("ivf.nprobe", "16")
    .execute_local()
)

# Step 2: Read matching rows using the search result
read_builder = table.new_read_builder()
scan = read_builder.new_scan().with_global_index_result(result)
plan = scan.plan()
table_read = read_builder.new_read()
pa_table = table_read.to_arrow(plan.splits())
print(pa_table)

你也可以添加一个标量过滤条件,在向量搜索之前预过滤行:

from pypaimon.common.predicate_builder import PredicateBuilder

predicate = (
    PredicateBuilder(table.fields)
    .equal("category", "electronics")
)

result = (
    table.new_vector_search_builder()
    .with_vector_column("embedding")
    .with_query_vector([1.0, 2.0, 3.0])
    .with_limit(5)
    .with_filter(predicate)
    .execute_local()
)

标量过滤条件会在向量搜索之前使用匹配的标量全局索引求值。为常用的元数据 过滤列(如 category、tenant_id 或 event_time)构建 BTree 索引, 这样向量搜索就能在运行 ANN 搜索之前先限定候选 row id。
