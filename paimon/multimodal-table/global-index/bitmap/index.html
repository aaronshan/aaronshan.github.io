Bitmap 索引

Bitmap 索引将每个不同的标量值映射到一个压缩的 64 位 row-id 位图。 它适用于枚举型维度和标签列——查询常使用等值、IN、补集或 null 谓词的场景, 例如 status、country、tenant_type 或业务标签。

与 BTree Index 相比,bitmap 索引针对精确 row-id 位图上的集合运算 做了优化。它通常更适合低基数或中基数的维度,尤其是 IN、NOT IN 或 != 谓词很常见的场景。对于范围谓词和高基数列(每个值只有少量行、且范围裁剪很 重要),BTree 索引仍然是更好的选择。

支持的谓词形式包括:

谓词示例
等值tag = 'vip'
INtag IN ('vip', 'trial')
不等tag != 'blocked'
NOT INtag NOT IN ('blocked', 'test')
Null 判断tag IS NULL、tag IS NOT NULL
字符串谓词tag LIKE 'vip%'、tag LIKE '%vip%'、tag startsWith 'vip'、tag contains 'vip'
范围谓词tag >= 'a'、tag BETWEEN 'a' AND 'm'
AND / OR 组合tag = 'vip' OR tag = 'trial'

等值、IN、null 判断和字符串前缀谓词使用直接的字典查找。其他谓词如 endsWith、contains、一般形式的 LIKE 和范围谓词,只有当候选 bitmap 索引 文件的总大小在配置的回退扫描预算之内时,才会回退为扫描位图字典条目。如果 超出预算,Paimon 会回退到其他匹配的索引或常规表扫描。

构建 Bitmap 索引​

  • SQL
  • Python SDK
-- Create bitmap index on 'tag' column
CALL sys.create_global_index(
    table => 'db.my_table',
    index_column => 'tag',
    index_type => 'bitmap'
);

可以只构建指定分区:

CALL sys.create_global_index(
    table => 'db.my_table',
    index_column => 'tag',
    index_type => 'bitmap',
    partitions => 'dt=2026-06-18;dt=2026-06-19'
);
table = catalog.get_table("db.my_table")

# Create bitmap index on 'tag' column.
added_files = table.create_global_index("tag", index_type="bitmap")
print(added_files)

该 API 返回已提交的索引文件数量。你可以传入 bitmap 构建选项,并将构建限制在指定分区:

added_files = table.create_global_index(
    "tag",
    index_type="bitmap",
    partitions=[{"dt": "2026-06-18"}, {"dt": "2026-06-19"}],
    options={
        "sorted-index.records-per-range": "10000000",
        "bitmap-index.dictionary-block-size": "16 kb",
    },
)
print(added_files)

Bitmap 索引与 BTree 索引共享有序索引构建路径。使用 sorted-index.records-per-range 控制每个生成的索引文件的预期记录数,使用 sorted-index.build.max-parallelism 限制 Flink 或 Spark 的构建并行度。旧配置键 btree-index.records-per-range 和 btree-index.build.max-parallelism 仍作为 兜底键被识别。

PyPaimon 的 bitmap 索引构建目前只支持将 bitmap-index.compression 设为 none(这也是默认值)。如果需要构建带压缩字典块的 bitmap 索引文件,请使用 SQL。

删除 Bitmap 索引​

  • SQL
  • Python SDK
CALL sys.drop_global_index(
    table => 'db.my_table',
    index_column => 'tag',
    index_type => 'bitmap'
);
table = catalog.get_table("db.my_table")

dropped_files = table.drop_global_index("tag", index_type="bitmap")
print(dropped_files)

你也可以将删除限制在指定分区,或只统计匹配的文件而不提交:

matched_files = table.drop_global_index(
    "tag",
    index_type="bitmap",
    partitions=[{"dt": "2026-06-18"}, {"dt": "2026-06-19"}],
    dry_run=True,
)
print(matched_files)

Bitmap 配置项​

配置项默认值说明
sorted-index.records-per-range10000000BTree、Bitmap 和 Multivalue 构建时,每个有序全局索引文件的预期记录数。
sorted-index.build.max-parallelism4096构建有序全局索引时 Flink 或 Spark 的最大并行度。
bitmap-index.dictionary-block-size16 kbbitmap 全局索引文件中字典块的目标大小。较小的块可减少高基数列的字典读放大;较大的块可减小字典块索引的大小。
bitmap-index.compressionnonebitmap 字典块和字典块索引的压缩算法。支持的值与 BTree 索引的块编解码器相同,如 none、lz4、lzo 和 zstd。
bitmap-index.compression-level1支持压缩级别的编解码器(如 zstd)所使用的压缩级别。
bitmap-index.fallback-scan-max-size256 mb对于无法使用直接位图查找的谓词,允许单个读取器回退字典扫描的 bitmap 全局索引文件最大总大小。设为 0 b 可禁用回退扫描。

使用 Bitmap 索引查询​

bitmap 索引构建完成后,当过滤谓词命中被索引列时,扫描会自动使用该索引。

  • SQL
  • Python SDK
SELECT * FROM my_table WHERE tag IN ('vip', 'trial');
from pypaimon.common.predicate_builder import PredicateBuilder

table = catalog.get_table("db.my_table")

read_builder = table.new_read_builder()
read_builder = read_builder.with_filter(
    PredicateBuilder(table.fields)
    .is_in("tag", ["vip", "trial"])
)

scan = read_builder.new_scan()
read = read_builder.new_read()
pa_table = read.to_arrow(scan.plan().splits())
print(pa_table)

对于 tag != 'blocked' 或 tag NOT IN ('blocked', 'test') 这类补集谓词, bitmap 索引会针对每个索引文件自身的非空 row-id 位图求补集。这样当一个逻辑 查询合并多个 bitmap 索引文件时,结果仍然保持正确。

文件格式​

bitmap 全局索引文件存储精确的 row-id 位图和一个按块索引的字典。读取器打开 文件时只读取其定长的 footer。null 行集合、非空行集合和字典块索引在有匹配 谓词需要时才惰性加载。点查随后读取包含目标值的字典块和对应的位图块。该 格式由 footer 驱动:footer 存储版本、魔数以及所有元数据块的偏移量。

+----------------------------------------------+
| null rows bitmap block                       |
+----------------------------------------------+
| non-null rows bitmap block                   |
+----------------------------------------------+
| value bitmap and dictionary payload blocks   |
+----------------------------------------------+
| ...                                          |
+----------------------------------------------+
| dictionary block index                       |
+----------------------------------------------+
| footer                                       |
+----------------------------------------------+

每个位图块都是一个序列化的 RoaringNavigableMap64。位图块不再包裹额外的 压缩层,因为 Roaring 本身已经紧凑地存储了 row id。值位图块按序列化键的顺序 为非空值写出。字典块在积攒到配置的目标大小时写出,因此物理负载区可能同时 包含值位图块和字典块。读取器使用存储的 offset 和 length 字段,不要求 值位图块或字典块在物理上连续。

每个字典块存储有序的键值条目。键使用与 BTree 全局索引键相同的键序列化器 序列化,并按序列化字节排序:

+----------------------------------------------+
| entry count (var-length int)                 |
+----------------------------------------------+
| key length (var-length int), key bytes       |
| bitmap block offset (var-length long)        |
| bitmap block length (var-length int)         |
+----------------------------------------------+
| ...                                          |
+----------------------------------------------+

上述字典块体以 BTree 风格的压缩块形式存储。写入时会尝试使用配置的字典压缩, 如果压缩不能节省足够空间,则保留未压缩的块体。每个字典块体之后跟随一个 5 字节的块尾部,记录实际的压缩类型和 CRC。存储的字典块 length 是块体长度, 不包含尾部。

字典块索引为每个字典块存储一条记录,其大小足够小,在打开索引文件时即可加载:

+----------------------------------------------+
| block count (var-length int)                 |
+----------------------------------------------+
| first key length (var-length int), key bytes |
| dictionary block offset (var-length long)    |
| dictionary block length (var-length int)     |
+----------------------------------------------+
| ...                                          |
+----------------------------------------------+

字典块索引使用与字典块相同的压缩块编码和 5 字节尾部。footer 中的字典块索引 length 同样不包含该尾部。

footer 长度固定,指向主要的元数据块:

+----------------------------------------------+
| null rows block offset (long)                |
| null rows block length (int)                 |
| non-null rows block offset (long)            |
| non-null rows block length (int)             |
| dictionary block index offset (long)         |
| dictionary block index length (int)          |
| value count (int)                            |
| version (int) = 1                            |
| magic (int)                                  |
+----------------------------------------------+

有序的字典块索引使等值和 IN 谓词可以通过二分查找定位候选值,而无需反序列化 文件中的每个字典块或值位图。null 判断只需读取所需的 null/非空位图。

每个 bitmap 索引文件还存储 manifest 级别的元数据,包括逻辑上的最小非空键、 最大非空键以及文件是否包含 null 值。扫描器利用这些元数据在打开 bitmap 索引 文件之前跳过不可能匹配的文件,这与 BTree 全局索引的文件裁剪类似。

+----------------------------------------------+
| first key length (int), first key bytes      |
| last key length (int), last key bytes        |
| has nulls (byte)                             |
| metadata version (byte) = 1                  |
| null key flags (byte)                        |
+----------------------------------------------+

对于无法通过点查或前缀查找解析的谓词,读取器可能会扫描所有字典块并读取 匹配的位图块。该回退由 bitmap-index.fallback-scan-max-size 控制,它会与 读取器所处理的候选 bitmap 索引文件的总大小进行比较。这既能让高基数标签或 维度列的点查读放大保持有界,又允许较小的 bitmap 索引直接响应更宽泛的谓词。
