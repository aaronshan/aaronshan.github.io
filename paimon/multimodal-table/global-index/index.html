Global Index

概述​

Global Index 是面向 Data Evolution(append)表的强大索引机制。它无需全表扫描即可实现高效的行级查找和过滤。Paimon 支持多种全局索引类型:

  • BTree 索引:基于 B-tree 的标量列查找索引。支持等值、IN、范围谓词,并可以通过 AND/OR 逻辑跨多列组合。
  • Bitmap 索引:基于位图的索引,适用于枚举型标量维度和标签列。基于压缩的 row-id 位图,支持等值、IN、字符串列前缀匹配、补集谓词和 null 判断。
  • Multivalue 索引:以位图支撑的索引,用于 ARRAY 列上的元素成员判断谓词。
  • FM 索引:面向字符列上 CONTAINS 谓词的精确分区子串索引。
  • Vector 索引:由 Paimon 向量索引库驱动的近似最近邻(ANN)索引,用于向量相似度搜索。
  • Full-Text 索引:由原生全文引擎支撑的全文检索索引,用于文本检索。支持词项匹配和相关性评分。
  • 混合检索:多路检索 API,在读取表行之前,将来自多个向量路由、多个全文路由或两者混合的结果进行合并。
索引类型适用场景说明
BTree数值、字符串、日期和时间戳列上的标量过滤当谓词具有高选择性时效果最佳,例如等值、IN、范围和 null 判断。
Bitmap枚举型维度和标签列基于压缩的 row-id 位图,最适合等值、IN、字符串前缀匹配、补集谓词和 null 判断。
Multivalue对支持的标量元素数组进行成员判断最适合 ARRAY_CONTAINS、ARRAYS_OVERLAP 和 ARRAY_CONTAINS_ALL。
FM字符列上的精确子串过滤支持任意字节长度的待查子串,并对被索引文本进行分区,以实现有界内存构建和按需加载读取。
Vector对 Embedding 进行 Top-K 相似度搜索使用 ANN 算法。通过调整构建期和查询期配置项,在召回率、延迟和索引大小之间取得平衡。
Full-Text文本列上的关键词搜索使用随每个索引文件一起存储的全文评分和分词器配置。
混合检索组合多个向量路由、多个全文路由,或向量与全文混合检索运行多个带评分的路由,并在读取行之前用 ranker 合并结果。

Global Index 构建于 Data Evolution 表之上。要使用全局索引,你的表必须具备:

  • 'row-tracking.enabled' = 'true'
  • 'data-evolution.enabled' = 'true'

当索引只覆盖表数据的一部分时,全局索引查询的结果可能不完整。如果查询谓词命中索引,Paimon 只返回已索引部分的结果;尚未被索引的数据中的匹配记录不会被返回。

前置条件​

创建一张具有所需属性的表:

  • SQL
  • Python SDK
CREATE TABLE my_table (
    id INT,
    name STRING,
    tags ARRAY<STRING>,
    embedding ARRAY<FLOAT>,
    content STRING
) TBLPROPERTIES (
    'row-tracking.enabled' = 'true',
    'data-evolution.enabled' = 'true',
    'global-index.enabled' = 'true'
);
import pyarrow as pa

from pypaimon import Schema

schema = Schema.from_pyarrow_schema(
    pa.schema([
        pa.field("id", pa.int32()),
        pa.field("name", pa.string()),
        pa.field("tags", pa.list_(pa.string())),
        pa.field("embedding", pa.list_(pa.float32())),
        pa.field("content", pa.string()),
    ]),
    options={
        "row-tracking.enabled": "true",
        "data-evolution.enabled": "true",
        "global-index.enabled": "true",
    },
)

catalog.create_table("db.my_table", schema, ignore_if_exists=False)

生命周期​

为所有分区或仅指定分区创建全局索引:

  • SQL
  • Python SDK
CALL sys.create_global_index(
    table => 'db.my_table',
    index_column => 'name',
    index_type => 'btree'
);

CALL sys.create_global_index(
    table => 'db.my_table',
    index_column => 'name',
    index_type => 'btree',
    partitions => 'dt=2026-06-18;dt=2026-06-19'
);
table = catalog.get_table("db.my_table")

added_files = table.create_global_index("name")
print(added_files)

该 API 返回已提交的索引文件数量。你可以传入构建选项,并将构建限制在指定分区:

added_files = table.create_global_index(
    "name",
    index_type="btree",
    partitions=[{"dt": "2026-06-18"}, {"dt": "2026-06-19"}],
    options={"sorted-index.records-per-range": "10000000"},
)

PyPaimon 的全局索引构建目前支持:在启用 row tracking 的表上构建单列 BTree 索引、 单列 Bitmap 索引、单列 paimon-vindex 向量索引和单列全文索引。

删除索引文件:

  • SQL
  • Python SDK
CALL sys.drop_global_index(
    table => 'db.my_table',
    index_column => 'name',
    index_type => 'btree'
);
table = catalog.get_table("db.my_table")

dropped_files = table.drop_global_index("name", index_type="btree")
print(dropped_files)

你也可以将删除限制在指定分区,或只统计匹配的文件而不提交:

matched_files = table.drop_global_index(
    "name",
    index_type="btree",
    partitions=[{"dt": "2026-06-18"}, {"dt": "2026-06-19"}],
    dry_run=True,
)

全局索引存储在索引文件中,并记录在表元数据里。要查看索引文件及其 row-id 覆盖 范围,可查询 table_indexes 系统表:

  • SQL
  • Python SDK
SELECT index_type, index_field_name, row_range_start, row_range_end
FROM my_table$table_indexes
WHERE index_field_name IS NOT NULL;
import pyarrow.compute as pc

table_indexes = catalog.get_table("db.my_table$table_indexes")
read_builder = table_indexes.new_read_builder().with_projection([
    "index_type",
    "index_field_name",
    "row_range_start",
    "row_range_end",
])

pa_table = read_builder.new_read().to_arrow(
    read_builder.new_scan().plan().splits()
)
pa_table = pa_table.filter(pc.is_valid(pa_table["index_field_name"]))
print(pa_table)

你还可以查询 file_key_ranges,查看数据文件的 row-id 范围并诊断覆盖情况:

  • SQL
  • Python SDK
SELECT file_path, first_row_id, record_count
FROM my_table$file_key_ranges;
file_key_ranges = catalog.get_table("db.my_table$file_key_ranges")
read_builder = file_key_ranges.new_read_builder().with_projection([
    "file_path",
    "first_row_id",
    "record_count",
])

pa_table = read_builder.new_read().to_arrow(
    read_builder.new_scan().plan().splits()
)
print(pa_table)

对于需要新追加的行在被已有全局索引覆盖后才可见的工作负载,可以启用可见性回调 (visibility callback):

  • SQL
  • Python SDK
ALTER TABLE my_table SET (
    'visibility-callback.enabled' = 'true',
    'visibility-callback.timeout' = '30 min'
);
from pypaimon.schema.schema_change import SchemaChange

catalog.alter_table(
    "db.my_table",
    [
        SchemaChange.set_option("visibility-callback.enabled", "true"),
        SchemaChange.set_option("visibility-callback.timeout", "30 min"),
    ],
)

覆盖范围与新鲜度​

全局索引文件覆盖的是 row-id 区间。如果在索引构建之后又追加了更多行,这些新行 不会被已有索引文件自动覆盖。重新构建全局索引,才能为新增未覆盖的数据创建索引 文件。标量查询默认使用 fast 搜索模式;向量查询和全文查询也默认为 fast, 并且只搜索已索引的 row 区间。

对于支持原始数据搜索的查询类型,可以通过以下设置提升新鲜度:

  • SQL
  • Python SDK
ALTER TABLE my_table SET ('vector-index.search-mode' = 'full');
from pypaimon.schema.schema_change import SchemaChange

catalog.alter_table(
    "db.my_table",
    [SchemaChange.set_option("vector-index.search-mode", "full")],
)

对已有 Table 实例进行只读覆盖:

full_table = table.copy({"vector-index.search-mode": "full"})

使用 full 搜索时,受支持的全局索引查询会先利用快照的 nextRowId 和全局索引 的 row-id 覆盖信息,检测是否存在未被索引覆盖的 row 区间;只有存在这种缺口时 才会扫描原始数据。当数据文件在索引创建后可能被重写或更新时,使用 detail 搜索:它会扫描数据文件元数据,找出精确的未索引 row 区间,并能处理由更新或 重写导致的索引失效。

针对某类索引,可分别使用 scalar-index.search-mode、vector-index.search-mode 或 full-text-index.search-mode。旧配置项 global-index.search-mode 没有默认值, 当对应的分类配置项未显式设置时,它作为兜底使用。

要临时禁用全局索引扫描加速(同时保留索引文件),可设置:

  • SQL
  • Python SDK
ALTER TABLE my_table SET ('global-index.enabled' = 'false');
from pypaimon.schema.schema_change import SchemaChange

catalog.alter_table(
    "db.my_table",
    [SchemaChange.set_option("global-index.enabled", "false")],
)

将其重新设为 true 即可在扫描时再次使用全局索引。

构建选项​

以下表配置项会影响全局索引的构建和读取行为:

配置项默认值说明
global-index.enabledtrue扫描时是否可以使用全局索引。
global-index.search-mode未设置全局索引查询的旧版兜底搜索模式。分类专属配置项优先。
scalar-index.search-modefastBTree、Bitmap、Multivalue 和 FM 查询的搜索模式。
vector-index.search-modefast向量查询的搜索模式。
full-text-index.search-modefast全文查询的搜索模式。
global-index.external-path未设置全局索引文件的根目录。未设置时,文件存储在表的 index 目录下。
global-index.column-update-actionTHROW_ERROR对被索引列发生更新时的处理动作。THROW_ERROR 拒绝更新;DROP_PARTITION_INDEX 删除受影响的分区索引;IGNORE 在更新期间保持已有索引文件不变,并使下一次增量索引构建扫描活跃的数据 manifest、重建受影响的 row 区间。在引入源元数据之前创建的索引文件不会被自动刷新。
sorted-index.records-per-range10000000BTree、Bitmap 和 Multivalue 构建时,每个有序全局索引文件的预期记录数。
sorted-index.build.max-parallelism4096构建有序全局索引时 Flink 或 Spark 的最大并行度。
global-index.row-count-per-shard100000向量和全文等非有序全局索引构建时每个分片的目标行数。
global-index.build.max-shard32全局索引构建的首选最大分片数。
global-index.build.max-parallelism4096构建非有序全局索引时 Flink 或 Spark 的最大并行度。
global-index.thread-num32全局索引 I/O 的最大并发线程数。
visibility-callback.enabledfalse批式或有界流式提交是否等待已有全局索引覆盖新增文件。
visibility-callback.timeout30 min可见性回调的最大等待时间。

BTree 索引​

BTree 索引用于标量列查找和范围谓词。构建和查询示例参见 BTree Index。

Bitmap 索引​

Bitmap 索引适用于通过等值、IN、字符串前缀匹配、补集或 null 谓词查询的枚举型维度和标签列。构建示例、配置项和文件格式细节参见 Bitmap Index。

Multivalue 索引​

Multivalue 索引用于 ARRAY 列上的元素成员判断谓词。Data Evolution 构建示例、Core 查询用法、配置项以及 null/空值成员语义参见 Multivalue Index。

FM 索引​

FM 索引用于字符列上的精确子串谓词。构建示例、精确性与覆盖语义、调优选项以及 primary-key 表配置参见 FM Index。

Vector 索引​

Vector 索引用于近似最近邻(ANN)搜索。支持的索引类型、配置项和搜索示例参见 Vector Index。

Full-Text 索引​

Full-Text 索引由原生全文引擎支撑,用于文本检索。分词器配置项和搜索示例参见 Full-Text Index。

混合检索​

混合检索(Hybrid Search)用于在一次请求中查询多个向量路由、多个全文路由或两者混合。路由配置、ranker 和 API 示例参见 Hybrid Search。
