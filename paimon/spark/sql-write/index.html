SQL 写入

Insert Table​

INSERT 语句向表中插入新行或覆盖表中的现有数据。插入的行可以由值表达式指定,也可以来自查询结果。

语法

INSERT { INTO | OVERWRITE } table_identifier [ part_spec ] [ column_list ] { value_expr | query };

参数

  • table_identifier:指定表名,可以可选地加上数据库名限定。

  • part_spec:可选参数,指定分区的键值对列表,以逗号分隔。

  • column_list:可选参数,指定属于 table_identifier 表的列列表,以逗号分隔。Spark 会根据指定的列列表重排输入查询的列,使其与表 schema 匹配。

    注意:从 Spark 3.4 起,带有显式列列表且列数少于目标表的 INSERT INTO 命令会自动为其余列填充相应的默认值(对于没有显式默认值的列则填充 NULL)。在 Spark 3.3 或更早版本中,column_list 的大小必须与目标表的列数相等,否则这些命令会失败。

  • value_expr ( { value | NULL } [ , … ] ) [ , ( … ) ]:指定要插入的值。可以插入显式指定的值或 NULL。子句中每个值之间必须用逗号分隔。可以指定多组值以插入多行。

更多信息请查阅语法文档:Spark INSERT Statement

Insert Into​

使用 INSERT INTO 将记录和变更应用到表中。

INSERT INTO my_table SELECT ...

Insert Overwrite​

使用 INSERT OVERWRITE 覆盖整个表。

INSERT OVERWRITE my_table SELECT ...

覆盖指定分区​

使用 INSERT OVERWRITE 覆盖某个分区。

INSERT OVERWRITE my_table PARTITION (key1 = value1, key2 = value2, ...) SELECT ...

动态分区覆盖​

Spark 的默认覆盖模式是 static 分区覆盖。要启用动态覆盖,需要将 Spark 会话配置 spark.sql.sources.partitionOverwriteMode 设置为 dynamic。

例如:

CREATE TABLE my_table (id INT, pt STRING) PARTITIONED BY (pt);
INSERT INTO my_table VALUES (1, 'p1'), (2, 'p2');

-- Static overwrite (Overwrite the whole table)
INSERT OVERWRITE my_table VALUES (3, 'p1');
-- or 
INSERT OVERWRITE my_table PARTITION (pt) VALUES (3, 'p1');

SELECT * FROM my_table;
/*
+---+---+
| id| pt|
+---+---+
|  3| p1|
+---+---+
*/

-- Static overwrite with specified partitions (Only overwrite pt='p1')
INSERT OVERWRITE my_table PARTITION (pt='p1') VALUES (3);

SELECT * FROM my_table;
/*
+---+---+
| id| pt|
+---+---+
|  2| p2|
|  3| p1|
+---+---+
*/
  
-- Dynamic overwrite (Only overwrite pt='p1')
SET spark.sql.sources.partitionOverwriteMode=dynamic;
INSERT OVERWRITE my_table VALUES (3, 'p1');

SELECT * FROM my_table;
/*
+---+---+
| id| pt|
+---+---+
|  2| p2|
|  3| p1|
+---+---+
*/

通过 Paimon 读取的 Format Table(format-table.implementation = paimon,默认值)遵循 同样的规则。未指定分区的 INSERT OVERWRITE 会替换整个表,因此查询未写入的 分区也会被替换,返回零行的查询会使表变空;dynamic 模式只替换被写入的分区, 未写入任何内容则不替换任何分区。启用 metastore.partitioned-table = true 时,catalog 决定了 表拥有哪些分区,因此覆盖整个表会清空这些分区,并留下只有 MSCK REPAIR TABLE 才能恢复的目录。

Truncate Table​

TRUNCATE TABLE 语句移除表或指定分区的所有行。

TRUNCATE TABLE my_table;
TRUNCATE TABLE my_table PARTITION (dt = '2025-01-01');

对于通过 Paimon 读取的 Format Table(format-table.implementation = paimon,默认值), TRUNCATE TABLE 删除表或指定分区的数据文件并保留 分区:它们的目录会保留,启用 metastore.partitioned-table = true 时其 catalog 注册信息也会保留,因此 SHOW PARTITIONS 返回的结果与之前相同。该设置还 使 catalog 成为表拥有哪些分区的裁决方,因此 truncate 会清空这些分区,留下 只有 MSCK REPAIR TABLE 才能恢复的目录,并将其统计信息替换为零。 只指定部分分区键的 spec 会清空其覆盖的分区;指定了表不存在的完整 spec 则是 错误。

Update Table​

更新满足谓词条件的行的列值。未提供谓词时,更新所有行的列值。

注意:

信息

当目标表是主键表时,不支持更新主键列。

Spark 支持更新 PrimitiveType 和 StructType,例如:

-- Syntax
UPDATE table_identifier SET column1 = value1, column2 = value2, ... WHERE condition;

CREATE TABLE t (
  id INT, 
  s STRUCT<c1: INT, c2: STRING>, 
  name STRING)
TBLPROPERTIES (
  'primary-key' = 'id', 
  'merge-engine' = 'deduplicate'
);

-- you can use
UPDATE t SET name = 'a_new' WHERE id = 1;
UPDATE t SET s.c2 = 'a_new' WHERE s.c1 = 1;

Delete From Table​

删除满足谓词条件的行。未提供谓词时,删除所有行。

DELETE FROM my_table WHERE id = 1;

Merge Into Table​

基于源表将一组更新、插入和删除合并到目标表中。

信息

当目标表是主键表时,不支持更新主键列。

语法​

MERGE INTO target
USING source
ON <merge condition>
WHEN MATCHED [AND <condition>] THEN { UPDATE SET ... | DELETE }
WHEN NOT MATCHED [AND <condition>] THEN INSERT ...

每个 WHEN 子句可以重复;子句按顺序求值,对给定行而言第一个匹配的子句生效。

示例​

以下示例假设源表和目标表的 schema 均为 (a INT, b INT, c STRING),其中 a 是主键。

简单 upsert —— 更新已有行,插入新行:

MERGE INTO target
USING source
ON target.a = source.a
WHEN MATCHED THEN UPDATE SET *
WHEN NOT MATCHED THEN INSERT *

多条件子句:

MERGE INTO target
USING source
ON target.a = source.a
WHEN MATCHED AND target.a = 5 THEN UPDATE SET b = source.b + target.b
WHEN MATCHED AND source.c > 'c2' THEN UPDATE SET *
WHEN MATCHED THEN DELETE
WHEN NOT MATCHED AND c > 'c9' THEN INSERT (a, b, c) VALUES (a, b * 1.1, c)
WHEN NOT MATCHED THEN INSERT *

列对齐​

赋值按列名对齐到目标表。

  • 显式子句(UPDATE SET col = expr / INSERT (col list) VALUES ...)—— 只写入提及的列。未提及的目标列在 UPDATE 时保留其当前值,在 INSERT 时填充 NULL / CURRENT_DEFAULT。
  • 星号子句(UPDATE SET * / INSERT *)—— * 针对目标列展开。当源表和目标列不完全匹配时,行为取决于 spark.paimon.write.merge-schema;覆盖 MERGE INTO * 和 byName INSERT 两种路径的完整对照表,请参阅 Write Merge Schema 下的 按写入路径的列对齐。

Write Merge Schema​

启用 write.merge-schema 后,Paimon 会在写入期间自动演进表 schema 以容纳传入数据中的新列,同时保证数据完整性。

信息

由于写入期间表 schema 可能更新,使用该功能需要禁用 catalog 缓存。请配置 spark.sql.catalog.<catalogName>.cache-enabled 为 false。

Schema 如何演进​

三个选项控制 schema 演进的激进程度;每个选项只有在前一个启用时才生效:

Option Description
write.merge-schema
 为 true 时,演进表 schema 以接受传入数据中的新列。已有列的类型保持不变,传入的值会被转换为已有类型;如需同时放宽已有类型,请启用 write.merge-schema.type-widening。
write.merge-schema.type-widening
 仅在 write.merge-schema 为 true 时生效。为 true 时,当传入数据具有更宽的兼容类型时放宽已有列的类型(例如 INT -> BIGINT、DECIMAL 精度提升)。有损变更仍会被拒绝,除非同时启用 write.merge-schema.explicit-cast。
write.merge-schema.explicit-cast
 仅在 write.merge-schema.type-widening 为 true 时生效。为 true 时,还允许兼容类型之间的有损类型变更(例如 BIGINT -> INT、STRING -> DATE)。

示例​

DataFrame 批式写入:

data.write
  .format("paimon")
  .mode("append")
  .option("write.merge-schema", "true")
  .saveAsTable("t")

Spark SQL(BY NAME 需要 Spark 3.5+):

SET `spark.paimon.write.merge-schema` = true;

CREATE TABLE t (a INT, b STRING);
INSERT INTO t VALUES (1, '1'), (2, '2');

INSERT INTO t BY NAME SELECT 3 AS a, '3' AS b, 3 AS c;

流式写入:

val inputData = MemoryStream[(Int, String)]
inputData
  .toDS()
  .toDF("col1", "col2")
  .writeStream
  .format("paimon")
  .option("checkpointLocation", "/path/to/checkpoint")
  .option("write.merge-schema", "true")
  .toTable("t")

按写入路径的列对齐​

当源 schema 与目标 schema 不完全匹配时,行为同时取决于 write.merge-schema 和写入路径。对于嵌套 struct 字段,所有 byName 路径行为一致;在顶层,MERGE INTO * 与普通的 byName INSERT 不同,因为 * 展开只引用目标列。

写入路径场景merge-schema=false(默认)merge-schema=true
byName INSERT(INSERT INTO ... BY NAME / saveAsTable / writeTo)源多出顶层列抛异常演进进目标 schema
目标顶层列在源中缺失填充 NULL填充 NULL
嵌套 struct 源多出字段抛异常演进进目标 schema
嵌套 struct 目标缺失字段抛异常填充 NULL
MERGE INTO *(UPDATE * / INSERT *)源多出顶层列静默丢弃(* 只覆盖目标列)演进进目标 schema
目标顶层列在源中缺失抛异常UPDATE * 保留当前值;INSERT * 填充 CURRENT_DEFAULT(无默认值时为 NULL)
嵌套 struct 源多出字段抛异常演进进目标 schema
嵌套 struct 目标缺失字段抛异常UPDATE * 保留当前值;INSERT * 填充 CURRENT_DEFAULT(无默认值时为 NULL)

说明:

  • 基于位置的写入(例如不带 BY NAME 的 INSERT INTO t VALUES (...))要求列数精确匹配,不参与 schema 演进;上表只覆盖 byName 写入。
  • merge-schema=false 时 byName INSERT 对目标顶层缺失列的行为与 Spark 的 INSERT FILL 语义一致 —— 只有嵌套缺失字段会抛异常。
  • 在严格模式(merge-schema=false)下,嵌套的源多出字段会抛异常以避免数据静默丢失;而在顶层 MERGE INTO * 中,源多出的字段会被静默丢弃,因为 * 从不引用它们。

COPY INTO​

COPY INTO 提供了一条 SQL 命令,用于将数据文件批量加载到 Paimon 表中,以及将表数据导出到文件。支持的格式:CSV、JSON 和 Parquet。

信息

SQL 方言: Paimon 的 COPY INTO 是 Snowflake 风格的扩展(FILE_FORMAT = (TYPE = ...)、PATTERN、FORCE、ON_ERROR),不是 Databricks 的 COPY INTO 形式(FILEFORMAT + FORMAT_OPTIONS (...) / COPY_OPTIONS (...))。它只实现了 Snowflake 语法的一个子集。特别地,ON_ERROR 支持 ABORT_STATEMENT(默认)、CONTINUE 和 SKIP_FILE;Snowflake 的变体 SKIP_FILE_<num> 和 SKIP_FILE_<num>% 不受支持。

CSV 导入​

COPY INTO table_name [(col1, col2, ...)]
FROM 'source_path'
FILE_FORMAT = (TYPE = CSV [, option = value, ...])
[PATTERN = 'regex']
[FORCE = TRUE|FALSE]
[ON_ERROR = { ABORT_STATEMENT | CONTINUE | SKIP_FILE }]

基本导入:

COPY INTO my_db.my_table
FROM '/data/csv_files/'
FILE_FORMAT = (TYPE = CSV);

指定列映射导入:

-- Only load into specified columns; omitted columns use their DEFAULT value or NULL
COPY INTO my_db.users (id, name)
FROM '/data/new_users/'
FILE_FORMAT = (TYPE = CSV, SKIP_HEADER = 1);

使用 NULL_IF 和 PATTERN 导入:

COPY INTO my_db.events
FROM '/data/logs/'
FILE_FORMAT = (TYPE = CSV, FIELD_DELIMITER = '|', NULL_IF = ('NULL', '\\N', ''))
PATTERN = '.*\.csv'
FORCE = FALSE;

JSON 导入​

COPY INTO table_name [(col1, col2, ...)]
FROM 'source_path'
FILE_FORMAT = (TYPE = JSON [, option = value, ...])
[PATTERN = 'regex']
[FORCE = TRUE|FALSE]
[ON_ERROR = { ABORT_STATEMENT | CONTINUE | SKIP_FILE }]

基本导入:

COPY INTO my_db.my_table
FROM '/data/json_files/'
FILE_FORMAT = (TYPE = JSON);

导入多行 JSON 数组:

COPY INTO my_db.events
FROM '/data/events/'
FILE_FORMAT = (TYPE = JSON, MULTI_LINE = TRUE);

JSON 列按列名匹配(而非按位置),因此源字段顺序无关紧要。

Parquet 导入​

COPY INTO table_name [(col1, col2, ...)]
FROM 'source_path'
FILE_FORMAT = (TYPE = PARQUET [, option = value, ...])
[PATTERN = 'regex']
[FORCE = TRUE|FALSE]
[ON_ERROR = { ABORT_STATEMENT | CONTINUE | SKIP_FILE }]

基本导入:

COPY INTO my_db.my_table
FROM '/data/parquet_files/'
FILE_FORMAT = (TYPE = PARQUET);

使用 PATTERN 导入:

COPY INTO my_db.events
FROM '/data/lake/'
FILE_FORMAT = (TYPE = PARQUET)
PATTERN = '.*\.parquet'
FORCE = FALSE;

Parquet 列按列名匹配(而非按位置)。源文件中多余的列会被忽略;缺失的列填充为 NULL。

写出 CSV 文件​

COPY INTO 'target_path'
FROM { table_name | (SELECT ...) }
FILE_FORMAT = (TYPE = CSV [, option = value, ...])
[OVERWRITE = TRUE|FALSE]

带表头并覆盖写出:

COPY INTO '/export/users_backup/'
FROM my_db.users
FILE_FORMAT = (TYPE = CSV, HEADER = TRUE, FIELD_DELIMITER = ',')
OVERWRITE = TRUE;

从查询写出:

COPY INTO '/export/active_users/'
FROM (SELECT id, name FROM my_db.users WHERE active = TRUE)
FILE_FORMAT = (TYPE = CSV, HEADER = TRUE);

写出 JSON 文件​

COPY INTO 'target_path'
FROM { table_name | (SELECT ...) }
FILE_FORMAT = (TYPE = JSON [, option = value, ...])
[OVERWRITE = TRUE|FALSE]

基本 JSON 导出:

COPY INTO '/export/events_backup/'
FROM my_db.events
FILE_FORMAT = (TYPE = JSON)
OVERWRITE = TRUE;

从查询导出 JSON:

COPY INTO '/export/recent_events/'
FROM (SELECT * FROM my_db.events WHERE event_date > '2024-01-01')
FILE_FORMAT = (TYPE = JSON);

写出 Parquet 文件​

COPY INTO 'target_path'
FROM { table_name | (SELECT ...) }
FILE_FORMAT = (TYPE = PARQUET [, option = value, ...])
[OVERWRITE = TRUE|FALSE]

基本 Parquet 导出:

COPY INTO '/export/data_backup/'
FROM my_db.events
FILE_FORMAT = (TYPE = PARQUET)
OVERWRITE = TRUE;

带压缩导出:

COPY INTO '/export/data_compressed/'
FROM my_db.events
FILE_FORMAT = (TYPE = PARQUET, COMPRESSION = GZIP)
OVERWRITE = TRUE;

从聚合查询导出 Parquet:

COPY INTO '/export/summary/'
FROM (SELECT dept, COUNT(*) AS cnt FROM my_db.employees GROUP BY dept)
FILE_FORMAT = (TYPE = PARQUET);

列映射​

当提供显式列列表时(例如 COPY INTO t (col1, col2) FROM ...):

  • CSV:列按位置映射到指定的列列表。
  • JSON:列按名称匹配到指定的列列表。
  • Parquet:列按名称匹配到指定的列列表。
  • 源列数必须与列列表长度一致(CSV)。对于 JSON 和 Parquet,源中缺失的字段填充为 NULL。
  • 不在列表中的列将填充其 DEFAULT 值(如果表 schema 中定义了)或 NULL。
  • 不在列表中且没有默认值的非空列会导致报错。

未提供列列表时:

  • CSV:列按位置映射到目标表的所有可写列。CSV 列数必须与可写列数一致。
  • JSON:列按名称匹配到可写列。JSON 中缺失的字段填充为 NULL。

重复导入​

默认情况下(FORCE = FALSE),COPY INTO 会跟踪已成功加载的文件。文件通过其路径、大小和最后修改时间戳来标识。

  • 重新运行相同的 COPY INTO 命令会跳过已加载的文件,并返回状态 SKIPPED。
  • 如果源文件被修改(大小或时间戳变化),它将重新具备加载资格。
  • FORCE = TRUE 绕过加载历史,始终重新导入所有匹配的文件。

输出结果​

导入为每个源文件返回一行:

列类型说明
file_nameSTRING源文件名
statusSTRINGLOADED、PARTIALLY_LOADED、LOAD_FAILED 或 SKIPPED
rows_loadedBIGINT写入的行数
rows_parsedBIGINT从文件中解析出的行数
errors_seenBIGINT错误行数(解析或类型转换失败)
first_errorSTRING遇到的第一个错误信息(无错误时为 NULL)

文件写出返回单行:

列类型说明
output_pathSTRING目标输出路径
file_countINT写出的文件数
rows_writtenBIGINT写出的总行数

限制​

  • CSV 列数不匹配:列数少于或多于目标 schema 的行被视为格式错误的记录。使用 ON_ERROR = CONTINUE 时,这些行会被跳过并计为错误。
  • 仅支持 CSV、JSON 和 Parquet 格式。
  • 不支持 SINGLE = TRUE(单文件输出)。
  • 文件格式选项必须在 FILE_FORMAT = (...) 中内联指定。
  • 文件列举是非递归的:只处理源路径下的直接文件。子目录会被忽略。
  • PATTERN 只匹配基本文件名(而非完整路径)。
  • 针对同一张表的并发 COPY INTO 命令可能产生重复数据。
  • SKIP_HEADER 只支持 0 或 1。
  • FROM (...) 接受任意只读查询(例如 SELECT、WITH ... SELECT、VALUES);有副作用的语句(例如 INSERT、INSERT OVERWRITE DIRECTORY、DDL)会被拒绝。
  • 对于 FROM (...) 导出,rows_written 是在文件写出前由一个单独的 pass 统计的执行期指标。由于 DataFrame 是惰性且未缓存的,写出会第二次重新执行该查询;如果查询是非确定性的(例如使用了 rand()、current_timestamp(),或读取不稳定的源),两次运行可能产生不同的行,因此 rows_written 可能与实际文件内容不一致。结果有意不做落盘暂存,因此导出不会消耗额外的 executor 磁盘。
