SQL DDL

Catalog​

创建 Catalog​

Paimon catalog 目前支持三种类型的 metastore:

  • filesystem metastore(默认),将元数据和表文件都存储在文件系统中。
  • hive metastore,同时将元数据存储在 Hive metastore 中。用户可以直接从 Hive 访问这些表。
  • jdbc metastore,同时将元数据存储在 MySQL、Postgres 等关系型数据库中。

创建 catalog 时的详细选项请参阅 CatalogOptions。

创建 Filesystem Catalog​

以下 Spark SQL 注册并使用一个名为 my_catalog 的 Paimon catalog。元数据和表文件存储在 hdfs:///path/to/warehouse 下。

以下 shell 命令注册一个名为 paimon 的 Paimon catalog。元数据和表文件存储在 hdfs:///path/to/warehouse 下。

spark-sql ... \
    --conf spark.sql.catalog.paimon=org.apache.paimon.spark.SparkCatalog \
    --conf spark.sql.catalog.paimon.warehouse=hdfs:///path/to/warehouse

你可以使用 spark.sql.catalog.paimon.table-default. 前缀为该 catalog 中创建的表定义任意默认表选项。

spark-sql 启动后,你可以使用以下 SQL 切换到 paimon catalog 的 default 数据库。

USE paimon.default;

创建 Hive Catalog​

使用 Paimon Hive catalog 时,对 catalog 的变更会直接影响对应的 Hive metastore。在此类 catalog 中创建的表也可以直接从 Hive 访问。

要使用 Hive catalog,数据库名、表名和字段名必须为小写。

你的 Spark 安装应能检测到或已包含 Hive 依赖。更多信息请参阅这里。

以下 shell 命令注册一个名为 paimon 的 Paimon Hive catalog。元数据和表文件存储在 hdfs:///path/to/warehouse 下。此外,元数据也存储在 Hive metastore 中。

spark-sql ... \
    --conf spark.sql.catalog.paimon=org.apache.paimon.spark.SparkCatalog \
    --conf spark.sql.catalog.paimon.warehouse=hdfs:///path/to/warehouse \
    --conf spark.sql.catalog.paimon.metastore=hive \
    --conf spark.sql.catalog.paimon.uri=thrift://<hive-metastore-host-name>:<port>

你可以使用 spark.sql.catalog.paimon.table-default. 前缀为该 catalog 中创建的表定义任意默认表选项。

spark-sql 启动后,你可以使用以下 SQL 切换到 paimon catalog 的 default 数据库。

USE paimon.default;

此外,你也可以创建 SparkGenericCatalog。

同步分区到 Hive Metastore

默认情况下,Paimon 不会将新创建的分区同步到 Hive metastore。用户在 Hive 中会看到一张非分区表。分区下推将通过过滤条件下推来实现。

如果你希望在 Hive 中看到分区表,并将新创建的分区同步到 Hive metastore,请将表属性 metastore.partitioned-table 设置为 true。另请参阅 CoreOptions。

创建 JDBC Catalog​

使用 Paimon JDBC catalog 时,对 catalog 的变更会直接存储在 SQLite、MySQL、Postgres 等关系型数据库中。

目前,lock 配置仅支持 MySQL 和 SQLite。如果你使用其他类型的数据库作为 catalog 存储,请不要配置 lock.enabled。

在 Spark 中使用 Paimon JDBC Catalog 需要正确添加用于连接数据库的相应 jar 包。你应先下载 JDBC connector 的 bundled jar 并将其加入 classpath,例如 MySQL、postgres。

数据库类型Bundle NameSQL Client JAR
mysqlmysql-connector-javaDownload
postgrespostgresqlDownload

JDBC catalog 支持持久化的 Paimon 视图。视图元数据存储在 catalog 数据库中自动创建的 paimon_views 表中。

在同一个数据库中,一个名称不能同时被表和视图使用;所有写入操作 (createTable、renameTable、createView、renameView)都会拒绝冲突的标识符。升级时的权限、单进程锁 语义以及数据库可见性细节,请参阅 Views。

spark-sql ... \
    --conf spark.sql.catalog.paimon=org.apache.paimon.spark.SparkCatalog \
    --conf spark.sql.catalog.paimon.warehouse=hdfs:///path/to/warehouse \
    --conf spark.sql.catalog.paimon.metastore=jdbc \
    --conf spark.sql.catalog.paimon.uri=jdbc:mysql://<host>:<port>/<databaseName> \
    --conf spark.sql.catalog.paimon.jdbc.user=... \
    --conf spark.sql.catalog.paimon.jdbc.password=...
    
USE paimon.default;

表​

创建表​

使用 Paimon catalog 后,你可以创建和删除表。在 Paimon catalog 中创建的表由 catalog 管理。 当表从 catalog 中删除时,其表文件也会被删除。

以下 SQL 假设你已经注册并正在使用一个 Paimon catalog。它在 catalog 的 default 数据库中创建一张名为 my_table 的托管表,包含五列,其中 dt、hh 和 user_id 是主键。

CREATE TABLE my_table (
    user_id BIGINT,
    item_id BIGINT,
    behavior STRING,
    dt STRING,
    hh STRING
) TBLPROPERTIES (
    'primary-key' = 'dt,hh,user_id'
);

你可以创建分区表:

CREATE TABLE my_table (
    user_id BIGINT,
    item_id BIGINT,
    behavior STRING,
    dt STRING,
    hh STRING
) PARTITIONED BY (dt, hh) TBLPROPERTIES (
    'primary-key' = 'dt,hh,user_id'
);

管理 Format Table 分区​

对于 metastore.partitioned-table 选项为 true 的 Format Table,catalog 持有 其分区,并且 Spark 支持标准的分区 DDL:

ALTER TABLE my_table ADD PARTITION (dt='2025-01-01');
ALTER TABLE my_table ADD PARTITION (dt='2024-12-31')
    LOCATION 'oss://archive-bucket/events/dt=2024-12-31';
ALTER TABLE my_table DROP PARTITION (dt='2025-01-01');
MSCK REPAIR TABLE my_table;
SHOW PARTITIONS my_table;
ANALYZE TABLE my_table PARTITION (dt='2025-01-01') COMPUTE STATISTICS NOSCAN;

对于分区来自文件系统发现的 Format Table,ADD PARTITION、 DROP PARTITION、MSCK REPAIR TABLE 和 ANALYZE TABLE 会报错失败。

ADD PARTITION 创建分区目录并注册分区;在写入任何数据之前查询新增的 分区不返回任何行。DROP PARTITION 注销 分区并删除其目录。

ADD PARTITION ... LOCATION 注册一个自定义的绝对 URI,不移动数据,并要求 兼容的 REST catalog。Paimon 可以读取该分区,但不会写入、删除或分析其 数据。DROP PARTITION 只会注销它,MSCK REPAIR TABLE 对其不做改动。

值为空或全为空白字符的分区值会被 ADD PARTITION、DROP PARTITION 和 TRUNCATE PARTITION 拒绝。这样的值会被写入由 partition.default-name 命名的分区(除非另行配置,默认为 __DEFAULT_PARTITION__),也就是 NULL 被写入的那个分区,因此它会指向该分区而不是自己的分区——应直接使用 该分区名。通过 INSERT 写入这样的值不受影响,仍会落到该分区。

ANALYZE TABLE 度量分区。Format Table 没有可承载表级统计信息的 快照,也没有列统计信息,因此 COMPUTE STATISTICS FOR COLUMNS 和 FOR ALL COLUMNS 在其上不受支持;该语句写回 catalog 的是被度量分区的文件数、字节大小、 最后文件创建时间和行数。每个被度量字段会替换 catalog 原持有的值,因此运行两次报告的数字与运行一次相同,而 无法度量的字段会保留原先存储的值。它永远不会添加或移除分区—— 如需该操作请使用 MSCK REPAIR TABLE。

NOSCAN 止步于目录列表,这能提供除行数之外的所有信息。不使用它时, 行数会从每个文件的 footer 读取,因此对携带 footer 的格式 (Parquet、ORC)是精确的,不含文件的分区计为零,而不携带 footer 的格式 (CSV、TEXT、JSON)则保留 catalog 已持有的行数,不做猜测。读取 footer 每个文件需打开一次,因此它运行在 executor 上,NOSCAN 是两者中 开销更低的。

PARTITION (...) 子句必须为分区列的前缀连续段提供值,因为 catalog 只能按这种形式选择。在按 (dt, hh) 分区的表上, PARTITION (dt='2025-01-01') 和 PARTITION (dt='2025-01-01', hh) 都会度量当天 每个小时的分区,而 PARTITION (hh='01') 会被拒绝,而不是放宽到每一天。指定一个 未注册的分区同样是错误,而不是报告度量了空集并声称成功。

信息

metastore.partitioned-table = true 启用 catalog 管理的分区,这要求 catalog 支持它的内部 Format Table(目前是 REST catalog),且不能与 format-table.implementation = engine 组合使用。REST catalog 会在 CREATE TABLE 时校验该组合,catalog 级表默认值 (spark.sql.catalog.paimon.table-default.*)会参与生效选项的计算:使该组合 无效的默认值会导致 DDL 失败。

在 REST catalog 中,对无法拥有 catalog 管理分区的表——如 外部表,或 format-table.implementation = engine——请求 catalog 管理的分区会失败,而不是返回一张 选项声称一回事、分区却来自别处的表。可以使用 ALTER TABLE my_table UNSET TBLPROPERTIES ('metastore.partitioned-table') 移除该选项。

在其他任何 catalog 中,该选项保持其原有含义——对 Format Table 而言没有含义。这类 表从文件系统加载和读取其分区,因此在 Format Table 上它 只在 REST catalog 中生效;在其他地方,分区从文件系统发现。 在 REST catalog 下,从未注册过分区的现有 Format Table 会被读作空表, 直到你用 MSCK REPAIR TABLE my_table 注册其分区。

混合版本注意事项:只有支持 catalog 管理分区的写入端才会注册 其产出的分区。在滚动升级期间,应先升级所有写入端再依赖 catalog 管理的 分区,或在升级后运行 MSCK REPAIR TABLE,因为旧版本写入端写入的数据在其分区 被注册之前不可见。

对于 Format Table,metastore.partitioned-table 只改变分区的来源;不改变 表的 managed/external 归属。

创建外部表​

当 catalog 的 metastore 类型为 hive 时,如果创建表时指定了 location,该表将被视为外部表;否则,它是托管表。

当删除外部表时,只有 Hive 中的元数据会被移除,实际数据文件不会被删除;而删除托管表会同时删除数据。

CREATE TABLE my_table (
    user_id BIGINT,
    item_id BIGINT,
    behavior STRING,
    dt STRING,
    hh STRING
) PARTITIONED BY (dt, hh) TBLPROPERTIES (
    'primary-key' = 'dt,hh,user_id'
) LOCATION '/path/to/table';

此外,如果指定位置已有数据存储,你可以创建表而不显式指定字段、分区、props 或其他信息。 在这种情况下,新表将从现有表的元数据中继承所有这些信息。

但是,如果你手动指定了它们,需要确保与现有表保持一致(props 可以是子集)。因此,强烈建议不要指定它们。

CREATE TABLE my_table LOCATION '/path/to/table';

Create Table As Select​

表可以通过查询结果创建并填充数据,例如,我们有一个这样的 SQL:CREATE TABLE table_b AS SELECT id, name FORM table_a, 生成的表 table_b 将等同于用以下语句创建表并插入数据: CREATE TABLE table_b (id INT, name STRING); INSERT INTO table_b SELECT id, name FROM table_a;

使用 CREATE TABLE AS SELECT 时,我们可以指定主键或分区,语法请参考以下 SQL。

CREATE TABLE my_table (
     user_id BIGINT,
     item_id BIGINT
);
CREATE TABLE my_table_as AS SELECT * FROM my_table;

/* partitioned table*/
CREATE TABLE my_table_partition (
      user_id BIGINT,
      item_id BIGINT,
      behavior STRING,
      dt STRING,
      hh STRING
) PARTITIONED BY (dt, hh);
CREATE TABLE my_table_partition_as PARTITIONED BY (dt) AS SELECT * FROM my_table_partition;

/* change TBLPROPERTIES */
CREATE TABLE my_table_options (
       user_id BIGINT,
       item_id BIGINT
) TBLPROPERTIES ('file.format' = 'orc');
CREATE TABLE my_table_options_as TBLPROPERTIES ('file.format' = 'parquet') AS SELECT * FROM my_table_options;


/* primary key */
CREATE TABLE my_table_pk (
     user_id BIGINT,
     item_id BIGINT,
     behavior STRING,
     dt STRING,
     hh STRING
) TBLPROPERTIES (
    'primary-key' = 'dt,hh,user_id'
);
CREATE TABLE my_table_pk_as TBLPROPERTIES ('primary-key' = 'dt') AS SELECT * FROM my_table_pk;

/* primary key + partition */
CREATE TABLE my_table_all (
    user_id BIGINT,
    item_id BIGINT,
    behavior STRING,
    dt STRING,
    hh STRING
) PARTITIONED BY (dt, hh) TBLPROPERTIES (
    'primary-key' = 'dt,hh,user_id'
);
CREATE TABLE my_table_all_as PARTITIONED BY (dt) TBLPROPERTIES ('primary-key' = 'dt,hh') AS SELECT * FROM my_table_all;

Replace Table​

Paimon 从 Spark 3.4 起支持为 Spark REPLACE TABLE 保留快照历史。

CREATE TABLE my_table (
    user_id BIGINT,
    item_id BIGINT,
    behavior STRING
) TBLPROPERTIES (
    'primary-key' = 'user_id',
    'bucket' = '2'
);

INSERT INTO my_table VALUES (1, 10, 'pv');

REPLACE TABLE my_table (
    user_id BIGINT,
    item_id BIGINT,
    category STRING
) TBLPROPERTIES (
    'primary-key' = 'user_id',
    'bucket' = '4'
);

在 Paimon 中,这不是一个原子替换。Paimon 将 Spark 的 drop+create 替换路径改为 truncate 当前表并提交新 schema,同时保留表的位置和快照 历史。当前表变为空并使用新 schema,但旧快照仍可通过 time travel 查询。

SELECT * FROM my_table;

SELECT * FROM my_table VERSION AS OF 1;

REPLACE TABLE 要求表已存在。如果表不存在,请使用 CREATE OR REPLACE TABLE。

REPLACE TABLE 不接受 AS SELECT。要替换表并用查询结果填充, 请使用 CREATE OR REPLACE TABLE ... AS SELECT。

CREATE OR REPLACE TABLE my_table
TBLPROPERTIES (
    'primary-key' = 'user_id',
    'bucket' = '4'
)
AS SELECT user_id, item_id, behavior FROM source_table;

当现有表和目标表使用不同的表类型时, 会回退为 drop+create 行为,而不是保留快照的替换 行为。

Create Table Like​

可以从现有源表创建新表。该功能自 Spark 3.4 起可用。

CREATE TABLE target_table LIKE source_table;

CREATE TABLE LIKE 复制源表的 schema 和分区。

在 SparkCatalog 中,如果不指定 USING xxx,目标表继承源表的 provider。

在 SparkGenericCatalog 中,使用 USING paimon 启用 Paimon CREATE TABLE LIKE 语义。

当由 Paimon 处理该命令时,仅当源表和目标表的 provider 相同时才复制注释和表属性。如果 provider 不同,则仅复制注释。

path、provider、location、owner、external 和 is-managed-location 永远不会被复制。用户仍可使用 TBLPROPERTIES 覆盖目标表。

SparkCatalog 不支持 STORED AS 。在 SparkGenericCatalog 中,不带 USING paimon 的命令使用 Spark 原生行为。

CREATE TABLE source_tbl (
    id INT,
    name STRING,
    pt STRING
) COMMENT 'source comment'
PARTITIONED BY (pt)
TBLPROPERTIES ('primary-key' = 'id,pt', 'bucket' = '5');

-- target inherits the source provider
CREATE TABLE target_tbl LIKE source_tbl;

视图基于 SQL 查询的结果集,当使用 org.apache.paimon.spark.SparkCatalog 时,视图由 Paimon 自身管理。 在这种情况下,当 metastore 类型为 hive、rest 或 jdbc 时支持视图。

Create Or Replace View​

CREATE VIEW 构建一个没有物理数据的虚拟表。

-- create a view or a temporary view. (temporary view should not specify database name)
CREATE [TEMPORARY] VIEW <mydb>.v1 AS SELECT * FROM t1;

-- create a view or a temporary view, if a view of same name already exists, it will be replaced. (temporary view should not specify database name)
CREATE OR REPLACE [TEMPORARY] VIEW <mydb>.v1 AS SELECT * FROM t1;

Drop View​

DROP VIEW 从 catalog 中移除与指定视图关联的元数据。

-- drop a view or a temporary view.
DROP VIEW <mydb>.v1;

Tag​

Create Or Replace Tag​

使用以下选项创建或替换 tag 语法。

  • 创建 tag 时可以指定或不指定快照 id 和保留时长。
  • 使用 IF NOT EXISTS 语法时,已存在的 tag 不会报错。
  • 使用 REPLACE TAG 或 CREATE OR REPLACE TAG 语法更新 tag。
-- create a tag based on the latest snapshot and no retention.
ALTER TABLE T CREATE TAG `TAG-1`;

-- create a tag based on the latest snapshot and no retention if it doesn't exist.
ALTER TABLE T CREATE TAG IF NOT EXISTS `TAG-1`;

-- create a tag based on the latest snapshot and retain it for 7 day.
ALTER TABLE T CREATE TAG `TAG-2` RETAIN 7 DAYS;

-- create a tag based on snapshot-1 and no retention.
ALTER TABLE T CREATE TAG `TAG-3` AS OF VERSION 1;

-- create a tag based on snapshot-2 and retain it for 12 hour.
ALTER TABLE T CREATE TAG `TAG-4` AS OF VERSION 2 RETAIN 12 HOURS;

-- replace a existed tag with new snapshot id and new retention
ALTER TABLE T REPLACE TAG `TAG-4` AS OF VERSION 2 RETAIN 24 HOURS;

-- create or replace a tag, create tag if it not exist, replace tag if it exists.
ALTER TABLE T CREATE OR REPLACE TAG `TAG-5` AS OF VERSION 2 RETAIN 24 HOURS;

注意:如果设置了 tag.automatic-creation,一个快照只能创建一个自动 tag。

Delete Tag​

删除表的一个或多个 tag。

-- delete a tag.
ALTER TABLE T DELETE TAG `TAG-1`;

-- delete a tag if it exists.
ALTER TABLE T DELETE TAG IF EXISTS `TAG-1`

-- delete multiple tags, delimiter is ','.
ALTER TABLE T DELETE TAG `TAG-1,TAG-2`;

Rename Tag​

将现有 tag 重命名为新的 tag 名称。

ALTER TABLE T RENAME TAG `TAG-1` TO `TAG-2`;

Show Tags​

列出表的所有 tag。

SHOW TAGS T;
