视图

视图是封装了业务逻辑和领域特定语义的逻辑表。 尽管大多数计算引擎都原生支持视图,但每个引擎都以专有格式存储视图元数据,这给跨平台的互操作性带来了挑战。 Paimon 视图对各引擎特定的查询方言进行抽象,并建立统一的元数据标准。 视图元数据能够实现集中式的视图管理,促进跨引擎共享,并降低异构计算环境中的维护复杂度。

Catalog 支持​

只有当 Catalog 实现支持时,视图元数据才会被持久化:

  • Hive metastore catalog —— 视图元数据与表元数据一起存储在 metastore warehouse 中。
  • REST catalog —— 视图元数据保存在 REST 后端,并通过 Catalog API 暴露。
  • JDBC catalog —— 视图元数据存储在 Catalog 数据库的 paimon_views 元数据表中。该表在 JDBC Catalog 初始化时自动创建。

File-system Catalog 目前不支持视图,因为它们缺少持久化的元数据存储。

表示结构​

字段类型描述
querystring定义视图的规范化 SQL SELECT 语句。
dialectstringSQL 方言标识符(例如 spark 或 flink)。

同一个版本可以存储多个表示,以便不同的引擎可以使用其原生方言访问该视图。

JDBC Catalog 注意事项​

JDBC Catalog 将视图存储在专用的 paimon_views 表中,该表在首次初始化时创建。 在已有 JDBC Catalog 之上运行时,有几点值得了解:

  • 升级所需的权限。 升级到支持视图的 Paimon 版本时,首次打开 Catalog 需要对 Catalog 数据库拥有 CREATE TABLE 权限,以便创建 paimon_views 表。在初始部署后将权限收紧为仅 CRUD 的运维人员, 应当临时恢复 CREATE TABLE 权限,或者提前手动创建 paimon_views 表。
  • 表与视图共享同一个标识符命名空间。 在同一个数据库中,同一个名称不能同时被表和视图使用。 createTable、renameTable、createView 和 renameView 都会在 Catalog 锁下校验该不变式; 针对同一标识符的并发操作中只会有一个胜出。
  • 单进程原子性不依赖 lock.enabled。 JDBC Catalog 还维护了一个以 (catalog key, database, object name) 为键的 JVM 内分段锁(stripe lock), 因此即使 lock.enabled = false,表与视图名称唯一性的不变式在单个 JVM 内依然成立。 对于多进程部署,仍建议设置 lock.enabled = true(配合 lock.type = jdbc), 因为分段锁只能串行化同一 JVM 内的操作。
  • 数据库可见性。 只包含视图(不包含表或属性)的数据库会出现在 listDatabases 和 SHOW DATABASES 的结果中。DROP DATABASE ... CASCADE 会删除该数据库中的 表和视图;不带 CASCADE 的 DROP DATABASE 会拒绝删除仍包含任何视图的数据库。
  • 跨数据库重命名。 当目标数据库不存在时,renameView(from, to) 和 renameTable(from, to) 会抛出 IllegalArgumentException(Database X does not exist.), 与 REST Catalog 的 BadRequest 语义一致。

操作​

创建或替换视图​

使用 CREATE VIEW 或 CREATE OR REPLACE VIEW 注册视图。Paimon 会分配一个 UUID,写入第一个元数据文件,并记录版本 1。

Catalog 只存储视图定义。它在视图创建时不会解析或校验被引用的表, 因此缺失或跨数据库的表引用由计算引擎在查询视图时检查。

CREATE VIEW sales_view AS
SELECT region, SUM(amount) AS total_amount
FROM sales
GROUP BY region;

通过 procedure 修改视图方言​

Paimon 提供 sys.alter_view_dialect procedure,让引擎可以为同一视图版本管理多个 SQL 表示。

Flink 示例​

-- Add a Flink dialect
CALL [catalog.]sys.alter_view_dialect('view_identifier', 'add', 'flink', 'SELECT ...');

-- Update the stored Flink dialect
CALL [catalog.]sys.alter_view_dialect('view_identifier', 'update', 'flink', 'SELECT ...');

-- Drop the Flink dialect representation
CALL [catalog.]sys.alter_view_dialect('view_identifier', 'drop', 'flink');

Spark 示例​

-- Add a Spark dialect
CALL sys.alter_view_dialect('view_identifier', 'add', 'spark', 'SELECT ...');

-- Update the Spark dialect
CALL sys.alter_view_dialect('view_identifier', 'update', 'spark', 'SELECT ...');

-- Drop the Spark dialect
CALL sys.alter_view_dialect('view_identifier', 'drop', 'spark');

删除视图​

DROP VIEW view_name;
