Manifest

Manifest List​

├── manifest
    └── manifest-list-51c16f7b-421c-4bc0-80a0-17677f343358-1

Manifest List 包含若干 manifest 文件的元信息。文件名包含 UUID，是一个 Avro 文件，其 schema 为：

  1. _FILE_NAME: STRING，manifest 文件名。
  2. _FILE_SIZE: BIGINT，manifest 文件大小。
  3. _NUM_ADDED_FILES: BIGINT，manifest 中新增文件的数量。
  4. _NUM_DELETED_FILES: BIGINT，manifest 中删除文件的数量。
  5. _PARTITION_STATS: SimpleStats，分区统计信息，包含该 manifest 中分区字段的最小值和最大值， 有利于查询时跳过某些 manifest 文件，类型为 SimpleStats。
  6. _SCHEMA_ID: BIGINT，写入该 manifest 文件时的 schema id。

Manifest​

Manifest 包含若干数据文件、changelog 文件或表索引（table-index）文件的元信息。文件名包含 UUID，是一个 Avro 文件。

文件的变更保存在 manifest 中，文件可以被添加或删除。Manifest 应该是有序的，同一个文件可能被多次 添加或删除，应该读取最后一个版本。这种设计可以使提交更轻量，以支持由 compaction 产生的文件删除。

Data Manifest​

Data Manifest 包含若干数据文件或 changelog 文件的元信息。

├── manifest
    └── manifest-6758823b-2010-4d06-aef0-3b1b597723d6-0

其 schema 为：

  1. _KIND: TINYINT，ADD 或 DELETE，
  2. _PARTITION: BYTES，分区信息，一个 BinaryRow。
  3. _BUCKET: INT，该文件所属的 bucket。
  4. _TOTAL_BUCKETS: INT，写入该文件时的 bucket 总数，用于 bucket 变更后的校验。
  5. _FILE：数据文件元信息。

数据文件元信息为：

  1. _FILE_NAME: STRING，文件名。
  2. _FILE_SIZE: BIGINT，文件大小。
  3. _ROW_COUNT: BIGINT，该文件中的总行数（包括新增和删除）。
  4. _MIN_KEY: STRING，该文件的最小 key。
  5. _MAX_KEY: STRING，该文件的最大 key。
  6. _KEY_STATS: SimpleStats，key 的统计信息。
  7. _VALUE_STATS: SimpleStats，value 的统计信息。
  8. _MIN_SEQUENCE_NUMBER: BIGINT，最小 sequence number。
  9. _MAX_SEQUENCE_NUMBER: BIGINT，最大 sequence number。
  10. _SCHEMA_ID: BIGINT，写入该文件时的 schema id。
  11. _LEVEL: INT，该文件在 LSM 中的层级。
  12. _EXTRA_FILES: ARRAY，该文件的附加文件，例如数据文件索引文件。
  13. _CREATION_TIME: TIMESTAMP_MILLIS，该文件的创建时间。
  14. _DELETE_ROW_COUNT: BIGINT，rowCount = addRowCount + deleteRowCount。
  15. _EMBEDDED_FILE_INDEX: BYTES，如果数据文件索引太小，则将索引存储在 manifest 中。
  16. _FILE_SOURCE: TINYINT，指示该文件是 APPEND 还是 COMPACT 生成的。
  17. _VALUE_STATS_COLS: ARRAY，元数据中的统计列。
  18. _EXTERNAL_PATH：该文件的外部路径，如果在 warehouse 中则为 null。

Index Manifest​

Index Manifest 包含若干 table-index 文件的元信息。

├── manifest
    └── index-manifest-5d670043-da25-4265-9a26-e31affc98039-0

其 schema 为：

  1. _KIND: TINYINT，ADD 或 DELETE，
  2. _PARTITION: BYTES，分区信息，一个 BinaryRow。
  3. _BUCKET: INT，该文件所属的 bucket。
  4. _INDEX_TYPE: STRING，"HASH" 或 "DELETION_VECTORS"。
  5. _FILE_NAME: STRING，文件名。
  6. _FILE_SIZE: BIGINT，文件大小。
  7. _ROW_COUNT: BIGINT，总行数。
  8. _DELETIONS_VECTORS_RANGES：仅 "DELETION_VECTORS" 使用的元数据，是一个 deletion vector 元信息数组， 每个 deletion vector 元信息的 schema 为：
    1. f0：该 deletion vector 对应的数据文件名。
    2. f1：该 deletion vector 在索引文件中的起始偏移量。
    3. f2：该 deletion vector 在索引文件中的长度。
    4. _CARDINALITY：被删除的行数。

附录​

SimpleStats​

SimpleStats 是嵌套行，其 schema 为：

  1. _MIN_VALUES: BYTES，BinaryRow，各列的最小值。
  2. _MAX_VALUES: BYTES，BinaryRow，各列的最大值。
  3. _NULL_COUNTS: ARRAY，各列的 null 数量。

BinaryRow​

BinaryRow 以字节而不是对象（Object）作为底层支撑，可以显著减少 Java 对象的序列化/反序列化开销。

一个 Row 有两个部分：定长部分和变长部分。定长部分包含 1 字节头部、null 位集（null bit set）和字段值。 Null 位集用于跟踪 null 值，并按 8 字节字边界对齐。Field values 保存定长原始类型以及可以存放 在 8 字节内的变长值。如果不能容纳变长字段，则存储变长部分的长度和偏移量。
