文件格式

目前支持 Parquet、Avro、ORC、CSV、JSON、Lance、Vortex、Mosaic 和 Row 文件格式。

  • 推荐的列式格式是 Parquet，它具有较高的压缩率和快速的列投影查询。
  • 推荐的行式格式是 Avro，它在整行（所有列）读写时性能良好。
  • 推荐的宽表格式是 Mosaic，一种列分桶混合格式，通过列分桶实现并行 I/O。
  • 推荐的点查列式格式是 Vortex，它使用自适应编码，具有出色的点查性能和高效的向量数据压缩。
  • 推荐的基于行号 O(1) 查找的格式是 Row，它以行向块存储数据，使用 ZSTD 压缩，支持按行号快速随机访问。
  • 推荐的测试格式是 CSV，可读性更好，但读写性能最差。
  • 推荐用于 ML 工作负载的格式是 Lance，它针对向量搜索和机器学习场景进行了优化。

Parquet 是 Paimon 的默认文件格式。

下表列出了从 Paimon 类型到 Parquet 类型的映射。

GEOGRAPHY(crs, algorithm) BINARY GEOGRAPHY(crs, algorithm)
DECIMAL(P, S) P <= 9: INT32, P <= 18: INT64, P > 18: FIXED_LEN_BYTE_ARRAY DECIMAL(P, S)
TINYINT INT32 INT_8
SMALLINT INT32 INT_16
INT INT32
BIGINT INT64
FLOAT FLOAT

TIMESTAMP(P) P <= 3: INT64, P <= 6: INT64, P > 6: INT96 P <= 3: MILLIS, P <= 6: MICROS, P > 6: NONE
TIMESTAMP_LOCAL_ZONE(P) P <= 3: INT64, P <= 6: INT64, P > 6: INT96 P <= 3: MILLIS, P <= 6: MICROS, P > 6: NONE

限制：

  1. Parquet 不支持可为 null 的 map key。
  2. 精度为 9 的 Parquet TIMESTAMP 类型会使用 INT96，但此 int96 是经过时区转换的值，需要额外调整。
  3. 含有 GEOMETRY 或 GEOGRAPHY 列的表，file.format、file.format.per.level 中的每一项以及配置时的 changelog-file.format 都必须使用 Parquet。

JSON​

实验性功能，不建议用于生产环境。

格式选项：

Option Default Type Description

 false Boolean 是否忽略 JSON 格式的解析错误。跳过解析错误的字段和行，而不是失败。解析错误时字段会被设为 null。

LANCE​

Lance 是一种现代化的列式数据格式，针对机器学习和向量搜索工作负载进行了优化。它提供原生支持 Apache Arrow 的高性能读写操作。

下表列出了从 Paimon 类型到 Lance（Arrow）类型的映射。

Paimon Type Lance (Arrow) type
CHAR / VARCHAR / STRING UTF8
BOOLEAN BOOL
BINARY / VARBINARY BINARY
DECIMAL(P, S) DECIMAL128(P, S)
TINYINT INT8
SMALLINT INT16
INT INT32
BIGINT INT64
FLOAT FLOAT
DOUBLE DOUBLE
DATE DATE32
TIME TIME32 / TIME64
TIMESTAMP(P) TIMESTAMP (unit based on precision)
ARRAY LIST
MULTISET LIST
ROW STRUCT

限制：

  1. Lance 文件格式不支持 MAP 类型。
  2. Lance 文件格式不支持 TIMESTAMP_LOCAL_ZONE 类型。

VORTEX​

Vortex 是一种列式文件格式，使用自适应的、依赖数据分布的编码，在保持快速扫描性能的同时实现高压缩率。它支持原生谓词下推和高效的列投影。

主要特性：

  • 自适应编码：根据数据分布自动为每一列选择最佳编码
  • 原生谓词下推：支持将过滤表达式下推到扫描层
  • 列投影：仅从磁盘读取请求的列

限制：

  1. Vortex 不支持 MAP 或 MULTISET 类型。

MOSAIC​

Mosaic 是一种针对宽表优化的列分桶混合格式。它将列分组为多个 bucket，并使用 ZSTD 独立压缩每个 bucket，从而实现高效的列投影——只读取包含所需列的 bucket。

主要特性：

  • 列分桶：将列分组到可配置的 bucket 中以实现并行 I/O，显著降低宽表上的读放大
  • Row Group 统计：每个 row group 的 min/max/null_count 统计信息可以在扫描时跳过 row group
  • ZSTD 压缩：所有数据使用 ZSTD 压缩（级别可配置）
  • Arrow 原生：使用 Apache Arrow 作为内存表示，实现零拷贝集成

格式选项：

Option Default Type Description
mosaic.num-buckets
 auto Integer 用于并行 I/O 的列 bucket 数量。设置为 0 或不指定时，由格式自动决定 bucket 数量。
mosaic.stats-columns
 (empty) String 用于收集 min/max 统计信息以支持下推过滤的列名，逗号分隔。为空表示不收集统计信息。

限制：

  1. Mosaic 不支持复杂类型：ARRAY、MAP、MULTISET、ROW、VARIANT、BLOB、VECTOR。

更多细节请参见 Mosaic 文档。

ROW​

Row 格式是一种面向行的存储格式，专为按行号进行 O(1) 随机访问而设计。数据按块组织，各块使用 ZSTD Level 1 压缩。每个块包含以紧凑二进制格式序列化的完整行，以及用于直接定位行的偏移量数组。

主要特性：

  • O(1) 行查找：块索引 + 块内偏移量数组，可以按全局行号直接访问任意行
  • 块级 ZSTD 压缩：每个块独立压缩，在快速解压的同时获得良好的压缩率
  • 紧凑序列化：行以 null 位图加顺序字段值的方式序列化，将开销降到最低
  • 行选择下推：支持基于 RoaringBitmap 的行选择，跳过不含选中行的整个块

Row 格式支持所有 Paimon 数据类型：BOOLEAN、TINYINT、SMALLINT、INT、BIGINT、FLOAT、DOUBLE、CHAR、VARCHAR、BINARY、VARBINARY、DECIMAL、DATE、TIME、TIMESTAMP、TIMESTAMP_LOCAL_ZONE、VARIANT、ARRAY、MAP、ROW。

详细的文件布局和二进制格式规范请参见 Row 格式。

BLOB​

BLOB 格式是一种专门用于存储大二进制对象（如图像、视频等）以及多模态数据的格式。与其他将数据内联存储的格式不同，BLOB 格式将大二进制数据存储在独立的文件中，并针对随机访问优化了布局。

BLOB 文件使用 .blob 扩展名，其结构如下：

+------------------+
| Blob Entry 1     |
|   Magic Number   |  4 bytes (1481511375, Little Endian)
|   Blob Data      |  Variable length
|   Length         |  8 bytes (Little Endian)
|   CRC32          |  4 bytes (Little Endian)
+------------------+
| Blob Entry 2     |
|   ...            |
+------------------+
| Index            |  Variable (Delta-Varint compressed)
+------------------+
| Index Length     |  4 bytes (Little Endian)
| Version          |  1 byte
+------------------+

每个物理 BLOB 文件存储一个逻辑字段。该字段可以是 BLOB、 ARRAY<BLOB> 或 MAP<K, BLOB>。对于 ARRAY<BLOB>，条目中的变长数据区域 使用如下嵌套负载：

+----------------------+-----------------------------------------------+
| Array Magic Number   | 4 bytes (1094861634, Little Endian)           |
| Array Version        | 1 byte                                        |
| Element Count        | 4 bytes (Little Endian)                       |
| Element Data         | Concatenated bytes of all non-null elements   |
| Element Length Index | Delta-Varint compressed element lengths       |
| Index Length         | 4 bytes (Little Endian)                       |
+----------------------+-----------------------------------------------+

元素长度为 -1 表示 null 数组元素。空数组的编码为元素数量为零且元素索引为空； 它与 null 数组是不同的。

对于 MAP<K, BLOB>，变长数据区域使用如下嵌套负载：

+----------------------+-----------------------------------------------+
| Map Magic Number     | 4 bytes (1296188226, Little Endian)           |
| Map Version          | 1 byte                                        |
| Entry Count          | 4 bytes (Little Endian)                       |
| Key Data             | Concatenated bytes of all non-null keys       |
| Blob Data            | Concatenated bytes of all non-null values     |
| Key Length Index     | Delta-Varint compressed key lengths           |
| Blob Length Index    | Delta-Varint compressed Blob lengths          |
| Key Index Length     | 4 bytes (Little Endian)                       |
| Blob Index Length    | 4 bytes (Little Endian)                       |
+----------------------+-----------------------------------------------+

key 和 Blob 的长度索引按条目位置对齐。长度为 -1 表示 null，而零表示 空 key 或空 Blob。支持的 key 类型及其编码如下：

Key typeEncoding
TINYINT, SMALLINT, INT, BIGINTSigned integer in little-endian byte order using the type's fixed width
BOOLEANOne byte: 0 for false and 1 for true
DECIMAL(p, s), p <= 18Eight-byte little-endian signed unscaled integer
DECIMAL(p, s), p > 18Minimal-length signed big-endian two's-complement unscaled integer
DATEFour-byte little-endian signed count of days since 1970-01-01
TIME(p)Four-byte little-endian signed count of milliseconds since midnight
BINARY, VARBINARY (BYTES)Raw bytes
CHAR, VARCHARUTF-8 bytes

DECIMAL 的 scale 由字段类型定义，不会存储在每个 key 中。BINARY 和 VARBINARY key 不会根据声明的长度进行补齐、截断或校验。空 map 的条目数为零， 它与 null map 是不同的。TIME(p) 编码使用 Paimon 的毫秒内部表示， 不会增加纳秒精度。

在外层文件索引级别，-1 表示 null 字段，-2 表示被数据演进 （data evolution）使用的字段占位符。

主要特性：

  • CRC32 校验：每个 blob 条目都有一个 CRC32 校验和，用于验证数据完整性
  • 索引访问：文件末尾的索引可以对文件中任意 blob 进行高效的随机访问
  • Delta-Varint 压缩：索引使用 delta-varint 压缩以节省空间

限制：

  1. BLOB 格式每个物理文件仅支持单个 BLOB、ARRAY<BLOB> 或 MAP<K, BLOB> 字段。
  2. BLOB 格式不支持谓词下推。
  3. BLOB 列不支持统计信息收集。

Video​

Video 是一种独立的、带版本的格式，使用 .video 扩展名。它打包一个或多个 完整的编码视频负载和逻辑帧序列（frame run）。这些负载是原始字节范围，没有 普通 BLOB 条目的头部、长度尾部或逐条目的 CRC：

+----------------------------+
| Encoded Video Payload 1    |  Raw complete video bytes
+----------------------------+
| Encoded Video Payload 2    |
+----------------------------+
| ...                        |
+----------------------------+
| Physical Length Index      |  Delta-Varint video lengths
+----------------------------+
| Run Length Index           |  Delta-Varint logical row counts
+----------------------------+
| Run Reference Index        |  Delta-Varint physical video ordinals
+----------------------------+
| Run First-Frame Index      |  Delta-Varint frame ordinals
+----------------------------+
| Physical Index Length      |  4 bytes (Little Endian)
| Run-Length Index Length    |  4 bytes (Little Endian)
| Run-Reference Index Length |  4 bytes (Little Endian)
| First-Frame Index Length   |  4 bytes (Little Endian)
| Magic Number               |  4 bytes (0x4F454449, Little Endian)
| Version                    |  1 byte
+----------------------------+

run 数组的元素数量相等。非负的 run reference 是物理长度索引中的序号。 对于起始于逻辑行 s 的 run 中的逻辑行 r，返回的 VideoFrameDescriptor 标识 引用的原始视频范围和帧序号 run_first_frame + (r - s)。-1 表示 NULL 的 run， -2 表示数据演进占位符 run。在 version 1 中，非负 run 的帧步长固定为 1； 一旦发生不连续，就会开始一个新的 run。

存储在 Arrow/数据文件单元中的序列化 VideoFrameDescriptor 拥有自己带版本的 网络布局。所有数值均为小端序：

FieldSizeDescription
Version1 byte描述符版本，当前为 1
Magic8 bytes0x564944454F46524D (VIDEOFRM)
URI length4 bytesUTF-8 URI 字节长度
URIvariable包含该内容的 .video 文件的 URI
Offset8 bytes完整编码视频负载的起始位置
Length8 bytes编码视频负载长度
Frame index8 bytes从 0 开始的按展示顺序的帧序号

描述符字节与 .video 容器独立地版本化。Java 和 Python 共享规范的描述符 和容器测试用例，以保持两个实现字节级兼容。

读取器会校验 footer 和索引边界、正的物理长度、负载区域的完整覆盖、相等的 run 索引数量、正的 run 长度、物理序号以及非负的第一帧。该格式目前每个文件 支持一个标量 BLOB 字段。物理视频复用使用精确的输入负载 BlobDescriptor 标识，且是文件本地的；不存在跨文件的负载引用。普通的 .blob 文件 保留其现有的版本、包装、校验和以及布局。

有关用法细节、配置选项和示例，请参见 Blob 类型。
