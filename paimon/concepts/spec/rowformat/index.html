Row 格式规范

Row 格式（.row）是一种面向行的文件格式，针对按行号进行 O(1) 随机访问进行了优化。它专为需要按行位置快速点查的场景设计，例如 deletion vector 应用和 changelog 物化。

文件布局​

一个 .row 文件由三个部分组成：

+====================================================================+
|                        ROW FILE (.row)                              |
+====================================================================+
| Data Block 0 (ZSTD compressed)                                     |
| Data Block 1 (ZSTD compressed)                                     |
| ...                                                                |
| Data Block K (ZSTD compressed)                                     |
+--------------------------------------------------------------------+
| Block Index (Delta+ZigZag+Varint encoded)                          |
+--------------------------------------------------------------------+
| Footer (fixed 32 bytes)                                            |
+====================================================================+

数据块​

每个数据块独立使用 ZSTD Level 1 压缩。解压后的内容布局如下：

+-----------------------------------------------------------+
| row_0_bytes | row_1_bytes | ... | row_N_bytes             |
+-----------------------------------------------------------+
| offset[0] (int32 LE) | offset[1] | ... | offset[N]       |
+-----------------------------------------------------------+
| row_count (int32 LE)                                      |
+-----------------------------------------------------------+
  • 行数据区域：每行使用紧凑行格式（见下文）顺序序列化。
  • 偏移量数组：int32 小端值数组，每行一个，存储每行在未解压块内的字节偏移量。
  • 行数：位于块最末尾的一个 int32 小端值，存储该块中的行数。

当预估的未压缩大小达到配置的块大小阈值时（默认 64 KB，可通过 file.block-size 配置）会刷出一个新块。

行序列化格式​

每行的序列化格式如下：

+-----------------------------------------------+
| null_bitmap | field_0 | field_1 | ... | field_N |
+-----------------------------------------------+

Null 位图：ceil(arity / 8) 字节。如果字段 i 为 null，则位 i 被置为 1。位的位置为 byte[i/8] & (1 << (i%8))。非 null 字段按顺序序列化；null 字段除位图中的位之外不占用任何空间。

原始类型编码​

所有多字节原始类型使用小端字节序。

Paimon TypeEncoding
BOOLEAN1 byte: 0 = false, 1 = true
TINYINT1 byte signed
SMALLINT2 bytes int16 LE
INT / DATE / TIME4 bytes int32 LE
BIGINT8 bytes int64 LE
FLOAT4 bytes IEEE 754 LE
DOUBLE8 bytes IEEE 754 LE
CHAR / VARCHARvarint(length) + UTF-8 bytes
BINARY / VARBINARYvarint(length) + raw bytes
DECIMAL(P, S) where P <= 188 bytes int64 LE (unscaled long)
DECIMAL(P, S) where P > 18varint(length) + unscaled bytes (big-endian two's complement)
TIMESTAMP(P) where P <= 38 bytes int64 LE (epoch millis)
TIMESTAMP(P) where P > 38 bytes int64 LE (epoch millis) + varint(nanoOfMillisecond)
VARIANTvarint(len1) + value bytes + varint(len2) + metadata bytes

Varint 编码​

变长整数编码（无符号 LEB128）：

  • 每个字节使用 7 位存储数据，1 位（MSB）作为延续标志。
  • 如果 MSB = 1，表示后面还有更多字节；如果 MSB = 0，表示这是最后一个字节。
  • int32 值最多占用 5 个字节。

复杂类型编码​

ARRAY：

varint(size) | null_bitmap[ceil(size/8) bytes] | element_0 | element_1 | ... | element_N

Null 位图使用与行 null 相同的位布局。非 null 元素按顺序使用元素类型的编码进行序列化。

MAP：

Map 被序列化为两个数组（先是 keys 数组，然后是 values 数组）：

[keys array] [values array]

每个数组遵循上述 ARRAY 编码（varint 大小 + null 位图 + 元素）。keys 和 values 都支持 null 元素。

ROW（嵌套）：

嵌套行使用与顶层行相同的格式：

null_bitmap[ceil(arity/8) bytes] | field_0 | field_1 | ... | field_N

块索引​

块索引存储所有块的元数据，可以实现二分查找，以定位包含指定行号的块。

+--------------------------------------------------------------------+
| varint(len_0) | encoded_block_compressed_sizes                      |
| varint(len_1) | encoded_block_uncompressed_sizes                    |
| varint(len_2) | encoded_block_row_starts                            |
+--------------------------------------------------------------------+

三个数组分别使用 Delta + ZigZag + Varint 压缩进行编码：

  1. 计算相邻值之间的差值
  2. 对每个差值进行 ZigZag 编码（将有符号数映射为无符号数）
  3. 对每个 ZigZag 值进行 Varint 编码

这种方式对单调递增序列（行起始位置）和值相近的序列（大小）非常高效。

三个数组分别为：

  • blockCompressedSizes：每个块的压缩大小。块偏移量通过前缀和推导（第一个块从文件位置 0 开始）。
  • blockUncompressedSizes：每个块的未压缩大小（用于分配解压缓冲区）。
  • blockRowStarts：每个块起始处的累计行数（用于二分查找）。

Footer​

Footer 是位于文件末尾的固定 32 字节结构：

+-----------------------------------------------+
| totalRowCount   | int64  | 8 bytes | LE       |
| blockCount      | int32  | 4 bytes | LE       |
| indexOffset      | int64  | 8 bytes | LE       |
| indexLength      | int32  | 4 bytes | LE       |
| version          | int8   | 1 byte  |          |
| reserved         |        | 3 bytes |          |
| magic            | int32  | 4 bytes | LE       |
+-----------------------------------------------+
  • totalRowCount：文件中的总行数。
  • blockCount：数据块的数量。
  • indexOffset：块索引在文件中开始的字节偏移量。
  • indexLength：块索引部分的字节长度。
  • version：格式版本，当前为 1。
  • reserved：为未来保留的 3 个字节（必须为 0）。
  • magic：0x524F5753（ASCII "ROWS"），用于格式校验。

按行号查找算法​

按全局行号读取特定行的过程：

  1. 读取 Footer：定位到文件末尾减去 32 字节处，读取 32 字节的 footer，校验 magic number。
  2. 读取块索引：定位到 indexOffset，读取 indexLength 字节，解码三个数组。通过对 blockCompressedSizes[] 求前缀和得到块偏移量。
  3. 二分查找：在 blockRowStarts[] 中查找满足 blockRowStarts[b] <= rowNum < blockRowStarts[b+1] 的块 b。
  4. 读取块：定位到 blockOffset(b)，读取 blockCompressedSizes[b] 字节。
  5. 解压：使用 ZSTD 解压到大小为 blockUncompressedSizes[b] 的缓冲区。
  6. 定位行：计算 localIdx = rowNum - blockRowStarts[b]。从解压后块末尾的偏移量数组中读取 offsets[localIdx]。
  7. 反序列化：从计算出的偏移量处开始使用行序列化格式读取该行。

列裁剪​

列裁剪在完整行反序列化之后应用。由于紧凑行格式顺序序列化各个字段且没有每个字段的偏移元数据，反序列化过程中无法跳过单个字段。完整行反序列化之后，再通过投影映射选取所需的列。

行选择（Deletion Vectors）​

通过 RoaringBitmap32 进行行选择可以实现高效过滤：

  1. 对每个块，检查选择 bitmap 是否与 [blockRowStart, blockRowEnd) 区间相交。
  2. 如果没有交集，则跳过整个块（不做 I/O 或解压）。
  3. 如果有交集，则解压该块，并仅按本地索引反序列化被选中的行。
