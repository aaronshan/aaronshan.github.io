概述

Paimon 支持多种将数据摄入到 Paimon 表的方式,并支持 Schema 演进。这意味着新增的列会实时同步到 Paimon 表中,且同步作业不会因此重启。

我们目前支持以下同步方式:

  1. MySQL 同步表:将 MySQL 中的一张或多张表同步到一个 Paimon 表中。
  2. MySQL 同步数据库:将整个 MySQL 数据库同步到一个 Paimon 数据库中。
  3. Program API 同步:将你自定义的 DataStream 输入同步到一个 Paimon 表中。
  4. Kafka 同步表:将一个 Kafka Topic 对应的表同步到一个 Paimon 表中。
  5. Kafka 同步数据库:将一个包含多张表的 Kafka Topic,或多个各包含一张表的 Topic 同步到一个 Paimon 数据库中。
  6. MongoDB 同步集合:将 MongoDB 中的一个 Collection 同步到一个 Paimon 表中。
  7. MongoDB 同步数据库:将整个 MongoDB 数据库同步到一个 Paimon 数据库中。
  8. Pulsar 同步表:将一个 Pulsar Topic 对应的表同步到一个 Paimon 表中。
  9. Pulsar 同步数据库:将一个包含多张表的 Pulsar Topic,或多个各包含一张表的 Topic 同步到一个 Paimon 数据库中。

什么是 Schema 演进​

假设我们有一张名为 tableA 的 MySQL 表,它有三个字段:field_1、field_2、field_3。当我们想要将 这张 MySQL 表加载到 Paimon 时,可以在 Flink SQL 中完成,或者使用 MySqlSyncTableAction。

Flink SQL:

在 Flink SQL 中,如果我们在摄入之后修改了 MySQL 表的 Schema,Schema 变更不会被同步到 Paimon。

MySqlSyncTableAction:

在 MySqlSyncTableAction 中,如果我们在摄入之后修改了 MySQL 表的 Schema,Schema 变更会被同步到 Paimon, 并且新增的 field_4 字段的数据也会被同步到 Paimon。

Schema 变更演进​

CDC 摄入支持有限数量的 Schema 变更。目前,框架不支持重命名表、删除列,因此 RENAME TABLE 和 DROP COLUMN 的行为会被忽略,RENAME COLUMN 会新增一列。目前支持的 Schema 变更包括:

  • 新增列。

  • 修改列类型。更具体地说,以下变更是支持的:

    • 从一种字符串类型(char、varchar、text)变更为另一种长度更长的字符串类型,
    • 从非字符串类型变更为字符串类型(char、varchar、text),
    • 从一种二进制类型(binary、varbinary、blob)变更为另一种长度更长的二进制类型,
    • 从一种整数类型(tinyint、smallint、int、bigint)变更为另一种范围更大的整数类型,
    • 从一种浮点类型(float、double)变更为另一种范围更大的浮点类型。

--computed_column 是计算列的定义。参数字段来自源表的字段名。

时间列的数据类型可以是以下几种情况之一:

  1. DATE、DATETIME 或 TIMESTAMP。
  2. 任意整数数值类型(如 INT 和 BIGINT)。在这种情况下,数据会被视为相对于 1970-01-01 00:00:00 的 Epoch 时间。 你需要设置该值的精度(默认为 0)。
  3. STRING。在这种情况下,如果你没有设置时间单位,数据会被视为 DATE、DATETIME 或 TIMESTAMP 值的格式化字符串。 否则,数据会被视为 Epoch 时间的字符串值。因此在后一种情况下你必须设置时间单位。

精度表示 Epoch 时间的单位。目前有四种有效的精度:0(表示 Epoch 秒)、 3(表示 Epoch 毫秒)、6(表示 Epoch 微秒)和 9(表示 Epoch 纳秒)。以时间点 1970-01-01 00:00:00.123456789 为例,Epoch 秒为 0,Epoch 毫秒为 123,Epoch 微秒 为 123456,Epoch 纳秒为 123456789。精度应与输入值匹配。你可以通过如下方式设置精度:date_format(epoch_col, yyyy-MM-dd, 0)。

date_format 是一个灵活的函数,能够将时间值按照不同的格式字符串转换为各种格式。 最常用的格式字符串是 yyyy-MM-dd HH:mm:ss.SSS。另一个例子是 yyyy-ww,它可以从输入中提取年份 和年内周数。注意,输出会受地区设置(locale)影响。例如,在某些地区一周的 第一天是周一,而在另一些地区是周日,因此如果你使用 date_format(date_col, yyyy-ww) 且 date_col 的输入是 2024-01-07(周日),输出可能是 2024-01(如果一周的第一天是周一)或 2024-02(如果 一周的第一天是周日)。

特殊数据类型映射​

有可能某些上游系统的数据类型无法直接映射到 Paimon 数据类型。我们有一些特殊的数据类型映射规则:

  1. MySQL TINYINT(1) 类型会被映射为 Boolean。
  2. MySQL BIT(1) 类型会被映射为 Boolean。
  3. MySQL BIGINT UNSIGNED、BIGINT UNSIGNED ZEROFILL、SERIAL 会被映射为 DECIMAL(20, 0)。
  4. MySQL BINARY 会被映射为 Paimon VARBINARY。这是因为在 binlog 中二进制值以字节形式传递,所以 应当映射为字节类型(BYTES 或 VARBINARY)。我们选择 VARBINARY,因为它可以保留长度信息。
  5. 某些上游系统可能不会传递 decimal 的精度(precision)和标度(scale)信息。在这种情况下,我们会使用 DECIMAL(38, 18)。
  6. 使用 Hive catalog 时,MySQL TIME 类型会被映射为 STRING。

我们提供了一些选项来自定义映射规则。请使用 --type_mapping option1,option2,... 来指定它们:

  1. tinyint1-not-bool:将 MySQL TINYINT(1) 映射为 Paimon TINYINT 而不是 Boolean。
  2. to-nullable:忽略所有 NOT NULL 约束(主键除外)。
  3. to-string:将所有 MySQL 数据类型映射为 STRING。
  4. char-to-string:将 MySQL CHAR(length)/VARCHAR(length) 类型映射为 STRING。
  5. longtext-to-bytes:将 MySQL LONGTEXT 类型映射为 BYTES。
  6. decimal_no_change:避免 Paimon CDC 框架自动使用 DECIMAL(38, 18)。
  7. bigint-unsigned-to-bigint:将 MySQL BIGINT UNSIGNED、BIGINT UNSIGNED ZEROFILL、SERIAL 映射为 Paimon BIGINT, 但存在潜在的数据溢出问题,因为 BIGINT UNSIGNED 可以存储最多 20 位整数值,而 Paimon BIGINT 只能存储最多 19 位整数值。因此在使用此选项时,你应确保不会发生溢出。
  8. allow_non_string_to_string:Schema 变更默认不支持非字符串类型到字符串类型的变更。使用此选项以允许该变更。

自定义作业设置​

Checkpointing​

使用 -Dexecution.checkpointing.interval=<interval> 来开启 checkpoint 并设置间隔。对于 0.7 及之后的版本, 如果你没有开启 checkpoint,Paimon 会默认开启 checkpoint 并将 checkpoint 间隔设置为 180 秒。

作业名称​

使用 -Dpipeline.name=<job-name> 来设置自定义的同步作业名称。

表配置​

你可以使用 --table_conf 来设置表属性和一些 Flink 作业属性(如 sink.parallelism)。如果表是 由 CDC 作业创建的,那么表的属性将与给定的属性一致。否则,作业会使用给定的 属性来修改表的属性。但请注意,不可变选项(如 merge-engine)和 bucket 数量不会被修改。
