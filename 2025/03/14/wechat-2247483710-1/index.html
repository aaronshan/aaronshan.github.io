项目简介 📖

ragflow4j(https://github.com/aaronshan/ragflow4j) 是一个开源的 RAG（检索增强生成）引擎。与 Dify、Ragflow 等不同，它是用 Java 开发的。市面上类似的产品大多使用 Python 开发。我希望通过这个项目能帮助以 Java 为主要开发语言的开发者更好地理解 RAG 的整体机制。

今日工作内容 ✨

今天主要完成了Content Retriever模块的设计与实现，这是RAG系统中非常关键的一个组件。主要完成了以下工作：

1. Content Retriever接口设计

设计了统一的检索器接口ContentRetriever，定义了以下核心方法：

  • • retrieve(String query): 基于查询文本进行检索

  • • retrieveWithScore(String query): 检索并返回相关度分数

  • • batchRetrieve(List<String> queries): 批量检索接口

2. 向量相似度检索实现

实现了VectorStoreRetriever类，主要功能包括：

  • • 集成Milvus向量检索

  • • 实现KNN近邻搜索

  • • 优化检索性能，支持批量查询

  • • 实现结果过滤和后处理

代码示例：

public class VectorStoreRetriever implements ContentRetriever {
    private final VectorStore vectorStore;
    private final TextEmbedding embedding;

    @Override
    public List<Document> retrieve(String query) {
        float[] queryVector = embedding.embed(query);
        return vectorStore.similaritySearch(queryVector);
    }
}

3. 混合检索策略实现

开发了HybridRetriever类，实现了多种检索方式的组合：

  • • 支持向量检索和关键词检索的混合

  • • 实现检索结果合并和去重

  • • 实现动态权重调整机制

  • • 支持结果重排序

4. 性能优化

针对检索性能进行了多项优化：

  • • 实现了检索结果缓存

  • • 优化了批量检索的并发处理

  • • 添加了性能监控指标

5. 单元测试

编写了完整的单元测试用例：

  • • 测试各类检索器的功能正确性

  • • 验证混合检索的结果准确性

  • • 进行性能基准测试

遇到的问题和解决方案 🔧

    1. 向量检索性能问题

  • • 问题：大规模向量检索时响应较慢

  • • 解决：实现了异步批处理和结果缓存机制

    1. 检索结果去重

  • • 问题：混合检索时出现重复结果

  • • 解决：实现了基于文档ID的去重算法

    1. 权重调整策略

  • • 问题：不同检索方式的权重难以平衡

  • • 解决：引入了自适应权重调整机制
